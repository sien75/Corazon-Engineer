# 系统改名:corazon → engineer

> iteration-2611 · 需求:命令行工具由 `corazon` 改名为 `engineer`;Web 左上角与标签页标题由 `Corazon` 改为 `Corazon Engineer`。范围取"全改"(方案 C)。

## 背景

产品对外名是 **Corazon Engineer**,但命令与内部标识一直用短名 `corazon`,Web 界面也只显示 `Corazon`。用户要求:

1. 命令 `corazon` → `engineer`;
2. Web 左上角 logo 与 `<title>` → `Corazon Engineer`;
3. 范围取"全改"(方案 C):含 `~/.corazon`、`CORAZON_HOME`、`corazon.yaml`。

## 命名约定

| 类别 | 旧 | 新 |
|---|---|---|
| 入口命令 | `corazon` | `engineer` |
| 服务二进制 | `corazon-log/static/ai/web` | `engineer-log/static/ai/web` |
| 安装目录 | `~/.corazon` | `~/.engineer` |
| 环境变量 | `CORAZON_HOME` | `ENGINEER_HOME` |
| 项目根标记 | `corazon.yaml` | `engineer.yaml` |
| 项目数据目录 | `.corazon/` | `.engineer/` |
| sqlite 库 | `corazon.db` | `engineer.db` |
| 压缩包 / 解压目录 | `corazon-<ver>-<os>-<arch>` | `engineer-<ver>-<os>-<arch>` |
| Web 注入全局 | `window.CORAZON` | `window.ENGINEER` |
| localStorage key | `corazon.theme` / `corazon.ai.*` | `engineer.theme` / `engineer.ai.*` |
| Go module | `corazon/log` / `corazon/static` / `corazon/web` | `engineer/log` / `engineer/static` / `engineer/web` |
| TS 类型 | `CorazonEvent` | `EngineerEvent` |
| 调试环境变量 | `CORAZON_AI_DEBUG` | `ENGINEER_AI_DEBUG` |
| 终端标题 / 进程名 | `corazon` | `engineer` |
| Web 品牌 | `Corazon` | `Corazon Engineer` |

**保持不变**(非命令/路径的专有名词):

- 产品名 `Corazon Engineer`;
- 概念术语 `Corazon-like project`(框架 / 方法论名,`agents/AGENTS.md` 的核心概念);
- `notes/` 下的文件名与截图文件名。

## 目标 / 验收

- 用户敲 `engineer` 能启动 / 查看状态 / 卸载整套服务;
- Web 标签页标题与左上角显示 `Corazon Engineer`;
- 仓库内不再有指向旧命令 / 旧路径 / 旧环境变量的功能性引用。

## 明确不做(Out of scope)

- 不保留旧命令 / 旧目录的兼容或迁移逻辑(方案 C 已确认会破坏老用户升级路径);
- 不改端口(prod 7500–7503 / dev 8500–8503);
- 不改契约的请求 / 响应结构(纯改名);
- 不改写 `devtime/development/iteration-2608/2609/2610` 的历史记录(那些记录的是当时事实)。

## 影响面

- **schema**:`corazon.yaml` → `engineer.yaml`;`atoms/*.yaml` 的 description 文案;
- **workspace**:log / static / web / ai 四个服务全部;
- **deploy**:`dev/launch.sh`、`dev/stop.sh`、`dev/BOOK.md`、`prod/launch.go`、`prod/install.sh`、`prod/BOOK.md`;
- **runtime/testing**:4 个 `case-core-*/TEST.md`,以及 `.playground` 的 mock 根标记;
- **docs / README / AGENTS / agents**(英文与 `_zh` 镜像);
- `.gitignore` ×3。

## 风险

- 老安装的 `~/.corazon` 与新 `~/.engineer` 并存,旧命令 `corazon` 仍指向旧版本 —— 已确认接受。
- 项目数据目录由 `.corazon/` 变为 `.engineer/`,旧项目数据不自动迁移;本仓库的 `.corazon/` 是本地私有数据,可重建。

## 验证

1. `grep -rniI corazon` 仅剩命名约定里"保持不变"的品牌 / 概念文案;
2. 三个 Go 服务 `go build` 通过,ai 能 `bun` 起;
3. 重新 `launch.sh` 后端口表正常、`engineer.yaml` 被识别、web 标题与 logo 正确;
4. 跑 `runtime/testing/dev/case-core-*` 全部用例;
5. 检查 prod 包名 / 入口名 / 安装路径(不实际发布)。

## 验证结果(2026-09-24)

- `grep` 复核:功能标识符已无 `corazon`;仅剩历史设计记录(2608/2609/2610)与品牌/概念文案。
- 构建:`go build` + `go vet`(log / static / web)通过;`bun x tsc --noEmit`(ai)通过。
- schema:`POST /static/validate` → `ok: true`。
- 用例回归(全部 pass,已写 `kind: test` log 记录):
  - `core-static-validate` 5/5;
  - `core-static-query` 5/5;
  - `core-static-stream` add/update/remove + atom 对象 + `kinds` 过滤;
  - `core-web-serve` 全项(含 `window.ENGINEER`、SPA 回退、403/404、`engineer web:` 启动日志)。
- dev 端到端:`devtime/deploy/dev/launch.sh` 起四服务,`engineer.yaml` 被识别,web 标题 / logo 为 `Corazon Engineer`。
- prod 入口:按 BOOK 方式打包到临时目录,`engineer version` 打印包目录名、`engineer status` 逐服务状态正确;把包放到 `engineer-v0.1.0-darwin-arm64/` 并用 `ENGINEER_HOME` 沙箱跑 `install.sh`,生成 `bin/engineer -> apps/current/bin/engineer`;prod launcher 自动避开 7500–7503 起在 7504–7507、SIGTERM 后端口释放、pid 清理。
