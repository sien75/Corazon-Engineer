### 多 agent 设计

首先 ai 能力这块, 需要多 agent, 主 agent 是宏观层面的, 修改 schema, 宏观层面执行运行/测试/连接/监控, 然后它不涉及具体的事情.

比如说, 增加了什么接口, 他不负责分析, 只负责出方案, 然后和子 agent 对话, 看他们的是否符合要求, 然后问子 agent 你增加了哪些能力, 然后补充到 schema 里, 但是通过测试去测试它对不对.

1. 角色系统(如公司叙事/古代朝堂叙事)
2. 游戏化(可视化/增加趣味和传播)

### static 重新设计(shell 化)

重新设计 static 部分, prompt + code 缓存机制 + 权限控制 + 校验机制

- **写入/读取 shell 化**: query / mutation / search 接口没必要;读写都收敛到 shell(自然语言 → shell 命令)。static 只留 stream(后端 → 前端的变动监听同步),甚至评估是否还需要 static 服务本身。
- **权限控制(超前, 暂缓)**: 现阶段只做粗粒度 —— 只能改本项目内容(直接改),改项目外内容需审核,读不限(可用 jev 判断)。后续很复杂:多 agent、按步骤/agent 限定可改哪个文件,验证通过再进入下一步。
- **校验机制(先做基础)**: 理想是完成一步后校验一次。先保证 YAML 语法/规范合规(atoms / contracts / edges 按 contract 规范);其余是 md,无法结构校验。后续再扩展校验其它内容。
- **缓存机制 / 预编译 shell(超前, 暂缓)**: 常用 shell 命令固化,展示到前端供快捷操作(本质是读操作,如"看所有 atoms"),此前调接口、现收敛为 AI 系统的"预编译 shell";AI 后续可动态新增。若接入 openui/a2ui,前端无需自行实现。
