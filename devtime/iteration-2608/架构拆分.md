# 架构拆分:static 纯 schema + log 数据服务

## 1. 总览

核心目标:**static 只负责 schema,不掺合运行时数据**。运行时数据(记录存储、实时分发)由独立的 log 服务承担。

```
                    ┌──────────────────────────────────────────────┐
                    │                  web(前端)                    │
                    └───────┬──────────────┬───────────────┬───────┘
                            │              │               │
                         读             改 / 对话          读
                            │              │               │
                            ▼              ▼               ▼

        ┌──────────────┐          ┌──────────────┐          ┌──────────────┐
        │    static    │◄────────►│    ai 编排    │◄───────►│     log      │
        └──────────────┘   写 / 查 └──────┬───────┘   写 / 查 └──────────────┘
                                         │                          ▲
                                         │ 调用                      │
                                         ▼                          │ 实时写入日志
                                  ┌───────────────┐                 │
                                  │      CLI      │─────────────────┘
                                  │ 连外部端点/查源 │
                                  └───────────────┘
```

## 2. 组件职责

| 组件 | 职责 | 不负责 |
|---|---|---|
| **static** | schema 解析 / 查询 / 详情 / 搜索(mutation 主要给 ai 调) | 一切运行时数据:sqlite、消息分发、外部连接 |
| **log**(新) | 拥有 sqlite;提供记录读接口(给前端)、SSE 分发、ingest 接收 | schema 解析与修改 |
| **ai**(独立进程) | 对话/编排(DeepSeek 模型,key 在 `.corazon/credentials.md`);调 static 读写 schema;CLI 工具连外部端点;写 / 查 log | 不做数据服务 |
| **web**(前端) | 架构图 / 列表详情(直连 static 读)、实时面板与记录(直连 log)、改操作走 ai 对话 | 不直连 sqlite(浏览器沙箱) |
| **sqlite** | 归 log 服务所有:`/log/query` 读给前端;写仅 ai | 不存 schema(schema 是文件) |

## 3. 接口划分

> 使用规则:**读直连 / 改走 ai**——前端读直接调 static / log;前端要改或操作,走 ai 对话,ai 再去调 static(mutation)等。

### static 服务(纯 schema,统一 `static` 前缀)
```
POST /static/query        查询(全量架构 + 目录条目)      ← 前端直连读 / ai 读
POST /static/query-detail 单个文件内容                  ← 前端直连读 / ai 读
POST /static/search       全局搜索                       ← 前端直连读 / ai 读
POST /static/mutation     增删改(校验、留痕)             ← ai 调
POST /static/stream        schema 变更 SSE(留痕展示)      ← 前端直连订阅
```

### log 服务(拥有 sqlite,统一 `log` 前缀)
```
POST /log/query          查记录(日志 / 测试 / 对话,列表)   ← 前端直连读 / ai 读
POST /log/query-detail   单条记录详情                     ← 前端直连读 / ai 读
POST /log/search         记录全文搜索                     ← 前端直连读 / ai 读
POST /log/mutation       写记录(仅 ai 经此写 sqlite)       ← ai 调
POST /log/stream         SSE 订阅,实时分发                ← 前端直连订阅
```

### ai 进程(接口直接暴露给前端)
```
POST /ai/new
POST /ai/ask
POST /ai/stream
POST /ai/approval
POST /ai/delete
```

前端"改 / 操作"走 ai 对话;ai 内部调 static(mutation)、log、外部 CLI 完成,对前端透明。

## 4. 数据归属

| 数据 | 存哪 | 谁能写 | 谁能读 |
|---|---|---|---|
| schema | `atoms/` 等文件 | static(mutation,由 ai 触发) | static(给前端 / AI) |
| 运行时记录 | sqlite | **仅 AI** | log(给前端)、AI(自用) |
| 凭据(含 ai 密钥) | `.corazon/credentials.md` | 人工 / AI | AI(CLI 连接用) |

## 5. 运行形态

三个独立 Go 模块,三个进程:

```
workspace/static:  corazon serve-static  [--addr :7502] [--root <项目>]   # schema 服务
workspace/log:     corazon serve-log     [--addr :7503] [--root <项目>]   # log 服务(存 .corazon/corazon.db)
workspace/ai:      corazon serve-ai      [--addr :7501] [--root <项目>]   # ai 服务(DeepSeek)
```

web 静态服务(`workspace/web`,serve.js)独立启动。互不依赖部署,可独立重启。

log 的存储全部落在项目根 `.corazon/` 下(已 gitignore):
- `credentials.md` —— 连接凭据,**含 ai 密钥**
- `corazon.db` —— sqlite 记录库(调用 / 观测 / 对话)
- `.playground/` —— 测试用的 mock 项目(从 `tests/.playground/` 拷贝)
