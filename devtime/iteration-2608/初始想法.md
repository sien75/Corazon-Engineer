## 当前 Coding Agent 的问题

现在的 Coding Agent 很多了嘛, 但是我实际使用下来发现一些问题:

1 Coding Agent 没有办法一定做对, 即使加上自动化测试的要求, 因为可能存在很多并不那么好发现的问题, 也不一定符合人的预期
2 人很难快速理解项目结构, 这个很关键, 因为理解项目结构是提要求的前提, 不了解就提很容易堆积无效代码, 造成问题

## 做一个 Engineering Agent

基于这种设想, 我其实想做一个宏观层面的 Engineering Agent / Architect Agent, 我认为实现很简单, 但是这里最重要的是确定思路和确定细节, 不用管实现, 先讨论设计思路和设计细节.

### 两个要素: 原子项目 & 组合方式

首先, 既然是宏观层面, 那么一定要先定义, 什么是原子, 和原子之间的组合方式.

原子, 其实基本上对应于一个代码项目, 这个项目内, 是 coding agent 的领域, 这个大家都熟悉.

组合, 这个其实最重要的是明确原子项目能接受哪些输入输出, 我理解这里有以下方式:
1. 网络接口
2. 进程间通信
3. 标准输入输出等

### 载体: 一种 schema

然后定义好了原子项目和组合方式, 那么在表现层面, 其实就是要把原子之间的关系去表达出来. 比如定义一个 schema, 明确原子需要哪些维度的描述, 组合方式需要哪些维度的描述.

schema 我希望能对应表现成一种交互式网页的形式, 因为纯 diagram 太抽象, 少了很多解释性的. 而纯文档, 又太静态, 不能宏观观察.

什么叫交互式网页? 就是打开一个网页, 看起来是项目全局介绍的文档, 但是里面的图表可以真实操作(什么操作下面说), 可以跳转其他文档页, 可以搜索, 可以看数据库内容, 可以全局 ai 问答和操作.

然后这个系统可以用于开发debug(把原子节点替换成本地服务), 也可以用于日志问题排查(把原子节点替换成线上服务), 因此我希望 schema 能去关联到真实的日志数据, 包括接口和数据库内的数据.

关于图表操作, 这个首先图表内单个节点应该能执行测试, 然后节点之间的互动应该能留痕观察.
