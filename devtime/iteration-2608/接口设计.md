# 接口设计

## 架构
- **后端**:暴露原子化接口,同时面向前端和 AI
- **AI**:独立进程,前端调 AI,AI 内部调后端完成编排
- **前端**:多端形态,统一通过接口交互

---

## 后端接口(原子化,面向前端 + AI)

### schema 查询
返回全量架构数据,用于绘制架构图和 atom/edge 详情展示。元数据级别,一次性返回,不分页。
atoms / edges 全量返回(完整内容,画图要用);其余(runtime / contract / test / devtime / docs / notes)只给引用 / 条目,内容按需走下方"内容查询",避免全量 payload 过大、省 AI 上下文。

### 内容查询
按需返回单个 runtime / contract / test / devtime / docs / notes 文件的具体内容。
schema 查询里 atoms / edges 已全量;其余钻取到某 runtime env、某接口的 contract、某 test spec / devtime 记录 / docs / notes 时再调此接口取内容。AI 排查 / 编排时也用。

### schema 增删改
面向 AI 设计的原子化 mutation。粒度精确到单个对象:atom / edge / runtime / test / contract / devtime / docs / notes。
每次只改一个对象(add / update / remove),底层改对应的文件,方便 AI 编排和留痕。
前端不直接调,通过 AI 编排。

### 运行时数据查询
查询某条 edge 的实际调用记录(前提:runtime env 已连接到执行实例)。
运行时数据本质就是 log / trace / metric 三类遥测信号 —— log 看日志,trace 看链路,metric 看指标;可从 edge 调用记录下钻到具体信号。AI 排查问题时也用。

### search
全局搜索 schema 内内容(atom / edge / runtime / test / contract / 接口路径 / 表名 / topic 等)。
前端架构图内搜索 + AI 查找都用。

### sse 订阅
长连接,推送 edge 触发事件。前端订阅,架构图上 edge 播动画用。

### 触发测试
触发系统测试。主要给 AI 用(AI 编排测试流程)。

## AI 接口(面向前端)

设计理念:AI 的能力(问答 / 规划 / 操作等)不通过独立接口区分,统一走 `ask`,**由 prompt 内容决定语义**。前端按钮也非硬编码,由流式消息的格式标记驱动渲染。授权单独走 `approval` —— AI 想做后端操作时经 stream 弹 approval 卡片,用户点了才授权。

### new
新建对话,不实际执行,只产生并返回 sessionid。

### ask
提问。携带 prompt(决定 AI 做什么)。

### approval
授权。用户点 approval 按钮时调用,允许 AI 执行某个待审批的后端操作(stream 里发出的 approvalId)。

### stream
流式接收 AI 输出。前端按消息内的格式标记渲染;`question` 可回传给 ask(发新 prompt),`approval` 走 authorization(授权)。
