# 跨目录引用风险

schema 层各目录之间靠引用串起来, 大部分是 YAML 字段里的 `./` 前缀根相对路径(规范明确), 但有几处是**隐式耦合**, 没有路径可查、没有工具校验, 改一处容易悄悄改断另一处. 记录如下:

## 1. edges 与 atoms 的接口 id 纯字符串配对

`edges/*.yaml` 的 `from` / `to` 是 atom 名, `from_interface` / `to_interface` 是接口 id, 必须与 `atoms/*.yaml` 里 `interfaces.provides/consumes[].id` 完全一致(如 `web-to-ai.yaml` 的 `ai-new` 要同时存在于 `atoms/web.yaml` 的 consumes 和 `atoms/ai.yaml` 的 provides).

风险: 这是裸 id 对裸 id, 不是路径引用, 改名/删接口时没有任何报错来源, 只能人工核对.

## 2. ~~runtime 端口与 workspace 代码默认端口两处硬编码~~(已缓解)

现状: 端口默认值只声明在两处——`runtime/cookbooks/<env>/config.yaml` 的 `ports.*` 和各服务代码的内置默认(log/static/ai/web), BOOK.md 散文不再出现端口号, 只按 key 引用 config. 启动时 CLI 参数 > config 默认.

残留风险: config.yaml 与代码内置默认仍是两份真相, 不一致时表现为「带参和不带参启动端口不同」; 约定是 config.yaml 与代码默认保持一致(本项目即如此).

## ~~3. system-prompt 两处手工同步的副本~~(已解除)

AI 能力描述已收敛到唯一事实源 `agents/AGENTS.md`(英文, 权威版) + `agents/zh/AGENTS_zh.md`(中文镜像),随工具发布. ai 的 system prompt 属于 Corazon 工具自身(安装后为 `~/.corazon/apps/<ver>/agents/`),不是被处理项目的 `agents/`——后者只是被操作的内容;具体读取位置待实现.

## 附: 引用格式现状

- YAML 字段值(`atoms` 的 `path`/`contract`)全部是 `./` 前缀的根相对路径, 符合 `agents/zh/schema.md` 约定.
- 但 markdown 正文/注释里的引用不带 `./`(如 contracts 注释里的 `see agents/zh/enum.md`、runtime 散文里的 `workspace/static`、`runtime/tests/dev/.playground`), 接口 id 参数值(如 `contracts/demo-api.yaml`)也不带 `./`. 两种写法并存, 目前无碍, 但若以后做自动校验需要兼容.
