# 跨目录引用风险

schema 层各目录之间靠引用串起来, 大部分是 YAML 字段里的 `./` 前缀根相对路径(规范明确), 但有几处是**隐式耦合**, 没有路径可查、没有工具校验, 改一处容易悄悄改断另一处. 记录如下:

## 1. edges 与 atoms 的接口 id 纯字符串配对

`edges/*.yaml` 的 `from` / `to` 是 atom 名, `from_interface` / `to_interface` 是接口 id, 必须与 `atoms/*.yaml` 里 `interfaces.provides/consumes[].id` 完全一致(如 `web-to-ai.yaml` 的 `ai-new` 要同时存在于 `atoms/web.yaml` 的 consumes 和 `atoms/ai.yaml` 的 provides).

风险: 这是裸 id 对裸 id, 不是路径引用, 改名/删接口时没有任何报错来源, 只能人工核对.

## 2. runtime 端口与 workspace 代码默认端口两处硬编码

`runtime/dev.yaml` 的 `endpoints` 写了 static:7502 / ai:7501 / log:7503 / web:7500, 而 `workspace/log/main.go`、`workspace/static/main.go`、`workspace/ai/src/main.ts`、`workspace/web/serve.js` 里的默认端口是各自硬编码的. `runbooks/dev.md` 也要求两者一致.

风险: 改端口要同时改 runtime yaml + 各服务代码 + runbook, 漏一处就起不来或连错.

## 3. system-prompt 两处手工同步的副本

`workspace/ai/system-prompt.md` 与 `devtime/system-prompt/SKILL.md`(+ `SKILL_zh.md` 中文版)内容几乎完全重复, 都约定了读 `contracts/` 契约、按 `runtime/dev.yaml` 端口、用 `.corazon/credentials/` 凭证.

风险: 靠手工保持同步, 已经存在漂移可能; 改提示词约定时要改两处(算上中文版是三处).

## 附: 引用格式现状

- YAML 字段值(`atoms` 的 `path`/`contract`、`runtime` 的 `runbook`/`case`)全部是 `./` 前缀的根相对路径, 符合 design.md 约定.
- 但 markdown 正文/注释里的引用不带 `./`(如 contracts 注释里的 `see devtime/schema/enums_zh.md`、tests/runbooks 里的 `workspace/static`、`tests/.playground`), 接口 id 参数值(如 `runtime/dev.yaml`、`contracts/demo-api.yaml`)也不带 `./`. 两种写法并存, 目前无碍, 但若以后做自动校验需要兼容.
