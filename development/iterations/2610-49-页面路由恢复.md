# 页面路由恢复

## 目标与范围

用户要求 + 打开 launcher 时地址变为 /new；在 /new、/session/<id> 或 / 刷新后继续展示对应页面。浏览器前进后退也跟随路径。只改前端路由和针对性浏览器测试，不改历史回放、主题、布局或后端协议。

## 契约与关系

现有 web SPA fallback 已支持任意 shell 路由；log/current/get、session/detail、session/on 和 ai/resume 契约均可复用，不增加接口。atoms/web.yaml 补充路由呈现职责，edges 不变。

## 设计

- + 的 openLauncher 写入 /new，boot 与 popstate 统一按路径恢复，恢复不新增历史。
- /session/<id> 优先激活已开标签；存在但关闭的 sub 会话重新加入工作区并 resume，缺失或非法路径回 main 并 replace 为 /，给出提示。
- 当前 main session 的直达链接归一为 /。不将其他历史 main 当作 Blueprint 打开。
- 外部点击收起 launcher 时同步到当前标签路径，防止页面与 /new 不一致；切标签时避免多写一次历史。

## 验收范围

真实 dev 浏览器检查 +→/new、重复 + 不增历史、/new 刷新、session 刷新、/ 刷新、后退前进、外部关闭同步 URL、无效 ID 与非法编码回退。复测 + 按压不闪切。仅运行本次路由和 launcher 测试，不运行后端 CRUD/模型测试。按 dev BOOK 重建启动，保留 7500。

## launcher 切标签闪 main 修复

用户报告 main → + → Pure Chat 先闪 main。根因：window mousedown 外部关闭在 tab click 前执行，提前露出 active main。标签区内的 mousedown 不再触发外部关闭，交由标签 click 的 activateTab 同步收起 launcher 并切换 view；避免额外写入中间 / 历史。无 API 或静态关系变化。先扩充 pointer 用例，再修复与真实按压验证。
