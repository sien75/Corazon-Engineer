# 2611-75 蓝图的 ai 能力、监听能力、蓝图目录与 dev/prod

> 状态:已实现(Phase 2、3 完成,未提交,等 review)。承接 2611-74。落地时的四点差异与两个顺手修的 bug 记在文末"实现记录"。

## 目标

1. 蓝图能用 ai(会话可复用、可换)与监听外部来源,而不为此新增"ai 节点"。
2. 蓝图不属于项目:统一放在一个本机蓝图目录;engineer 开着,后端就常驻。
3. 开发与使用分离:dev / prod 各一个入口、各一个库。
4. 概念上把系统分成 **GUI 模式**(蓝图)与 **CLI 模式**(purechat,和 ai 服务挂钩的最简对话),两者都是和用户交互的面。

## 一、ai:不设节点,脚本 + 蓝图存储

- 蓝图用自己的存储保存 sessionId,逻辑写在脚本里。flow:`sql` 读 sid → `run` 脚本 → `sql` 写回。
  脚本:无 sid 则 `/ai/new`(带 `system` 提示词),有 sid 则只 `/ai/ask`;返回 `{reply, sid}`。
  换新会话 = 改/清存储里那一行。
- **删除内置 `ai` step**(`flow.go` / `runtime.go` 的 `runAI`、`followAI`、`aiArgs`)。
- ai 服务**不改**。现有接口够用:`/ai/new {cwd, system, title}`、`/ai/ask {id}`、`/ai/stream {id, since}`、`/ai/resume {id}`。
  两个坑写进提示词模板:复用会话时 `/ai/stream` 要传上一轮的 `since`,否则历史里旧的 `agent_settled` 会被当成这一轮结束;
  engineer 重启后复用旧 sid 前先 `/ai/resume`。
- 蓝图之间独立:不做公共 helper;ai 协议靠提示词里简短说明 + 一个 js 模板,各蓝图自带。
- 脚本与 ai 的 `cwd` = 蓝图目录。

## 二、init 节点:唯一能发事件的脚本

- 一个蓝图至多一个:`<script type="blueprint/init.js">`(也可 `.sh` / `.py`,与 `blueprint/js` 等并列)。
- 不接 flow、无 `on`、无 `id`:蓝图加载(或 dev 重启)时跑一次;需要监听什么、初始化什么,都写在这里。
- **只有它能发事件**:stdout 每行一个 JSON `{"emit":"<type>","data":{...}}`,运行时把它当成 `source: init` 的事件放上总线。
  其它脚本(`run`)保持纯 stdin → stdout,不能发事件。
- 不碰库:要写库就 emit 给 flow(flow 的 `sql` step)或前端处理,"库只经 flow / 前端写"的规则不变。
- 长驻允许,**不设超时**;stderr 每行仍是 `log` 事件。进程崩溃只报一条 `log` 事件,不自动重启。
- 重新加载(prod 刷新)/ 重启(dev)时,先杀掉旧 init 进程再起新的。
- 没有 flow 的 `init` 触发器;init 也不依赖 `maxHops`、不吃 10 分钟的 `scriptTimeout`。

## 三、蓝图目录

- 蓝图不再放项目的 `.agents/blueprints/`:engineer 的 web UI **首次打开时必须选定一个文件夹**(外壳弹窗,不是命令行参数,也不是进了 `/bp` 才提示),
  本机蓝图全放这里,该文件夹可自己 git 托管。浏览器拿不到本机文件夹的绝对路径,所以这个对话框是一个填绝对路径的输入框,服务端校验(存在、是目录;不存在可选择创建)。
  不引入"托管项目"概念。
- 扩展名仍是 `.html`;**不做**双击导入 / `engineer open`(没有专属扩展名,系统无法关联),也就没有"外来文件自动复制并执行"的问题。
- sqlite 库位置不变:`<home>/blueprints/`;代码是代码、数据是数据,蓝图目录里不含库。

## 四、dev / prod

| | prod | dev |
|---|---|---|
| 入口 | `/bp/<slug>` | `/bp-dev/<slug>` |
| 库 | `<home>/blueprints/<id>.prod.sqlite` | `<home>/blueprints/<id>.dev.sqlite` |
| init | engineer 启动时对**所有**蓝图运行(页面开不开都不影响后端) | **只在"重启"(试运行)时**运行,不随 engineer 启动 |
| 重载 | 页面上的**刷新按钮**(手动) | 页面上的**重启按钮**(手动) |

- 两者都**不自动重载**,文件改了不自动生效。
- 页面开不开只影响前端是否收发事件,不影响后端脚本与 sql。
- prod 与 dev 是两份独立运行时:各自的事件总线、库、init 进程,互不影响。

## 五、GUI / CLI 模式

- **GUI 模式** = 蓝图(`/bp`、`/bp-dev`)。**CLI 模式** = purechat:没有蓝图时也有的最简对话页,直接挂 ai 服务接口。
- 概念上分开,代码**先不拆**:purechat 仍在 `workspace/blueprint/shell/`,不新增 atom。

### 问 ai 服务

没有 `ai` 步骤. 脚本自己调 ai 服务: 它的地址在环境变量 `BP_AI` 里 (每个脚本都会注入), 会话 id 存在蓝图自己的表里,
所以什么时候沿用会话, 什么时候换新, 由 flow 决定.

- id 存在一张表里 (`CREATE TABLE IF NOT EXISTS chat(id INTEGER PRIMARY KEY, sid TEXT)`). flow 用 `sql` 步骤读出来,
  把 `{ sid, prompt, system }` 交给脚本, 再把返回的 `sid` 写回去. 没有这一行 (或 `sid` 为空) 就是新会话; 删掉这一行
  就是重新开始.
- 没有 `sid` → `POST /ai/new { cwd, system }` (系统提示词只在这里给一次). 有 `sid` → 不再给 `system`; 先
  `POST /ai/resume { id }` (engineer 重启后活会话没了), 记下它的 `lastSeq`.
- 然后 `POST /ai/ask { id, blocks: [{ type: "text", text }] }`, 读 `POST /ai/stream { id, since }` 直到
  `agent_settled`. **`since` 传 resume 返回的 `lastSeq`** (新会话传 0), 否则上一轮的 `agent_settled` 会让读取立刻结束,
  回复是空的. 回复文本在 `text_delta` 事件里.
- 请求体可以是 JSON (YAML 能解析); 返回是 YAML (`js` 脚本里用 `Bun.YAML.parse`); 流是 SSE, 事件是 `data:` 行里的 YAML.

一个能跑的 `js` 脚本 (测过): 入 `{ sid?, prompt, system? }`, 出 `{ sid, reply }`.

```js
export default async ({ sid, prompt, system }) => {
  const ai = process.env.BP_AI;
  const post = async (path, body) => {
    const r = await fetch(ai + path, { method: "POST", headers: { "Content-Type": "application/yaml" }, body: JSON.stringify(body) });
    if (!r.ok) throw new Error(`${path}: ${r.status} ${await r.text()}`);
    return r;
  };
  const yaml = async (r) => Bun.YAML.parse(await r.text());

  let since = 0;
  if (!sid) sid = (await yaml(await post("/ai/new", { cwd: process.cwd(), system }))).sessionId;
  else since = (await yaml(await post("/ai/resume", { id: sid }))).lastSeq;

  await post("/ai/ask", { id: sid, blocks: [{ type: "text", text: prompt }] });

  let reply = "", buf = "";
  const res = await post("/ai/stream", { id: sid, since });
  for await (const chunk of res.body.pipeThrough(new TextDecoderStream())) {
    buf += chunk;
    let i;
    while ((i = buf.indexOf("\n\n")) >= 0) {
      const frame = buf.slice(0, i); buf = buf.slice(i + 2);
      const text = frame.split("\n").filter((l) => l.startsWith("data:")).map((l) => l.slice(5).replace(/^ /, "")).join("\n");
      if (!text) continue;
      const ev = Bun.YAML.parse(text);
      const d = ev.assistantMessageEvent;
      if (ev.type === "message_update" && d?.type === "text_delta") reply += d.delta;
      if (ev.type === "error") throw new Error(ev.error?.message ?? "ai error");
      if (ev.type === "agent_settled") return { sid, reply };
    }
  }
  return { sid, reply };
};
```

## 实现记录(Phase 2/3 落地时与方案的差异)

1. **`--blueprints` 不是"保留为覆盖项",而是彻底去掉** —— launcher(dev 的 `launch.sh`、prod 的 `launch.go`)、
   BOOK、两个用例都不再传;测试要指定目录就往 data home 写 `config.yaml`。方案第七节里那句"保留为覆盖项"作废。
2. **`blueprint-config` 拆成两个契约**(`blueprint-config` 读、`blueprint-config-set` 写):gen-docs 按接口 id
   找同名契约文件,一个 id 只能对一个文件。
3. **脚本文件与 bun harness 留在 `<home>/blueprints/.work/<id>.<mode>/`,只有 `cmd.Dir` 是蓝图目录** ——
   蓝图目录是用户的、可能进 git,不能往里写临时文件。`process.cwd()`、`/ai/new` 的 `cwd` 仍然是蓝图目录。
4. **刷新/重启按钮由 `bp.js` 自己注入**(右下角,`reload` / `restart` 两个词,`bp.mode` 给页面用),
   不需要蓝图作者记得加。`op` 里 `reload` 与 `restart` 是同一个动作的两个名字。

### 顺手修的两个 bug(都是文档里早就写着、实际不成立的)

- `${{ event.data.<key> }}` 一直是 `nil`:`lookup` 把 `event` 这个 struct 直接交给 `dig`,而 `dig` 只认 map。
  现在 `Event.fields()` 先摊成 map。`${{ event.data }}` 也因此第一次真的能用了。
- `${{ steps.<id>.output.0.<column> }}` 一直是 `nil`:`store.Query` 返回 `[]map[string]any`,而 `dig` 只认 `[]any`。
  补了 `[]map[string]any` 分支。上面"问 ai 服务"一节的例子靠它才成立。

### 文档随之改掉的错(不在方案里,是写文档时发现的)

- flow 的 `with` 不能写成 `{ sid: ${{ … }} }` 这种 flow 风格 map —— `${{` 里的 `{` 在 flow 上下文是非法字符,
  YAML 直接解析失败。例子一律改块状。
- 存 sessionId 的那一句必须是 **upsert**(`ON CONFLICT … DO UPDATE`):第一段对话还没有这一行,`UPDATE` 一行都匹配不到。

### 事件流没有历史回放

`/events` 只推订阅之后的事件。init 脚本在启动时打的 log,页面后连上来是看不到的;用例因此改成
"先订阅,再 reload",崩溃那条用例让 init 延迟 1.2 秒再崩。这一条不是本轮要改的,记在这里免得下次又踩。
