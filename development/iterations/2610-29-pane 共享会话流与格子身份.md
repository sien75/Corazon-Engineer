# pane 共享会话流与格子身份

> 修 `2610-26`（句柄化的布局 id）留下的两笔欠账：**订阅按 pane 走**、**格子没有身份**。顺带把布局里的尺寸术语换成 flex 的。

## 需求

一个会话挂在多个 pane（同一个 tab 分屏，或者两个 tab）时：

- 在任意一处发送，**所有显示它的 pane 实时同步** —— 同一条流，不是各拉各的快照。
- 后台 tab 里还在跑的会话**不断流**：只要有 pane 登记着就保持连接（连接数 = 有 pane 的会话数，与 pane 数无关）。

## 现状（改之前）

**订阅长在 pane 上，不在会话上。** `aiStream(pane)`（`app.js:1706`）把连接与渲染状态都挂在 pane 上：

```js
pane.streamCtl / streamGen / seenSeq     // 连接 + 水位
assistant / thinking / tools（闭包）      // 渲染状态，其实是"这条流画到哪"
aiRenderPane = pane                       // 目标列表，单指针
```

即 **1 pane = 1 连接 = 1 份渲染状态 = 1 个目标列表**。于是：

| 事实 | 位置 |
|---|---|
| 只有发起的那一格订阅：`aiSend` → `aiStream(pane)` | `app.js:1994` |
| `activateTab` 只订阅第一个 chat pane（`firstChatKey`） | `app.js:2578` |
| 切走 tab 掐掉该 tab 全部 pane 的流 | `app.js:2597` |
| 另一格只有创建/切回时的一次 `/ai/resume` 快照 | `app.js:3589` |
| 设计注释写明假设："for the same session we must not open a second subscription" | `app.js:1702` |

**后端本来就能多播**：`listeners: Set<Listener>`（`registry.ts:247, 698-702`），`/ai/stream` 每个连接各带自己的 `since` 回放（`server.ts:147-192`）。缺的只有前端扇出。

**格子没有身份。** 树里 `pane.id` 是内容 id（`layout.ts:14`：「A pane's id is its content id … so the same content may appear in two panes」），前端只能拿**树路径**当 key（`buildPaneNode` 的 `path.join(".")`，`app.js:815`）。改树后路径会漂：新格插在前面，老 pane 从 `"0"` 变 `"1"`，`ensurePane` 认不出 → 建新 pane 对象，老的留在 `tab.panes` 里变孤儿，**它的流还活着，往一段已脱离文档的 DOM 里画**。

**两条后端事实**（决定水位怎么管）：

- `sess.events` 无上限、会话无 TTL/淘汰，只在 `ai/delete` 时消失（`registry.ts:246, 560-570`）→ 同进程内 `since` 重放可靠。
- 但 `seq = sess.events.length + 1`（`registry.ts:709`），而 `resume` 从 log 重建时 `events: []`（`registry.ts:395-410`）→ **重建后 seq 从 1 重数，任何被缓存的 seq 水位都会失效。**

## 决策

1. **一个会话一条 SSE。** 前端加 hub 层，事件先到 hub、由 hub 分发给所有登记过的 pane。**不是**每个 pane 各开一条。
2. **引用计数决定断流。** 还有 pane 登记就保持连接（后台 tab 不断）；最后一个退订才 abort。
3. **本地回声归 hub。** 用户气泡不是服务端事件（`aiSend` 里 `aiAppendUserParts` 只画到发送格，`app.js:1975`），所以 hub 有**两个输入源**：SSE 事件 + 本地回声。否则分屏下另一格看不到你刚问的问题。同理 `ask_user` 提问、`[error]` 气泡、停止键状态，全部升到 hub 级。
4. **树里加格子身份 `paneId`。** 内容身份与格子身份彻底分开。
5. **布局尺寸术语换成 flex 的**，合并成单个 `flex` 字段，照 CSS 语义。
6. **不写 `flex` = `1 1 0`（均分）**，不是 CSS 的初始值 `0 1 auto` —— 后者会让 chat pane 缩到内容宽度。这是唯一一处与 CSS 语义的偏离，必须写进工具说明。
7. **旧树不迁移。** 读的时候缺 `paneId` 就内存补一个，下次写树时落盘。pane 对象本来就不跨刷新存活（刷新后历史从 log 重放），身份只需在一次页面会话内稳定。
8. **文档与示例一律用占比**（`flex: 2 1 0`），px 只在数据结构上合法，不作为推荐写法。

### 树的新形状

```yaml
# 叶子
pane:
  paneId: p_a1                 # 唯一标识：这是哪一格
  contentType: chat | page     # 内容类型
  contentId: s_c996            # 内容 id：这段对话 / 这个 blueprint
  flex?: "0 0 320px"           # CSS flex 简写；不写 = 1 1 0

# 分割
split:
  flexDirection: row | column  # flex-direction
  flex?: "2 1 0"
  children: [ ... ]
```

| 现在 | 改后 |
|---|---|
| `pane: { content, id }` | `pane: { paneId, contentType, contentId, flex? }` |
| `{ split: "col", weight: 2, children }` | `{ split: { flexDirection: "column", flex: "2 1 0", children } }` |
| `pane.size: "brief"` | 删；`flex: "0 0 132px"` 可表达，但不推荐 |
| CSS `--w` 变量 + `splitEl(dir, weight)` | `el.style.flex = value`，直接写 |

`paneId` 由工具发（`p_` + 8 hex），模型不编 —— 与 session id 同一套规矩：**保留一格就把读到的 `paneId` 原样传回，不传 = 新格子。**

## 方案

### 前端 `workspace/web/app.js`

- 新增 hub 层：`aiHubs: Map<sessionId, { id, ctrl, gen, seenSeq, renderState, panes: Set, streaming }>`。
- `aiStream(pane)` → `hubAttach(hub)` + `hubSubscribe(hub, pane)`；`aiCancelStream(pane)` → `hubDetach(hub, pane)`（归零才 abort）。
- 渲染拆成两步：**推进一份 renderState**，再把结果写进 `hub.panes` 里每个列表。
- **新 pane 中途加入**：先 `aiLoadSession` 回放 log 历史（只有完整 turn），再由 hub 按 `renderState` 重画 in-flight 的半截内容 —— 今天靠 `lastSeq` 从半个句子接起，这是 B 顺带修掉的 bug。
- **水位经 `/ai/resume` 重新取，不落盘、不跨 incarnation 复用**（见上面第 2 条后端事实）。
- `tab.panes` 改 `Map<paneId, pane>`；树是"有哪些格、怎么排"的唯一来源，树变化按 `paneId` 对账：交集复用（DOM / 历史 / 滚动 / 订阅都在）、消失的拆（退订）、新的建。
- `ask_user` 提问、停止键、`[error]` 升到 hub 级：任一格作答/停止，所有格同步。
- **删**：`aiRenderPane` 单指针、pane 上的 `streamCtl/streamGen/seenSeq`（`streaming` 归 hub）。

### 后端 `workspace/ai`

- `src/layout.ts`：类型；`normalizeLayout` 生成 `paneId` 并加两条校验（同树内 `paneId` 不许重复；传了但不在本 tab 当前树里 → 报错并列出本 tab 的格子；根节点不许写 `flex`）；`flex` 按窄白名单校验（`<grow> [<shrink>] [<basis>]`，grow/shrink 整数 0..3，basis 是 `0` | `auto` | `<n>px`，其余一律拒；`flex: "0 0 320"` 无单位也拒）；`describeLayout` 带上 `paneId`。
- `src/registry.ts`：工具说明（`117-139`）与头注释 —— 头注释现在写着 *"asks it to hold no pane ids at all"*，**这是当初的有意选择，本次反转它**，注释里要写清理由（一个会话多视图 + pane 现在持订阅，身份必须稳定）。
- `docs/ai.md`、`.agents/skills/pane-layout/SKILL.md`：形状、术语、示例全部改（skill 现在写的正是 `{pane: {content, id}}` 和 weight 版示例）。

### 不用改

`contracts/` —— `log-tab-mutation.yaml:7` 明说 layout 是 opaque `object`，log 不理解其结构。

顺手修 `app.js:2033` 那句过期注释（"The tree is not rendered yet"，但 `renderPanes` 早就真的渲染 split 了）。

## 验收

- 同一 session 挂在两个 pane（或两个 tab）时，任一处发送，所有视图实时同步；关掉其中一个，另一个不受影响。
- 后台 tab 里正在跑的会话不断流，切回来无缝。
- 改布局（含模型调 `layout` 工具）后，原有 pane 的 DOM / 历史 / 滚动位置 / 订阅都在，不出现孤儿 pane。
- 服务器重启后会话仍可用：水位重新取，不出现"事件被 seq 过滤掉、屏幕不动"。
- 两格各有独立滚动，左格翻历史不被右格拽到底。

## 未采纳 / 待定
