# main 与工作区：外壳只剩一个对话，tab 交给 main 的工具

## 需求

1. 删掉 web 外壳上所有固定 tab（graph / how-to / development / contracts / docs / notes），
   只留一个 **main**：外壳自己承载的那段对话。
2. 没有 main 就在启动时建一个，存在 log 里；main 里的「clear」= 再建一个新 main 会话，
   旧的保留不删。
3. 会话分 **main / sub** 两种：`sessions` 表里 `kind` 为 `main` 或 `sub`（缺省 `sub`）。
4. blueprint 页面里的 agent（sub）没有工作区能力：不能 new、delete、list、resume、改布局；
   保留 pi 内置工具 + `ask_user`。开 / 关 / 拆分 / 删除 tab 都由 main 做。
5. main 的工具：`session-list`、`session-resume`、`tab-list`、`tab-mutation`、`tab-on`、
   `tab-off`、`tab-delete`；`layout` 工具下线。
6. 工作区状态必须有一份 SSOT，不放 localStorage：`current` 表（单行）记当前开了哪些 tab
   以及 main 会话。
7. `agents/` 按角色拆分：`agents/main/AGENTS.md`、`agents/sub/AGENTS.md`（中文镜像
   `agents/zh/main|sub/AGENTS.md`）。

## 决策

- **SSOT 在 log 的 sqlite**：`sessions`、`tabs`、`current` 三张表。前端不再往 localStorage
  写 tab（theme 仍留着）。
- **`current` 是单行表**：`open_tabs`（JSON 数组，按显示顺序）+ `main_session`。
  `tab/new` 自动入列，`tab/off` 出列但保留记录，`tab/delete` 删记录并出列；
  `current/put` 只用于修复/重排。
- **main 不是 tab**：它没有 tab 记录，只有 `current.main_session`；前端刷新后永远落在 main。
- **tab 的样子由 ai 的工具写 log，前端按工具帧重新读**：main 在外壳里，外壳自己消费 main
  的流，所以 `tool_execution_end` 就是「重读 current/tabs」的信号；不做 ai → 前端回连。
- **resume 由外壳负责**：启动时读 `current` → 读每个 tab 的 layout → 取出所有 sessionId →
  逐个 `/ai/resume`，然后才画页面。页面自己不 resume。
- **会话没有记录也能 resume**：实例化出来、还没问过的 agent 有 `sessions` 行和副本；
  resume 从副本的 README 重建（否则重启后页面的第一次提问会 404）。
- **删除一处不能漏**：删会话 = live 会话 + records + `sessions` 行 + 副本；
  删 tab = `tabs` 行 + `current` 里的 id。
- **`layout` 工具删除**；布局只有 `tab-mutation` 一条路。

## 实现

### log（Go）

- 新表：

```sql
CREATE TABLE sessions (session_id TEXT PRIMARY KEY, kind TEXT NOT NULL DEFAULT 'sub', created_at TEXT NOT NULL);
CREATE TABLE current  (id INTEGER PRIMARY KEY CHECK (id = 1), open_tabs TEXT NOT NULL,
                       main_session TEXT NOT NULL DEFAULT '', updated_at TEXT NOT NULL);
```

  启动时建表、插 `current` 单行，并从 `records` 回填 `sessions`（`INSERT OR IGNORE`，
  老项目不需要迁移脚本）。
- 新接口：`log/session/upsert`、`log/session/detail`、`log/current/get`、`log/current/put`、
  `log/tab/off`、`log/tab/delete`；`log/tab/new` 现在会把 id 加进 `current`；
  `log/delete` 同时删 `sessions` 行并清掉 `main_session`；`log/list` 每条会话带 `kind`。

### ai（Bun/TS）

- `blueprint.ts`：整目录复制（上一单），不变。
- `registry.ts`：
  - `Sess.kind`（main/sub），`new(blueprint?, kind)` 写 `log/session/upsert`；
  - `resume` 读 kind（没有行且没有记录 → 404；有行没记录 → 用副本 README 重建）；
  - 每个会话按 kind 选 spec（`--agents` 现在是目录：`main/AGENTS.md`、`sub/AGENTS.md`）；
  - 工具：所有会话 = pi 内置 + `ask_user`；main 另加七个工作区工具；`layout` 删除；
  - `deleteSession(id)`：dispose + 删副本 + `log/delete`。
- `workspace.ts`（新）：七个工具的实现。tab 工具只读写 log，不做前端回连。
  `tab-mutation` 复用 `normalizeLayout`（paneId 填充、flex 校验、`blueprint` 叶子现开 agent）。
- `server.ts`：`/ai/new` 收 `kind`；`/ai/ask` 去掉 `tabId`。
- `main.ts`：`--agents` 读目录下的两份 spec。

### web（外壳）

- `index.html`：只剩 topbar（logo + tab 条 + theme）和 `#panes`；固定视图、graph、launcher 全删。
- `app.js`：保留 pane 树 / chat pane / markdown / 芯片 / 图片粘贴 / 主题；删掉 graph、static
  视图、launcher、命令抽屉（`/new` `/list` `/resume`）、localStorage tab。
  - `boot()`：读 `current` → 确保 main 会话（没有就 `/ai/new {kind:"main"}` 并写回）→
    读开着的 tab 记录（记录没了的从 `current` 摘掉）→ 逐个 resume → 渲染 → 始终激活 main →
    回放 main 的历史。
  - tab 条：main（带 ⟳ = clear，新 main 会话，旧的保留）+ 每个打开的 tab（× = `tab/off`）。
  - 工具帧（`tab-*` / `session-*`）→ `refreshWorkspace()`：重新读 `current` + `tabs`，
    新增的 tab 自动激活，删掉的摘掉，布局变了的重建。
  - 页面 tab 的名字取第一格 iframe 的 `document.title`。
- `style.css`：`#panes > .pane` 撑满、`.pane[hidden]`、iframe `min-height: 0`（否则 iframe 被
  150px 的固有高度卡住）。

### agents 拆分

```
agents/main/AGENTS.md        main：工作区、tab/会话工具、开发规范
agents/sub/AGENTS.md         sub：页面、ask_user、无工作区工具
agents/zh/main|sub/AGENTS.md 镜像
```

`--agents` 由文件改成目录；launch.sh / prod launch.go / 两份 BOOK / 所有用例同步。

## 验证（真跑）

- **浏览器**：boot 建 main（`sessions.kind=main`、`current.main_session`）；
  对 main 说「用 tab-on 开一个 simple」→ 新 tab 自动激活、iframe 加载；
  「用 tab-mutation 拆成 2:1」→ 两格 iframe 宽度 1551 / 775、高度 1137；
  tab 的 × → `tab/off`、回到 main；关闭的 tab 出现在 `tab-list` 的 closed 里，
  `tab-delete` 后 `tabs` 行、`sessions` 行、records、`.engineer/agents/<id>` 全部消失。
- **重启后 resume**：停掉整套 dev 再起，刷新外壳 → main 历史回放（29 条），
  点开恢复的 tab，页面里提问得到回答（说明 boot 的 resume 覆盖了「还没问过的 agent」）。
- **`case-core-log-workspace`（新）** 1–7 全过：空工作区、kind 缺省 sub、main 指针、
  tab new 入列、off 出列且记录还在、delete 删记录且重复删除 404、删 main 会话清指针。
- **`case-core-agent-instantiate` 1–7 重跑通过**（`--agents` 改为目录后）。

## 已知遗留

- 旧的 E2E 用例里有一部分描述的是已经删掉的东西，**没有重写**：
  `case-core-web-tabs`、`case-core-web-page`（launcher / 固定视图）、
  `case-core-web-panes`（layout 工具）、`case-core-web-chat-route` / `-scroll` /
  `-controls` / `-input-*`（独立 chat pane 的交互）、`case-core-web-tab-records`
  （localStorage 恢复）。它们现在会失败或失去意义，应随下一单重写或删除。
- `main` 的 clear 只换会话，不删旧 main 的历史（按需求保留）。
- 多窗口共享一份 `current`，后写的覆盖先写的（先按单窗口假设）。
- 删 tab 同时删掉它所有 agent 的记录与副本，没有回收站。

## 追加（review 后）

- **launcher 回来**：`+` 打开一个轻量弹层（不是视图），列 `New main conversation`、Blueprints（static）
  和 Recent（log，`kind=sub` 且排除当前 main）。选蓝图 → `/ai/new` + `log/tab/new` +
  `log/tab/mutation`，和 main 的 `tab-on` 写同一种记录；选 recent → 先确认 `/agent/<sid>/`
  存在，再开 tab。tab 因此有两个入口：main 的工具，和 launcher。
- **main tab 不再带按钮**：clear 挪进 launcher 的第一行（旧 main 会话保留）。
- 关闭按钮改成淡色小 ×，hover 才明显；logo `flex:none; white-space:nowrap`，tab 条自己滚动。
- **`/agent/…` 不再回落到外壳**：副本没有那个文件就 404。否则缺失的副本会在 iframe 里画出
  一层外壳（旧遗留）。launcher 打开一个没有副本的旧会话时给出 toast，不再开一个空 tab。
- tab 名在打开前就取：`fetch /agent/<sid>/` + DOMParser 读 `<title>`（按 session 缓存），
  不必点开 iframe。

## 追加：对话收敛成 `<engineer-chat>` 组件

- 新资产：`workspace/web/components/chat.js`（自定义元素）+ `components/chat.css`（原 `/chat.css`
  搬进来）。`--assets` 根直接服务 `/components/…`，服务端没改。
- 组件自包含：shadow DOM + 自带样式；`session` 属性或页面地址 `/agent/<sid>/`；`/config.js`
  自己加载；`autofocus`；`history` 从 log 回放（main 用）。事件 `engineer-tool`
  （`{name, isError}`）——main 的 `tab-*` 工具靠它让外壳重读工作区。
- **main 也改成这个组件**：`app.js` 里约 2000 行 chat 实现（composer/流/渲染/图片/历史/hub）
  全部删除，剩 tabs / launcher / page panes / boot / refresh。main 的历史由组件的 `history` 回放。
- `simple` 蓝图缩回两个文件：`README.md` + `index.html`（主题脚本 + `<engineer-chat>`）。
  对话细节不再写在模板里，how-to 只说「引 `/components/chat.js`，放一个 `<engineer-chat>`」。
- 打包/文档同步：prod BOOK 增加 `components/`；atoms/web、`components/README.md`。

验证：main 组件挂载并回放历史；发消息得到回复；`tab-on` 工具帧 → 新 tab 实时出现并激活；
新建 simple 实例的页面里组件收发正常。
