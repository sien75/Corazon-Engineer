## 二、"light / warm / cold 生效,dark / slate 不生效"的原因(已修)

- 那不是主题半生效,而是**主题从来没进过 iframe**:外壳只在自己的 `<html>` 上设 `data-theme`,
  蓝图页另有自己的 document,只有它自己 link 了 `/theme.css` 才拿得到变量;目录里那两个页面都没 link。
- 第一版我给每条颜色加了**亮色 fallback**(`var(--border-strong, #d8dde5)` …)。于是:
  - light / warm / cold:本来就是浅色,看起来"对了"——其实是 fallback 的颜色;
  - dark / slate:外壳变深,frame 里仍是这套亮色 fallback,所以"不生效"。
- 修法(这次做了):主题由外壳交给 frame(`workspace/web/shell/app.js`)
  - `frameFor` 里给 iframe 挂 `load` → `dressFrame`:同 origin,往 frame 的 `documentElement` 写 `data-theme`,
    并在 head **最前面**插一个 `/theme.css` 的 `link`(带 `data-engineer-theme` 标记,插最前是为了让页面自己的样式仍能覆盖)。
  - `applyTheme` 里调 `dressFrames()`:所有已开的 frame 立刻跟着换,不用重载。
  - 蓝图页因此**不需要知道主题存在**;自己 link 过 theme.css 的页面只是多一个同 URL 的 link。
  - fallback 保留:直接打开 `/bp/...`(不在外壳里)时页面仍有一套能看的亮色。
- 代价:frame 是载入后才上色,深色主题下新开一个 tab 可能有一瞬的浅色。要消掉得在 shell 侧给 iframe 先铺
  `--surface` 底色,或改成 blueprint 服务注入一小段引导脚本(读 localStorage),都还没做。
