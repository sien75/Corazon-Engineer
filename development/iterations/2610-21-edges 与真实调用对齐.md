# edges 与真实调用对齐

## 需求

上一轮（2610-20）我提了两件事，用户定「和代码对齐」：schema 描述代码实际的样子，而不是把代码改成 schema 的样子。

1. `edges/` 里缺流式边。
2. `/ai/stop` 的 500 用 `ai_error` —— 契约已经如实写了 `ai_error`，**无需改动**（不改代码去迁就 `internal`）。

核对时发现"缺边"不止一处，而且和我上一轮的判断不完全一样，逐条查了调用方再落。

## 现状（谁真的调了什么）

以调用点为准，全仓扫了一遍：

| 调用方 | 路径 | 出现位置 |
| --- | --- | --- |
| shell | `/ai/stream` | `workspace/web/app.js:1564` |
| blueprint | `/log/query` | `.agents/blueprints/log-viewer/index.html:94`、`service-endpoints/index.html:91` |
| blueprint | `/log/query-detail` | `.agents/blueprints/log-viewer/index.html:118` |
| blueprint | `/static/validate` | `.agents/blueprints/validate-report/index.html:71` |

- **`ai-stream` 有 consume（在 `atoms/web.yaml`）、没有边**：漏登记。
- **`log-query-detail`、`static-validate` 两边都没有**：漏登记。（`static-validate` 原只在 ai 侧登记——ai 自己调；web 侧的调用来自 blueprint 页面。）
- **`log-stream` 的 consume 是幻影**：`git log -S "/log/stream" -- workspace/web` 没有任何提交命中——前端从没调过它，blueprint、skill 里也没有。它只是当初写进 schema 的"打算"。
- **`log-query` 的 consume 和边其实是真的**：虽然 shell 的 `app.js` 不调它（`git log -S "/log/query" -- workspace/web` 同样零命中），但 **blueprint 页面调**——`log-viewer` 就是那个"records panel"，边原来的描述说的正是它。我一开始按"shell 代码不调"误判为幻影，查了 blueprint 才纠正。
- blueprint 页面归谁：blueprint 是项目资源、不是 atom，由 web 的 `serve-web` 在多 root 下服务到浏览器、与 shell 同源（`atoms/web.yaml` 描述里已写明 `/pages/<id>/` 与 `--pages`）。所以这些调用记在 web 上，是这张图里唯一说得通的归属。

## 决策

1. **补 `web-to-ai-stream`**：`ai-stream` 已有 consume，补边即可。
2. **补 `web` 的 `log-query-detail`、`static-validate` consume + 对应边**：调用方是 blueprint 页面，归属 web。
3. **保留 `web` 的 `log-query` consume 与 `web-to-log` 边**，描述改成说清是 blueprint 在读记录（原来的描述"records panel"是对的，只是没说出口）。
4. **删 `web` 的 `log-stream` consume**：全仓零调用，是当初的"打算"而非事实；`log` 侧仍提供该接口（服务可以多提供，图只记谁用）。
5. **不动 `/ai/stop` 的 `ai_error`**：契约与代码一致，本轮零改动。
6. **不把"provider 无人消费"当成错误**：`log` 仍提供 `log-search`、`log-stream` 两条无人调用的接口。它们有契约、有文档，是服务的 API 面；删它们等于删能力，是另一个决定。

## 范围外

- 不动任何服务代码、不动契约、不动 `docs/`（docs 是"服务提供什么"的参考，不是"谁在用"）。
- 不动 blueprint 页面本身。
- 不删 `log-search` / `log-stream` 两条接口——留待用户决定。

## 方案

- `edges/web-to-ai.yaml`：加 `web-to-ai-stream`（web → ai，`ai-stream`）。
- `atoms/web.yaml`：consume 增 `static-validate`、`log-query-detail`；删 `log-stream`。
- `edges/web-to-log.yaml`：加 `web-to-log-query-detail`；`web-to-log`（`log-query`）描述改为点明 blueprint。
- `edges/web-to-static.yaml`：加 `web-to-static-validate`。

## 验收

- `POST /static/validate` → `ok: true`、`errors: []`。
- 自查脚本：每条边的 `from_interface` 都能在 from atom 的 consumes 里找到、`to_interface` 都能在 to atom 的 provides 里找到；每个 consume 都有边。
- 全表对照：库里的调用点与 schema 里的 consume 一一对上，不多不少。
- 无代码改动，无需跑 E2E。

## 实施记录（Phase 3）
