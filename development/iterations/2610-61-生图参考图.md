# 2610-61 生图工具收参考图

## 需求

`image` 工具现在只会「从无到有」画一张。要能**按已有图片生成新图**：改这张、派生这张、
以这张为底。

## 设计

### 1. 参考图就是一个路径

不引入「图句柄」之类的会话状态。这个系统里命名一张图的写法已经存在两种，都能直接传：

- `image` 工具的结果正文里本来就有绝对路径（`file: <home>/.engineer/uploads/<sha>.png`）；
- 粘贴的图进模型上下文只有像素，**没有**名字 —— 所以补一处：`registry.ts` 的 `ask()`
  在图片块后追加一行 `[image: <path> — /blobs/<sha256>]`，那行进 pi 的会话历史，下一轮
  模型就能把它当参数传回来。

`reference` 接受三种拼法，都解析成同一份字节：文件路径（相对 cwd / 相对 engineer home）、
`/blobs/<sha256>`、裸 `<sha256>`。上限 8 张、单张 20MB（参考图整体进请求体，与其等网关回
413，不如自己先拒）。取到的字节先 `saveImage` 进同一个内容寻址存储 —— 传进来的图都变成
blob，log 记下的就是发出去的那一张，源文件之后改动也不影响。

### 2. 有参考图 = 走编辑

- 形状 1（有参考图）：`POST {baseUrl}/images/edits`，multipart：`model` / `prompt` / `n` /
  `size` + `image`（单张）或 `image[]`（多张）。Content-Type 交给 fetch 写 boundary。
- 形状 1（无参考图）：保持原样，JSON 打 `/images/generations`。
- 形状 2（chat 网关）：`modalities:["image","text"]`，参考图作为 `image_url` part（`data:` URL）
  和文字放进同一条 user 消息。

降级规则不变：只有 404/405 才换形状 —— 「这个网关没有 images 端点」是网关属性；而
「这个模型不收图片输入」是 4xx，原样报给模型，不换形状重试（那只会再买一次失败）。

`details` 多一个 `references: [{sha256, mimeType}]`，正文首行加 `from N reference image(s)`。

### 3. 模型收不收，是能力问题

不改按模型的能力表（现在只有尺寸档）。gpt-image 系列收参考图，dall-e 3、多数纯文生图模型
不收；不给静态黑名单 —— 网关的 4xx 文案比一张要维护的表准。

## 范围

- 改：`workspace/ai/src/images.ts`（`reference` 参数、multipart 编辑、chat 形状带图）、
  `workspace/ai/src/blobs.ts`（`findBlobFile` 导出）、`workspace/ai/src/registry.ts`（粘贴图标记）。
- 改文档：`agents/main|sub/AGENTS.md`(+zh)、`atoms/ai.yaml`、`docs/ai.md` 的 image 工具那句。
- 不改：`chat.js` / 页面 —— 结果还是 `details.images` 那一套，参考图不显示。
- 不做：参考图的来源白名单、页面上的「以此图再生成」按钮。

## 验证

1. `bunx tsc --noEmit`（workspace/ai）干净。
2. 真跑：拿 home 里已有的一张 blob 当参考图，`zenmux-openai/openai/gpt-image-2` 走
   `/images/edits`，看返回图落 blob、`details.references` 有值、`/blobs/<sha>` 可回读。
3. 无参考图的调用回归一次（`/images/generations` 仍通）。

### 结果（PASS）

- 冒烟（直接调工具）：路径引用、`/blobs` 引用、无参考图三种都出图；夜景色/铅笔稿两次
  是真按参考图改的；`details.shape` 分别是 `images-edits` / `images-edits` / `images`。
- `development/testing/dev/case-core-ai-image-reference`（真模型 + 真生图，端口 9130-9132）：
  sub 会话发一张 32×32 红图，模型把标记里的 `…/uploads/<sha>.png` 原样当 `reference` 传回
  （该路径只可能来自标记），工具正文 `from 1 reference image(s)`，
  `details.references[0].sha256` 等于粘贴图的内容地址，新图另落一个 blob 且 `/blobs` 200、
  下载字节的 sha 与地址一致、图确实是红→蓝。
- 遗留：`shape` 一开始写死成 `images`，已改为 `images-edits`（编辑分支）并复验。

## 风险

- 有的网关 `/images/edits` 存在但只收单图；多图 `image[]` 会被 400 —— 报错原样回给模型，
  模型可以改成一张。
- edits 的 `size` 语义（输出尺寸）与 generations 略有差别，先沿用同一套档位。
