# 2611-76 多文件夹(项目)与前台切换

> 状态:已实现(Phase 2、3 完成,未提交,等 review)。承接 2611-75:那里是"一台机器一个蓝图目录",这里改成多个。

## 目标

- 蓝图目录可以有多个,每个叫一个**项目**。
- 右上角、**主题按钮左边**加一个切换按钮(主题菜单那样的下拉),列出已导入的项目 + "添加文件夹…"。
- 切换只是**换前台**:不启不停任何运行时。导入(添加)即执行;删除才停止执行。
- 执行的含义沿用 2611-75:prod 运行时在**载入时**起(建表 + 起 init),dev 在打开页面时才起。

## 一、配置(`<home>/config.yaml`)

```yaml
projects:
  - id: notes                     # 目录名 slug,撞名时 -2、-3
    path: /Users/me/blueprints    # 绝对路径,用户选的
foreground: notes                 # 前台项目的 id
```

- 旧格式 `blueprints: <path>` 读时当单体列表迁移(写回新格式),不另留兼容分支。
- 添加:路径校验、`mkdir -p`、分配 id、**立刻**为该项目的每个蓝图载入 prod 运行时(建表 + init)。
- 删除:先停该项目的 prod 与 dev 运行时(杀 init、关库),再从配置里删。**库文件不删**(数据是数据),
  蓝图目录本身也不碰(用户的)。
- 切换:只改 `foreground`,不动运行时。

## 二、身份与路由

现在是 `/bp/<slug>`,一个 slug 全局唯一。多项目下 slug 会撞(两个目录各有一个 `notes.html`),
而且"前台切换"之后,一个已经打开的页面不能因为前台变了就指向别的项目。

所以路由要带上项目:**`/bp/<project>/<slug>`** 与 `/bp-dev/<project>/<slug>`(`/bp` 列前台项目的蓝图)。

- 库仍然按 `<meta id>` 落,但**按项目分目录**:`<home>/projects/<project>/<id>.prod.sqlite`。
  两个项目里同名 `<meta id>` 的蓝图各自一份数据,不互相覆盖。
- 页面里的 `bp` 前缀就是 `/bp/<project>/<slug>`(沿用现在"从 script 标签的 src 推出来"的做法)。

## 三、Registry

- 每个项目一套 `prod` / `dev` 注册表(现有 `Registry` 加 `project` 字段即可);
- 一个总表 `map[projectID]*Project`,每个 Project 持有 `path` 与两份 Registry;
- 前台只影响 `/bp` 列表与 shell 的默认落地页;
- 添加/删除的入口只有配置接口,和页面上的按钮。

## 四、接口(替换 2611-75 的两个配置接口)

- `GET /config/projects` → `{projects: [{id, path}], foreground: id}`
- `POST /config/projects` → `{path}` 添加(或已存在则返回已存在的 id)
- `POST /config/projects/foreground` → `{id}`
- `DELETE /config/projects?id=` → 停止该项目的运行时并从配置移除
  (用 POST `/config/projects/remove` 也行,看实现顺手;倾向 DELETE,语义更准)

`/bp/<project>/<slug>` 的 project 不是已知项目 → 404。

## 五、UI

- 主题按钮左边一个按钮(项目名),点开是菜单:每个项目一行(当前的前台打勾)、分隔线、"添加文件夹…"、
  每行的删除(×,带确认)。
- "添加文件夹…" 打开 2611-75 那个对话框(输入绝对路径)。
- 没有项目时:外壳仍被对话框拦住(和 2611-75 一致),选完就导入。

## 实现记录(与方案一致,外加两处)

1. 方案四条全部按原样落地:`/bp/<project>/<slug>`、库分到 `<home>/projects/<project>/blueprints/`、
   删除只停不删、项目 id 取目录名(撞名 `-2`)。
2. 顺带修的:**服务收到 SIGTERM/SIGINT 时把 init 子进程一起收走**。init 自成进程组,kill 父进程够不着它,
   否则每次重启都会留下一份监听(用例里"重载后速率不翻倍"验证的就是这件事的另一面)。launcher 的 `stop.sh`
   也因此在第一次就停不干净(`web.pid` 缺失那次),现在服务自己会收尾。
3. `config.yaml` 的旧键 `blueprints` 只读不写(`omitempty`),读到时迁移成一个项目再写回列表形式。
4. 文档随之改了:契约换成 `blueprint-projects` 四件套(`GET` / `POST` / `POST foreground` / `DELETE`),
   `structure/docs` 重新生成、README 手工同步,`agents/` 的蓝图两节与 sub/main 的说法都改成"项目 + 带项目的地址"。
