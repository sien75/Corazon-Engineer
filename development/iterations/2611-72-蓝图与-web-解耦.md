# 2611-72 蓝图与 web 解耦

## 目标

web（shell）和蓝图各管各的:web 的组件、库、主题只属于 web;蓝图页就是一个自带资源的 html 目录,不再依赖 shell 提供的任何东西,也不再要求带 `<engineer-chat>`。为重构蓝图腾位置。蓝图页将来怎么放对话、调哪些接口,本轮不定。

## 改动

- 删除项目里现有的三个蓝图 `.agents/blueprints/{development,library,structure}`。
- 删除 `.agents/BLUEPRINT_how-to{,_zh}.md`。通用部分(目录形态、两个必需文件、相对路径、`<title>`、不用 CDN、改动/建议的做法)挪到 `agents/blueprint.md`(含 `zh/`);shell 专属部分(`/components`、`/vendor`、`/theme.css`、`/config.js`、一页一个 chat)不再写进任何蓝图说明。
- ai:`blueprint.ts` 去掉「恰好一个 `<engineer-chat>`」检查(`countChatSlots` 与报错),实例化只检查 `README.md` / `index.html` 两个文件;sub 的 reference 行加上 `blueprint.md`。
- 文档:`agents/sub/AGENTS.md`(含 zh)去掉 chat 规则与对 `BLUEPRINT_how-to` 的指向,改指 `blueprint.md`;根 `AGENTS.md` / `_zh` 的第三类重新梳理:范围是 `how-to/`、`agents/`、本项目 `AGENTS.md` 与 skill,不点名具体文件;`humanwrite/` 默认不改,用户明确要求才改。
- 测试:`case-core-agent-instantiate` 删掉 nochat / twochats 的拒绝断言(规则已不存在)。

## 不做

- web 的 `/components`、`/vendor`、`/theme.css`、`/config.js` 保持原样,仍是 web 自己的;因为同源,蓝图页技术上仍能请求到,但不再是承诺的接口,文档里不写。
- 不碰 web 对 `/agent/<sessionId>/` 的伺服、不设计蓝图的对话方式与接口。
- 历史迭代记录、`humanwrite/` 不改。

## 验证

`case-core-agent-instantiate`(更新后)通过;其余 case 里用到 `<engineer-chat>` 的探针页不受影响(多出的标签无害)。
