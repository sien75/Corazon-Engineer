# 页面与主题一致（page 的主题跟随）

## 需求

page（iframe 里的蓝图）应该**跟着外壳的主题走**：切 light / dark / solarized 时，页面一起变；
也不再在暗色下看到白底（加载白闪）。

## 现状

- 主题就是 `<html data-theme="light|dark|solarized">`（`app.js:341 applyTheme()` 是唯一入口），
  调色板是 `style.css:7-96` 的三段 CSS 变量（`:root` / `[data-theme=dark]` / `[data-theme=solarized]`）。
- 主题存在 `localStorage["engineer.theme"]`。
- page 是**同源** iframe（`/pages/<id>/`），但 iframe 是独立 document：外壳的 CSS 变量不继承进去，
  而且 `#page iframe { background: #fff }` 是写死的白。

## 决策

1. **继续用 iframe，不改 Shadow DOM**。Shadow DOM 的诱惑是「CSS 自定义属性会跨 shadow 边界继承」，
   主题确实能免费跟随；但它换掉的是蓝图最值钱的性质——**任意 html 丢进来就能跑**：
   - `<script>` 用 innerHTML 注入**不会执行**，得逐个重建脚本节点；
   - 蓝图脚本在同一 realm 里，`document` / `location` / `title` 等一律指向外壳，`document.querySelector`
     找自己就找不到，很多库直接废；
   - 影子树里没有 `html` / `body`，蓝图的 `:root{…}`、`body{…}` 选择器**全部失效**；
   - 相对资源路径的基准变成外壳文档，`./app.js` 的含义变了。

   结论：蓝图的定义就是「一个前端资源、单 html 入口」（`2610-15`），那它是**一份文档**，不是一段片段。
   用 iframe 保持这个性质，主题靠下面这三件小事补齐，代价远小于 Shadow DOM。

2. **调色板抽成 `/theme.css`**：`style.css` 里的三段变量原样搬到 `workspace/web/theme.css`，
   外壳和蓝图都链它。蓝图因此可以直接写 `var(--surface)` / `var(--fg)`，四套主题自动对齐，
   一个变量都不用抄——这是 Shadow DOM 唯一的那点好处，用一份共享样式表就能拿到。

3. **外壳主动把主题推进 iframe**：同源可直接写 `iframe.contentDocument`。在
   `applyTheme()`（切主题）和 iframe `load`（新页面加载）两处写：
   `documentElement.dataset.theme = currentTheme()`，并同步 `color-scheme`（原生控件/滚动条跟着走）。
   蓝图只要认 `html[data-theme]`，不用监听任何事件。

4. **iframe 元素底色用 `var(--surface)`**，替掉写死的 `#fff`：加载前、以及蓝图自己没有背景时，
   看到的是当前主题的底色，不再是白闪。

5. **约定写进文档**：`docs/ai.md` 的 blueprint 段加一节「主题」，蓝图作者视角三条：
   链 `/theme.css`、用 `var(--*)`、认 `html[data-theme]`。示例蓝图 `hello` 就是活样本。

6. **备用通道**：万一将来蓝图要放到别的源（跨域），`postMessage` 是唯一可行的办法；同源场景不用，
   本次不做，只记在这里。

## 方案

- `workspace/web/theme.css`（新）：`:root` / `html[data-theme="dark"]` / `html[data-theme="solarized"]`
  三段变量，逐字从 `style.css` 搬出。
- `workspace/web/style.css`：删掉这三段（其余不动）；`#page iframe` 的 `background` 改 `var(--surface)`。
- `workspace/web/index.html`：`<link rel="stylesheet" href="/theme.css">` 放在 `style.css` 之前。
- `workspace/web/app.js`：
  ```js
  // 蓝图是独立文档：把当前主题写进去，它就能跟着外壳走。
  function pushPageTheme() {
    const doc = pageFrameEl.contentDocument;
    if (!doc) return;
    const theme = currentTheme();
    doc.documentElement.setAttribute("data-theme", theme);
    doc.documentElement.style.colorScheme = theme === "dark" ? "dark" : "light";
  }
  ```
  `applyTheme()` 末尾调一次；`pageFrameEl.addEventListener("load", pushPageTheme)`；page tab 的
  `activateTab` 分支里也调一次（同一个 src 不重载时有意义）。
- `docs/ai.md`：blueprint 一节补「主题」。
- `atoms/web.yaml` description：补一句「把当前主题交给它渲染的页面（`data-theme` + `/theme.css`）」。
- `.agents/blueprints/hello/index.html`：改用 `/theme.css` + `var(--*)`，并把 `data-theme` 显示出来。
- `development/testing/dev/case-core-web-page`：`hello` 蓝图加主题探针；新增断言
  `/theme.css` 可取、开 page 后 iframe 的 `data-theme` 与外壳一致、外壳切主题后 iframe 跟着变、
  iframe 元素底色是当前主题的 surface。

## 范围外

- 不做 Shadow DOM / 片段式蓝图（见决策 1）。
- 不做 `postMessage` 通道（跨源才需要）。
- 不统一蓝图的**字体**（`font-family` 不继承；蓝图自己写或链 `/theme.css` 后自行设）。
- 不做「蓝图自己维护一套主题」的机制——它可以选择不跟随，外壳只负责把手上的主题交出去。

## 验收

- `/theme.css` 可取（`200 text/css`）；外壳样式与改动前一致（三段变量搬走、值不变）。
- 开一个 page tab 后，iframe 文档的 `<html data-theme>` 等于外壳当前主题；`color-scheme` 同步。
- 在外壳切到 dark / solarized，iframe **不重载**就跟上（`data-theme` 变、用 `var(--surface)` 的
  元素背景变）。
- 暗色下 iframe 加载前后都看不到白底。
- 蓝图的 `:root` / `body` 选择器照常生效（证明仍是独立文档）。
- `case-core-web-page`、`case-core-web-tabs` 通过；`static/validate` 通过。

## 补记：初始化在蓝图、变更在外壳（用户 2026-10-10 定的分工）

- **初始化**：蓝图在 `<head>` 最前自己读一次 `localStorage["engineer.theme"]` 设 `data-theme`
  （同源共享 key）——保证**首帧**就对，不闪浅色；示例蓝图与 `docs/ai.md` 骨架都写上这三行。
- **变更**：仍然由外壳在 `applyTheme()` 时直写 iframe 文档；蓝图侧**零监听**。
- 外壳在 iframe `load` 时补推一次，所以**不写自举的蓝图也能跟随**，只是首帧可能闪一下。
- 用例新增断言：蓝图自举读到的 `window.__bootTheme` 就是外壳那份 key 的值（`light`），
  `core-web-page` 重跑 ok:true 14/14。
