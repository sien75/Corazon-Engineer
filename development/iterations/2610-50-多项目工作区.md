# 多项目工作区（一）：项目注册与两段 launcher

## 目标与范围

用户的诉求（原文要点）：

- Engineer 现在"在项目文件夹打开"，不够内聚：程序应该就是运行，跟从哪个目录启动无关；不做单例，多实例只要端口不冲突就能各自跑。
- 无论在哪个文件夹启动，都能在 web 页面上添加 / 删除项目（文件夹），并记住已经打开的项目。
- 前端 launcher 拆成两个：**project launcher**（blueprints + recents，按项目）和 **Engineer launcher**（项目棋盘：名称 + 按钮）。
- titlebar 的平铺 tab 改成 Chrome 分组式（按项目分组、分组常驻、分组内展示打开的 session tab、分组上的 edit 图标新开 project launcher tab、分组可隐藏、最右 `+` 是"添加项目"进 Engineer launcher）。

分两期。**本期（P1）**只做底层多项目 + 两段 launcher + 平铺 titlebar 的适配；分组化、显隐、分组内 edit 图标放到 P2，P1 的 launcher 先把 P2 要用的位置留出来。

P1 范围：home 数据目录；log 的项目注册表；session 带 projectId；static / ai / web 去 `--root` 化；dev 启动脚本不再要求当前目录是项目；两个 launcher 页面与路由；Engineer 自身历史数据的一次性迁移。

不做：Chrome 式分组与显隐（P2）；prod 打包脚本的等价改造（P2）；`project launcher` 的 edit / eye 按钮（P2）；项目内的 `.engineer/engineer.db` 迁移（用户明确：从零新建）。

## 现状（为什么这是底层改动）

- 四个服务全部由 `how-to/deploy/dev/launch.sh` 用 `--root <项目目录>` 拉起：log 在这个 root 下落 `.engineer/engineer.db`；static 从这个 root 读 schema；ai 把它当 bash cwd、blueprint 目录、会话历史根；web 从 `<root>/.agents/blueprints` 出页面。
- log 的 `current` 是一行全局状态（`openSessions` + `mainSession`），session 行只有 kind / blueprint / title。
- `web` 的 `/agent/<sessionId>/` 通过 log 反查 blueprint slug，再从固定的 `--blueprints` 出文件。

所以"项目变成数据"必须四服务 + 前端一起动。

## 契约与关系

新增：

- `contracts/log-project-list.yaml` — `POST /log/project/list`，列出**在场的**项目。
- `contracts/log-project-get.yaml` — `POST /log/project/get`，按 projectId 取项目（含路径）；web / static / ai 用它把 id 换成路径。
- `contracts/log-project-add.yaml` — `POST /log/project/add {path, name}`，登记项目；同路径已存在则复用同一行（含已移除的），返回项目。
- `contracts/log-project-remove.yaml` — `POST /log/project/remove {projectId}`，把项目从棋盘上撤下（软移除，不删行、不删磁盘）。
- `contracts/web-project-add.yaml` — `POST /project/add {path}`，web 校验"这是一个 engineer 项目"（目录存在且含 `engineer.yaml`）后转发 log；路径与校验规则只在这一处。

变更：

- `static-query` / `static-query-detail` / `static-stream` 请求带 `projectId`（旧的无 root 请求不再成立）；stream 事件带 `projectId`。
- `ai-new` 请求带 `projectId`（kind=sub 必填）；`ai-resume` 不变，但内部按 session 的 projectId 找根。
- `log-list` 支持按 `projectId` 过滤（project launcher 的 recents）。
- `log-session-upsert` / `session-detail` / `list` 的 session 行带 `projectId`。

atoms / edges：

- `atoms/log.yaml`：新增四个 provides。
- `atoms/static.yaml`：去掉"用 `--root` 绑定项目"，改为按请求的 projectId 解析；consumes 增 `log-project-get`、`log-project-list`。
- `atoms/ai.yaml`：`--root` 改为 `--home`（上传件）+ 按 session 解析项目路径。
- `atoms/web.yaml`：去掉 `--root` / `--blueprints` / `--agents`，provides 增 `web-project-add`。
- 新增 `edges/static-to-log.yaml`。

## 设计

### home：程序自己的数据目录

- 所有服务共享一个 home（默认 `~/.engineer`，`--home` 可覆盖）：`engineer.db`（records / sessions / projects / current）+ `uploads/`（图片，按 sha256 命名）。
- home 与"从哪个目录启动"、与任何项目目录都无关；项目路径是 home 里的数据。
- 多实例：两个实例用不同端口就能同时跑，并且**共用同一个 home**——"记住的项目"只有一份，tab 状态（`current`）也共用（同一个工作区，两个窗口）。要互不干扰就各自 `--home`。

### 项目注册表（log）

`projects(project_id TEXT PRIMARY KEY, path TEXT UNIQUE, name TEXT, created_at, updated_at, removed_at TEXT DEFAULT '')`

- `project_id` = `p_` + 12 位十六进制，由 log 生成；路径可变（项目搬走再添加回来是另一行），行不删。
- `name` 由 web 从 `engineer.yaml` 的 `project:` 读，读不到用目录名；log 只存。
- 移除是软移除：`removed_at` 非空即不在 `list` 里；同路径 `add` 清空它，于是重新添加后历史 session（projectId 相同）原样回来。
- 不删 session：项目被移除后其 tab 被关掉，记录留着，但不在任何 launcher 里出现。

### session.projectId

- `sessions` 加 `project_id`（空串 = 不属于任何项目，即 main）。
- `current` 仍是全局一行：main 是**全局**的统筹对话，不属于任何分组（P2 的分组只按 session 的 projectId 归拢）。

### 各服务

- **log**：`--root` → `--home`；新增四个 project 接口；session 行写 / 读 projectId；`/log/list` 支持 `projectId` 过滤。存储不碰文件系统（不校验路径）。
- **static**：`--root` → `--log`。每个请求按 `projectId` 向 log 取路径（缓存 5s，与 web 的 slug 缓存同法），再在 `<path>` 下读树。无 projectId / 未知项目 → 400 / 404。文件监听同时轮询已登记的全部项目，事件带 `projectId`。
- **ai**：`--root` → `--home`。`ai/new` 带 projectId（sub 必填）→ 取路径 → 校验 blueprint 两文件、读 README / `<title>`、建 session 行、`cwd` = 项目路径、`SessionManager` 按项目、上传件落 `home/uploads`。`resume` 用 session 行的 projectId 取路径；项目已移除但路径仍在时照常恢复（历史不丢），路径不存在则报错。main 的 workspace 工具：`session-new` 增 `project`（projectId 或路径），`session-list` 增项目列。
- **web**：`--root` / `--blueprints` / `--agents` 全去掉。`/agent/<sessionId>/` 走 session → projectId → 路径 → `<path>/.agents/blueprints/<slug>/`；新增 `POST /project/add`（校验 `engineer.yaml`，读名字，转发 log）。legacy 的 per-agent 副本目录不再服务（新项目从零开始）。
- **迁移**：**已无此逻辑**（2026-10-27）。曾经有 `engineer migrate` 子命令（移旧库 + 登记项目 + 归位孤儿 session），启动器在发现项目目录里有旧 `.engineer/engineer.db` 时调它。现在两样都没了：数据 home 是唯一数据库，项目目录里的旧库文件不被任何代码读到。已经迁完的数据不受影响；新 home 从空棋盘开始，项目在页面上 `+` 添加。

### 启动与多实例

- `launch.sh` 不再要求 `$PWD` 是项目：`ROOT` 由脚本自身位置解析（`dirname $0/../../..`），`ENGINEER_HOME` 默认 `~/.engineer`。
- 实例目录 `$ROOT/.engineer/dev${ENGINEER_INSTANCE:+-$ENGINEER_INSTANCE}`：pid / 日志 / 二进制都在里面，`pkill` 也只命中本实例的 bin，于是同仓库起第二个实例只要给 `ENGINEER_INSTANCE`（端口自动找下一个空位）。
- 端口选择照旧（8500–8503，占用则顺延）。

### 前端：路由与两段 launcher

- 路由：`/` = main；`/new` = Engineer launcher；`/project/<projectId>/new` = project launcher；`/session/<id>` 不变。
- `+` 打开 Engineer launcher（仍是覆盖层，位置和行为沿用现在的 `#launcher`）：顶部一个路径输入 + "添加"，下面是项目列表（名称、路径、`打开`、`移除`）。失败原因原样显示（不是 engineer 项目 / 目录不存在 / 重复）。
- project launcher：标题是项目名，两段 Blueprints / Recent 都按 projectId 取；行点击 = 建 / 开 tab 并激活。带一个返回 Engineer launcher 的入口。
- 移除项目：先关掉该项目打开的 session（`session/off`），再 `project/remove`，刷新工作区。
- titlebar 仍是平铺 tab（main 在前），P2 再换成分组；tab 语义不变（一个 tab = 一个打开的 session）。

## 二期：分组 titlebar（2026-10-26 已落）

- **数据**：`projects.visible`（log 存，`POST /log/project/visible`）。隐藏只是不画分组——项目还在棋盘上，session 一个都不关；再显示出来就是原来那些 tab。
- **titlebar**：`main` 在最左且不属于任何分组；棋盘上每个项目一个 group chip（项目名 + `✎`）；chip 展开后按顺序是 launcher tab、该项目开着的 session tab；分组在最后一个 tab 关闭后仍在（空分组给一行提示）；隐藏的分组整块不画，但它开着的 tab 仍在 `current` 里。
- **展开状态**是这一页的状态（不落盘）：点 chip 切换；某个 tab 被打开或被激活时自动展开该组，所以刷新后你正在用的那组是展开的。
- **`✎`**：在该组的 tab 里打开这个项目的 launcher（一个项目最多一个 launcher tab，重复点只是切过去）；分组被隐藏时先显示分组再打开。launcher tab 不是 session，不写 log，按路由 `/project/<id>/new` 在刷新后重建。
- **eye**：Engineer launcher 每行的眼睛按钮 → 写 `visible`；藏起来的项目在列表里置灰并标注 "hidden from the titlebar"；`edit` 对隐藏项目等于"先显示，再打开 launcher，并高亮"；藏掉当前 tab 所在的分组时屏幕回 main（tab 不关）。
- **`+`**：仍是添加项目 → Engineer launcher。
- **安全修正**：棋盘读不到时（log 挂了 / 库还没迁移）boot 与 refresh **不再**用空棋盘去修 `current`——那会把所有开着的 session 写成空（P1 实测踩到过：`visible` 列缺失导致 `/log/project/list` 500，刷新把 `openSessions` 清空）。现在 `projectsKnown/boardKnown` 为假时只保留现状，不写回。

## 验收范围

按 dev BOOK 重建启动（home 用临时目录，避免污染真实 `~/.engineer`），真机跑：添加项目（含非 engineer 目录被拒）、记住项目（重启后仍在）、移除项目（tab 关闭、历史留着、重新添加回得来）、project launcher 的 blueprints / recents 只出该项目的、开 tab、`/agent/<sessionId>/` 出该项目的 blueprint、迁移一次（旧库会话进 home）。E2E 用例按端口块更新后跑受影响的那批（static、log-workspace、ai-new/resume、web-launcher/tabs/route），不跑模型真实对话类。

## 二期的结果（2026-10-26）

实现与实测：

- log：`projects.visible`（含迁移 `ALTER TABLE projects ADD COLUMN visible`），`POST /log/project/visible`；`/log/project/list|get|add|remove` 都回 `visible`；空名字回落到目录名。
- 前端：分组 tab 条（chip = 项目名 + ✎，展开后是 launcher tab 与该项目的 session tab）、分组在最后一个 tab 关闭后仍在、空分组给提示；`✎`/`edit` 建/切到该项目的 launcher tab（一个项目一格），隐藏的分组先显示再打开；eye 写 `visible`，隐藏不动 session，藏掉当前 tab 所在分组时屏幕回 main；分组展开状态是本页状态，**有开着的 tab 的分组默认展开**（重载后还看得见自己的 tab），空分组只有 chip。
- 找到并修掉的两个真问题：① 项目 launcher 页建一次就不再刷新，导致新建的 session 不出现在它的 Recent 里（现在每次激活 launcher tab 重建）；② 棋盘读不到时（库还没迁移时 `/log/project/list` 500）boot/refresh 会把 `current.openSessions` 写成空，把开着的 tab 全关掉（现在 `boardKnown/projectsKnown` 为假时只保留现状，不写回）。
- dev 栈上另用浏览器走了一遍 P1 的入口（add → 分组出现 → 开它一个 blueprint → 移除 → 分组与 tab 一起消失 → 重新 add 同一文件夹拿回同一个 projectId），全部符合预期。
- `case-core-web-tabs` 按新模型重写并真跑：**33/33 通过**（分组、launcher tab、`/project/<id>/new` 重载重建、隐藏/显示、关闭后分组仍在、Recent 重开同一条 session 并回放、重载 `/` 恢复、iframe 与地址）。

## launcher 图标移到分组的 tab 末尾（2026-10-26）

用户的第二版：分组 chip 只留项目名（点它收/展），launcher 图标**挂到该组 tab 的末尾**，不再和 chip 一体。

- 未打开：组末尾是一枚图标（笔+框的线稿，无标签、无 ×、无下划线），点它在这个分组里打开 project launcher。
- 打开后：同一位置变成**launcher tab**——图标当标签、激活时带下划线；**没有 ×，不可关闭**（它是这个分组的
  自己的页面，组里的 tab 从这里开出来）。刷新（浏览器专属的 tab 不落盘）后回到那枚裸图标，点它再开。
- 分组里 tab 的顺序：session tab 在前，launcher 在最后（像浏览器的"新建"按钮）。
- Engineer launcher 每行的 `edit` 仍是同一枚图标（那里是行内按钮，不是 tab）。
- `case-core-web-tabs` 补了"launcher 在 tab 末尾""裸图标 ↔ 真正 tab"的断言并重跑：**38/38 通过**。

## 图标改成一笔一画的形状（2026-10-26）

分组 chip 的 edit 换成"笔 + 一张纸"的线稿（内联 SVG，`currentColor`）；Engineer launcher 每行的
edit 也换成同一枚图标（`aria-label` / `title` 保留），eye 换成细线描的简笔眼睛、隐藏时同一只眼加一道
斜杠并压暗，不再用 emoji；`remove` 仍是文字（破坏性操作写成字更清楚）。两个图标都写在 `app.js` 里
（`ICON_EDIT` / `ICON_EYE` / `ICON_EYE_OFF`），没有字体、没有 CDN；`aria-label` / `title` 不变。
`case-core-web-tabs` 相应改成断言"图标是画出来的 SVG、remove 是文字"，并真跑复验。

## 迁移改成可重复的增量合并（2026-10-26）

旧的 live 实例（本次对话所在的那个，用旧构建、仍写 `<repo>/.engineer/engineer.db`）在首次迁移之后又写了新记录，home 里没有。
`engineer migrate` 原来只在 home 没库时复制一次，所以补成：

- **首次**（home 没库）：复制整个库，然后把没有 project 的 sub 会话归到登记的项目。
- **之后每次**（home 已存在）：`MergeDatabase` 把旧库里新出现的行按主键合并进来（`INSERT OR IGNORE`，
  不覆盖已有行），再归一次孤儿 sub 会话。表/列缺失按默认值读，所以更早的库也能合。`current`
  不合并（哪几个 tab 开着属于"正在看的那个窗口"，两个实例共用一个 home 会互相拉扯），会话都在项目的 Recent 里。
- dev `launch.sh` 与 prod `launch.go` 本来就在"旧库还在"时每次启动跑这条命令，于是它变成"每次启动追平一次"，
  直到旧实例退役、旧库可以删掉。

实测：home 20754 → 20930 条记录（+176），旧库 20938 条里一条不缺；重启 dev 栈又补了 6 条（这中间的对话）。

## 结果

2026-10-26 落完 P1 的代码与文档（log / static / ai / web 四服务、dev 与 prod 两个启动器、前端两段 launcher、契约 / atoms / edges / docs / how-to / agents 主副两份 spec），按 dev BOOK 在临时 home（`/tmp/eng-p1-home`）上真跑：

- 迁移：`engineer migrate` 把 checkout 的旧库复制进 home，并给 329 条 sub session 归到登记的项目上；home 里没有库时才复制（再次启动不再复制）。
- 项目入口：`/project/add` 对 `/tmp`（无 engineer.yaml）返回 400 与可读原因；同一路径重复添加返回同一个 projectId。
- 按 projectId 取树：`/static/query`、`/static/query-detail` 正常；缺 projectId → 400，未知项目 → 404。
- `ai/new`（projectId + blueprint）写出的 session 行带 projectId 与 blueprint，`/agent/<sessionId>/` 出的是那个项目的 blueprint 页面。
- `/log/list` 带 projectId 时只返回该项目的 session。
- 软移除：棋盘上消失、页面照旧可取、重加同一路径拿回同一个 projectId。
- Engineer launcher：棋盘行、添加输入、失败原因、移除（同时关掉该项目的 tab）都符合预期（ego-browser 实测）。
- project launcher：blueprints / recents 都只出该项目；点一行建 tab 并画出页面（ego-browser 实测）。
- 多实例：同一 checkout 起两个实例（8500 段与 8504 段）各自 pid 目录、各自端口；手起的空 home 栈 boot 出 main、棋盘为空。
