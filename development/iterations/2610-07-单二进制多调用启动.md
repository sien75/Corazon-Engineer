# log / static / web 合并进 `engineer` 单个二进制（多调用），减少公司 EDR 白名单弹窗

## 需求

在本机（macOS，公司端点安全软件 星点/Aspect）运行 engineer 时，首次启动每个可执行文件都会弹一次「不在安全策略默认允许的范围内，程序启动已被阻止 → 允许运行并重新启动」的窗口，需要逐个点击。当前一次完整启动涉及 5 个不同的可执行文件路径：

```
bin/engineer        （启动器，不提供服务）
bin/engineer-log
bin/engineer-static
bin/engineer-ai
bin/engineer-web
```

目标是**把可执行文件数量降到最少**，让首次使用的点击次数尽量低；不改任何对外行为（端口、HTTP 接口、契约、日志目录、进程模型）。

## 现状与根因

根因已在 2610-05 之后的排查中确认（见该记录的「与安全软件的关系说明」补充与 telemetry 记录 `c176990210d7ca27`、`a74dab890b3da319`）：

- 命中的是星点 EDR 的**进程创建**事件（`ruleId:kEdrRuleProcessCreate`，`ES_EVENT_TYPE_PROCESS_EXEC`），不是端口监听事件。
- 弹窗载荷为 `id:PROC_WHITE_BLOCK_1`、`blockType:blockProcess`、`policyId:122100036|`、`applyExclusion:true`，`placeholders` 同时给出 `__TARGET_PATH__` 与 `__TARGET_MD54K__`。
- 弹窗**按 `__TARGET_PATH__` 计数**：一次完整启动 = 5 个不同路径 = 最多 5 次弹窗（用户此前跑过 `engineer version`，启动器那条已加白，故实际看到 4 次）。
- 加白是**本机记录**，不跟人走；每个新版本目录（路径带 git hash）都会重新触发。

结论：可控制变量只有「同一次安装里有多少个不同的可执行文件路径」。因此把可以合并的三个 Go 服务合并进启动器自身。

## 方案

**多调用（multi-call）二进制**：`bin/engineer` 一个文件同时承担启动器与三个 Go 服务，靠 `argv[1]` 分发；启动器用自身路径 exec 自己带子命令。

```
engineer                          ← 同一个文件
 ├── engineer serve-log    --root <R> --addr <h:p>
 ├── engineer serve-static --root <R> --addr <h:p>
 ├── engineer serve-web    <port> --bind <h> --root <web> --static <u> --ai <u> --log <u>
 └── bin/engineer-ai       --root <R> --addr <h:p> ...      ← 仍是独立文件（Bun 单文件，无法并入）
```

1. **三个服务从可执行包改为库包**：`workspace/{log,static,web/server}` 的根包由 `package main` 改为库包，`func main()` 改为 `func Serve(argv []string)`，函数体（参数解析、监听、错误处理、usage 文本）保持不变。
2. **启动器新增内部分发**：`how-to/deploy/prod/launch.go` 的 `main` 在原有 `start|status|version|uninstall` 之外识别 `serve-log|serve-static|serve-web` 并调用对应 `Serve(os.Args[2:])`。这三个子命令是**内部接口**（由启动器拉起自己时使用），不面向用户，`usage` 一行不变。
3. **启动器拉起自身**：`specs` 里 log/static/web 的 `bin` 由「兄弟文件」改为自身可执行文件路径（`selfDirs()` 里已经解析出来的 realpath），参数前面补上对应子命令（web 原本没有子命令，新增 `serve-web`）。pid 文件、端口顺延、前台守着、Ctrl-C 收尾、`reclaim()` 全部不变。
4. **构建绑定**：新增 `how-to/deploy/prod/go.mod`（module `engineer/launcher`），用 `require` + `replace` 指向 `workspace/log`、`workspace/static`、`workspace/web/server` 三个本地 module，使启动器能 import 三个服务包；不需要 go.work。
5. **dev 与 prod 对齐**：dev 不再 build 三个服务二进制，改为 build 一个 `engineer`（同样带子命令启动）；因为 dev 的 ai 本来就走 `bun src/main.ts`，dev 的可执行文件路径从 3 个降为 1 个。
6. **进程名相关的匹配同步改**：`pkill -f "$BIN/engineer-"`（dev `launch.sh`）、`pkill -f "$CUR_REAL/bin/engineer-"`（`install.sh`）、`killMatching(.../bin/"engineer-")`（启动器 `uninstall`）三处模式改为 `.../engineer`，否则升级/卸载/回收会漏掉合并后的进程。

## 范围外

- **不改 `engineer-ai` 的发布方式**：Bun 单文件无法并入 Go 二进制；「把 ai 二进制嵌进去、运行时释放到临时目录再 exec」只会换成另一个路径重新触发，没有收益。所以**自包含发包的地板是 2 次弹窗**（`engineer` + `engineer-ai`）。降到 1 次要改走「依赖目标机 bun、`bun run ai/src/main.ts`」（`prod/BOOK.md` 已有的 fallback），本次不做。
- **不做任何绕过公司安全管控的事**：不写 EDR 缓存、不预置排除项。走公司白名单（星点用户服务群）是唯一 0 次点击的路径，属于环境变更，不在本次代码改动内。
- 不改端口、默认绑定、`ENGINEER_BIND`、`reclaim()` 逻辑、服务间 URL 与 `/config.js` 内容。
- 不改任何 contract / atom / edge。
- 不改 web 前端资源（仍 `--root` 指向 `workspace/web`）。

## 验收

- `go build`（launcher module）产出单个 `bin/engineer`；包里 `bin/` 只剩 `engineer` 与 `engineer-ai` 两个可执行文件。
- dev：`how-to/deploy/dev/launch.sh` 起 4 个服务，四个端口（8500-8503 顺延）行为与改动前一致；web UI、schema 查询、ai 对话正常。
- prod：按 `how-to/deploy/prod/BOOK.md` 打包（darwin-arm64 与 linux-amd64 交叉编译各一次），`file bin/*` 两个文件都对目标平台；装包后 `engineer` 启动，四个服务监听 127.0.0.1、地址打印与改动前一致，Ctrl-C 整体退出，`engineer status` 正常。
- `lsof` 里三个服务显示的进程名变为 `engineer`（不再是 `engineer-log/-static/-web`），所以按进程名断言的测试用例要同步改。
- 影响面：可执行文件路径数 5 → 2（首次使用弹窗次数上限同比例下降）；若公司侧加白，则全部为 0。

## 实测结果（2026-09-30）

打包 `engineer-v0.3.0-5-gf875043-darwin-arm64` 并由用户 `install.sh` 安装后启动，星点弹窗次数与路径：

| 序 | 时间 | `__TARGET_PATH__` |
| --- | --- | --- |
| 1 | 17:24:39 | `.../versions/engineer-v0.3.0-5-gf875043-darwin-arm64/bin/engineer` |
| 2 | 17:24:49 | `.../bin/engineer-ai` |

**2 次**，与预期地板一致：`AspectDaemon` 对该版本目录只有 2 条 `kEdrRuleProcessCreate` DENY，`serve-log` / `serve-static` / `serve-web` 三个子进程复用 `bin/engineer` 这一条路径，**未再产生弹窗**。对照组：改造前同一台机器上全新目录 `/private/tmp/packcheck/.../bin/` 的 5 个二进制逐个命中。

其他已验证：

- prod 包内 `bin/` 只有 `engineer` 与 `engineer-ai`，均 Mach-O arm64；装后 7500–7503 正常运行、四个服务均 `127.0.0.1`。
- dev 冒烟（改造后单二进制）：四服务起、web 200、`/config.js` 地址正确、`static/query` 与 `log/query` 正常；本轮 dev 启动 0 弹窗（`.engineer/dev/bin/` 目录此前已为旧二进制点过允许，机制待定，不影响结论）。
- 加白粒度：本轮的新版本目录是全新目录，仍按**路径**逐个弹（2 个路径 2 次），说明弹窗计数 = 首次执行的不同可执行文件路径数。
