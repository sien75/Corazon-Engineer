# Skill 系统

## 需求

把"打开一个对话"变成一等产品对象：用户可以保存常用 skill 并反复实例化，系统也能从使用历史里发现候选 skill。

- **Skill = 一段文本**（名称 + 文本）。**实例化 = 开一个对话，把这段文本作为首个 prompt 交给大模型执行。**
- **Skill Session = Skill 的一次执行**：对应一个 ai session，前端表现为一个 tab。
- Skill 可增可删；系统自动发现的候选（suggested）经用户确认后进入用户 skill 列表。
- 前端：现有顶栏类型（graph / how-to / development / contracts / docs / notes）保留为**固定 tab，不可删**；skill 以**可增删的 tab** 形式与之并存；点 `+` 打开**新建页**（像浏览器的新标签页：整页展示、内容居中、不是弹窗），里面最重要的是能直接开一个空白对话。
- 创建 Skill 本身也是 AI 的能力：用户在对话里描述，AI 整理成 Skill 落库。

## 现状

- `workspace/web`：`index.html` 顶栏是视图按钮（graph / how-to / development / contracts / docs / notes），`#ai` 是对话面板；没有 tab 概念，没有 skill。
- `workspace/web/app.js`：**单会话**——全局 `aiSession` + localStorage 里一个 session id；`/new`、`/history` 命令抽屉是唯一的"skill"雏形。
- `workspace/ai`：`Registry` 持有所有 session，pi 事件原样透传 SSE；`agent_settled` 是一次运行结束的标记；会话记录经 `recorder.record` fire-and-forget 写 log。
- `workspace/log`：sqlite（`.engineer/engineer.db`），records 表统一存 test / telemetry / conversation。
- 无 skill 表、无 suggested 机制。

## 决策

1. **Skill 实现在 ai 服务内**，数据落**独立 sqlite**（`.engineer/skill.db`，用 Bun 内置 `bun:sqlite`）：不新开 atom，也不复用 log 的库。理由：skill 是 ai 侧的产品概念（对话的入口），log 的边界是"记录"。
2. **Skill 只有一种 kind：chat**。没有工具白名单、没有可视化、没有执行方式配置——skill 就是一段文本，实例化就是开对话。
3. **固定 tab 不属于 skill 系统**。graph / how-to / development / contracts / docs / notes 仍按现有方式渲染，只是从"顶栏按钮"变成 tab 栏里的固定项、不可关闭。它们的展示重构（如 graph 怎么在 tab 里画图）**不在本次范围**。
4. **超限丢最新的那条**，被丢的留在待总结队列，参与下一轮。
5. **"忽略过的不再出现"靠把已有 skill 的概要随扫描一起发给模型**，外加代码侧同名 / 同文本兜底比对。
6. **队列里的 run 文本在 settle 时于内存里抓取**，不回读 log：既省一次往返，也避开"记录还在路上、扫描已经开跑"的竞态。

## 数据模型（`.engineer/skill.db`）

```
skill(id PK, name, text, source, status, evidence, created_at, updated_at)
  source: custom | suggested
  status: active | ignored          # ignored 只对 suggested 有意义，保留文本用于去重

skill_session(session_id PK, skill_id, created_at)
  # 实例映射：哪个 session 是哪个 skill 的实例（ad-hoc 运行时 skill_id 为空）

scan_pending(id PK, session_id, text, created_at, summarized_at)
  # 待总结队列 + 已总结标记；一行 = 一次 agent_settled（一个 run），text 是这一轮
  # 的 user + assistant 文本（工具调用 / 工具结果不进队列）

scan_state(key PK, value)
  # in_progress 防重入、last_scan_at 等
```

删除语义：

- custom 删除 = 硬删（关掉对应 tab）；
- suggested 忽略 = `status = ignored`，**保留文本**用于去重；
- 保存一个 suggested（带 id 调 save）＝ 接受，`source` 转为 `custom`、`status` 转 `active`。

## 接口（新增 contracts）

| 契约 | 作用 |
| --- | --- |
| `ai-skill-list` | 列 skill（可按 source / status 过滤） |
| `ai-skill-save` | 新建 / 更新 / 接受 custom skill |
| `ai-skill-delete` | 删 skill |
| `ai-skill-ignore` | 忽略 / 取消忽略 suggested |
| `ai-skill-run` | 实例化：`{skillId}` 或 `{name, text}` → 建 session + 把文本作为首条 user prompt → 返回 sessionId |
| `ai-skill-refresh` | 手动触发一次总结 |

`/ai/skill/run` 是对"开对话"的封装：内部 `registry.new()` + `registry.ask(sess, [{type:"text", text}])`，并写 `skill_session`；前端仍用现有 `/ai/stream` 订阅该 session。

**AI 建 skill** 通过一个新的 pi 自定义工具 `save_skill(name, text)`（与 `ask_user` 并列），落库走同一个 store。用户在对话里说"把这件事存成 skill"即可。

## Suggested 引擎

### 触发

- 钩子挂在 `Registry.append()` 上：任何路径产生的 `agent_settled`（真实 pi 与 dev stub 都走这里）都会把这一轮的 run 文本入队。文本为空（空 run）不入队也不计数。
- 触发条件：`scan_pending` 中 `summarized_at IS NULL` 的行数 **≥ 10**，**跨 session 全局计数**，不 debounce。
- 触发时 `void` 起一个**独立异步任务**：不 await、不进任何 session 的 tail、不阻塞主对话；`scan_state.in_progress` 在同步段内 check-and-set，天然防重入。
- 该任务**不复用用户 session**，单独一次模型调用（一次性、非流式、无工具），与用户对话完全隔离。

### 取数与超限

- 取**最旧的 10 条** run（一行即一轮的文本）。
- 发送前自己估 token（chars/4）。超预算就**丢最新的那条**（取 9 条重试），再超取 8……直到不超。
- 真发出去后仍遇 provider overflow（按错误信息判定），同样再减一重试。
- 兜底：减到 1 条仍超，则对这一条文本做头尾截断后再发；仍失败则放弃本轮（不标记，下轮再来）。
- 预算 = `contextWindow − 24000`（输出预留 + 安全余量），下限 2000；无 contextWindow 时取 8000。
- 不依赖 pi 的自动压缩：pi 的压缩是"切历史"，单条消息本身切不掉；这里我们自己控输入。

### 输入 / 输出

- **输入**：本批 run 的对话文本 + **已有 skill 概要**（custom + suggested + ignored 全部，每条只给"名称 + 文本首行"），并明确要求"不要重复已有 / 已忽略的"。
- **输出**：结构化 JSON `{"skills":[{"name","text"}]}`，最多 3 条；落库为 `source = suggested, status = active`，并带上 `evidence`（命中的 sessionIds / run ids / scannedAt）。
- **代码侧兜底**：返回项与已有 skill（含 ignored）或同批前一条的名称/文本归一化后相同 → 丢弃。

### 标记

- 只有**真正参与并成功**总结的 run 才写 `summarized_at`；
- 被挤出去的（第 10 条 / 减下去的那些）不打标，留在队列里下一轮一起算，因此不会漏；
- 传输类失败不打标，下轮重试；
- **模型调用成功但输出无法解析**视为本轮已处理（打标）：重发同一批输入大概率还是同样结果，只会再花一次钱。

## 前端

- **tab 栏**（`#tabs`）：固定项（graph / how-to / development / contracts / docs / notes，无 ×）+ skill 项（可关）+ `+`。
- **三种内容面板，同一时刻只显示一种**：固定视图（graph / 各目录树）／skill 会话／新建页。选中 skill tab → `#left` 隐藏、`#ai` 变成整页（去掉侧栏宽度与左边框）；点 `+` → `#newtab` 整页（`+` 自身高亮成"当前 tab"），Esc 或点任意 tab 离开。打开的 skill 会话留在 tab 里，切走的只是视图。
- **新建页**（点 `+`，内容水平+垂直居中）分三部分，与 `development/plans/2610/Task 设计.md` §3 对齐：
  1. `Built-in` —— 目前只有 `Chat`（开一个**没有 skill 的空白对话**：只建 session、不发给模型）。Graph / Development / How-to 已按决定变成固定 tab，不属于 skill，所以不在这里。
  2. `My Skills` —— custom 列表，点击运行、可删。
  3. `Suggested` —— 候选列表，点击运行、可 save / ignore、可 refresh。
  4. `Recent` —— 最近会话（`/log/list`）。**关掉 tab 只是删掉 tab，会话本身还在**（ai 内存 + log），所以这就是"关掉之后怎么再打开"的入口：点一条 → `/ai/resume` + log 重放 → 重开成 tab。已经在 tab 里的会话不重复列出。log 服务不可用时这一段留空，不影响其余部分。
  空分区显示 `nothing here yet`。**页面上不放新建 skill 的表单**——建 skill 只走 AI（`save_skill`），页面上手动建显得乱。
- **实例化**：调 `/ai/skill/run` 拿 sessionId → 开 tab → 把**skill 文本**作为首条 user 气泡本地画出（SSE 里没有 user 事件）→ 从 seq 0 订阅流。非新建的 tab 走 `/ai/resume` + log 历史重放（与 `/history` 恢复同一条路径）。
- **会话是一个居中的列**：消息区与输入区都限宽 `1000px` 并水平居中（`#ai > *`），否则在宽屏上整句话横跨整页、很难读。
- **消息区右侧留出滚动条的位置**：`#ai-messages` 用 `scrollbar-gutter: stable` 且 `padding-right: 18px`——经典滚动条下它本来会压在气泡上（气泡铺满内容盒）。
- **tool / thinking 是窄条，展开变宽**：`.ai-collapse.ai-tool` 与 `.ai-collapse.ai-thinking` 收起时固定 `300px`、左对齐（它们是回复旁边的旁注，不该撑成和对话一样宽的一整条）；`.open` 时放宽到整列——窄条里看工具输出太难读。
- **多会话**：tab 列表与当前 tab 存 localStorage（`engineer.skill.tabs` / `engineer.skill.active`），刷新后恢复；`aiSession` / `aiSeenSeq` 仍是一份，但切换 tab 时整体重放，所以按 tab 隔离。
- **刷新不得抢走当前 tab**：`refresh()` 只重画左侧视图（`showView`），不碰"哪个 tab 是激活的"（否则 schema 推送会把用户踢出 skill tab）。

## 范围外

- 固定 tab 的展示重构（graph 在 tab 里怎么画、how-to / development 的文件树等）；
- skill 的工具白名单 / 参数 / 可视化 / 执行方式；
- 多客户端（web / app / tui）与会话输入仲裁；
- suggested 的置信度排序、TTL、指纹库（当前用"概要随扫描一起发"去重）。

## 测试与验收

`development/testing/dev/` 新增用例：

1. `case-core-skill-crud`：save / list / update / ignore / delete、过滤、8 个错误分支、重启后仍在。
2. `case-core-skill-run`：`/ai/skill/run` 后按 sessionId 订阅 `/ai/stream`，首条 user 记录就是 skill 文本；ad-hoc 运行不落 skill；同一 skill 两次运行得到两个 session。
3. `case-core-skill-suggest`：9 条 run 不出建议、第 10 条出 1 条；批次被标记（refresh 报 `triggered: false, scanned: 0`）；ignore 后不再出现（第二批重复同文本仍只有那一条 ignored）；带 id save 可接受为 custom。
4. `case-core-web-skill-tabs`：浏览器用例——固定 tab 无关闭按钮、顶栏没有 `ai` 按钮；新建页列出 skill、空分区显示 `nothing here yet`、没有建 skill 表单、内容居中，且能开空白对话（无消息、可直接输入）或运行 skill（此时只有 `+` 是"当前 tab"）；skill tab 占满整页、首条消息是 skill 文本、回复流式写入；固定 tab 不丢 skill tab；重开 tab 重放会话；关掉最后一个 skill tab 回到 graph；刷新后 tab 与激活态恢复。

测试用的两个开关：

- `--stub`：跳过模型解析，走 echo stub。skill 的 CRUD / 运行 / 队列机制都不需要模型，suggested 扫描在无模型时用一个确定性兜底候选（取最旧那条 run 的首行），因此用例可离线、可重复。
- 用例都在 `.engineer/.skill-test` 这个临时 project root 上跑，不碰真实的 `.engineer/skill.db`。

## 影响面

- `contracts/`：新增 6 个 `ai-skill-*.yaml`。
- `atoms/ai.yaml`：`provides` 增加对应接口；`description` 补 skill 系统（独立 sqlite）。
- `atoms/web.yaml`：`consumes` 增加对应接口。
- `edges/web-to-ai.yaml`：新增 6 条 edge。
- `workspace/ai/src/skill/`：`store.ts`（sqlite + CRUD + 队列）、`suggest.ts`（扫描）；`registry.ts` 挂 settle 钩子、`oneShot`、`save_skill` 工具、`--stub`；`server.ts` 新增 6 条路由；`main.ts` 解析 `--stub`。
- `workspace/ai/src/recorder.ts`：顺带修了一个既有竞态——`record()` 原本无条件 fire-and-forget，同一 session 的两条记录可能乱序落库，而 `session-detail` 按 rowid 返回，重放历史时 assistant 会排在 user 前面（skill tab 重开走的就是这条路径）。改为用一个 promise 链串行写（仍然不 await、不阻塞对话），保证落库顺序 = 程序调用顺序。
- `workspace/web/`：`index.html`（`#menu` → `#tabs`，新增 `#newtab`，删掉 `ai` 切换按钮）、`app.js`（tab / 新建页 / 空白对话 / 多会话状态 / `showView`；删掉侧栏开关与 `engineer.ai.open`）、`style.css`（tab 栏、skill 模式、新建页）。空白对话复用现有的 `/ai/new`，不需要新接口。
- `development/testing/dev/case-core-web-input-grow`：该用例原本靠 `ai` 按钮把面板打开，现在改为开一个 skill tab（因此它需要 ai 服务在场）；同时把"缩窄窗口重排"一步改成显式派发 `resize`（CDP 改视口不保证投递该事件）。
- 无 log / static 变更。
