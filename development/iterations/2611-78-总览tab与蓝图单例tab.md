## 一、Pure Chat 打不开:`log/session/upsert: HTTP 500`

- 现象:打开 Pure Chat,页面上只有一句 `Pure Chat: log/session/upsert: HTTP 500`。
  `POST /chat/session` 在 blueprint 那一层也是 `400` + 同一句(blueprint 把 ai 的失败原样带回来)。
- 根因:ai 建会话要先 `POST /log/session/upsert` 写一行会话;storage 的 `sessions` 表**由旧版本建过**,
  列是 `session_id / kind / project_id / blueprint / title / model / image_model / created_at / open_index / is_main / touched_at`,
  **没有 `cwd` / `system`**。现在的代码要写这两列,而 `CREATE TABLE IF NOT EXISTS` 对已存在的表什么也不做,
  于是每次写都失败:`SQL logic error: table sessions has no column named cwd (1)`。
- 数据目录比代码活得久:dev 跑的就是真装的那一份(`~/.engineer/data`),里面的库是旧版本留下的。
  这不是"某个测试库脏了",是升级路径上一定会遇到的事,所以在代码里修,不靠删库。
- 修法(`workspace/storage/internal/store/workspace.go`):storage 启动时读 `PRAGMA table_info(sessions)`,
  把缺的列用 `ALTER TABLE sessions ADD COLUMN` 补上(默认 `''`)。补的列:`cwd`、`system`、`title`、
  `model`、`image_model`(最老的库连后面三个也没有)。已有的列不动,旧行照旧读得回来(补出来的列是空串)。
  旧版本多出来的列(`kind` / `project_id` / `open_index` 等)留着不管:它们都有默认值,新的写入不受影响。
- 影响面:这是数据目录里的一张表的形状变化,发生在启动时,一次性的、幂等的。prod 的旧版本(7500)对
  `sessions` 只读它认识的列,新增列不影响它。
- 用例:新增 `development/testing/dev/case-core-storage-sessions-migrate`,旧库 → 补列 → `upsert` 回 200。

## 二、外壳改成 tab:Overview 常驻,蓝图单例可关

- 起因:上一版外壳的顶部条"列出前台项目的全部蓝图",主体一次只显示一个;用户要的是**打开的页面**:
  最左边一个总览 tab(英文名 `Overview`)、关不掉、能看到蓝图列表;蓝图从那里打开,一个蓝图一个 tab,
  tab 可以关。
- 形态(`workspace/web/shell/app.js` 的 tabs 一节):
  - 顶部条 = `Overview` + 每个打开过的蓝图一个 tab。`Overview` 没有 ×;蓝图 tab 有 ×。
  - `Overview` 是外壳**自己画的唯一一页**:前台目录的路径 + `blueprints` 一节(一蓝图一行,标题 + slug),
    行的样式沿用 launcher 那套(`.launcher-head` / `.launcher-sec` / `.launcher-item`)。空目录写
    `this folder has no blueprints yet`,不再是空白页。
  - 从 Overview 点一行 → 开 tab;蓝图页仍是 iframe(`/bp/<project>/<slug>`,同源)。
  - **单例**:已经在的蓝图不再开 tab,回到已有的那个。
  - `×` 关掉 tab 和它的 frame,前台落到它左边那个 tab;没有就落回 `Overview`。
  - 不是前台的 frame 只是 `hidden`,不销毁:tab 切回来时对话和滚动位置都还在。
  - tab 列表和"哪个在前"按目录分开记在浏览器里(`engineer.tabs.<project>` / `engineer.active-tab.<project>`),
    刷新回来还是那几个;换目录时 frame 全部丢掉、按新目录的记录重建。
  - Overview 每次到前台都重读一次 `/config/blueprints`:蓝图是用户(或 agent)随时加的文件,
    列表旧了会留下一个已经不存在的 tab。
- 没采用:
  - 顶部条继续列全部蓝图(用户要的是"打开的页面",列全部等于把目录当 tab 条)。
  - 一次只显示一个 frame、切 tab 重建(简单,但切回来对话要重载、滚动丢)。
  - tab 记在 storage(会话行里已经有"属于哪个蓝图"这一层) —— tab 是浏览器里的视图状态,不是数据。
- `structure/` 不变:没有新接口、没有新契约,`GET /config/blueprints` 的返回形状没动。
  `style.css` 只加 Overview 页的布局和"隐藏的 frame 不显示"。
