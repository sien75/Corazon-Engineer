# 拆窗渲染与布局工具（pane 拆分 · i3）

> 接 i1（`2610-22`）与 i2（`2610-23`）。i2 把 tab 层级接上了但只渲染主 pane；本文把它真正拆开，并给模型改布局的能力。

## 需求

- 一个 tab 下按布局树渲染多个 pane，每个 pane 展示一个内容（`chat` / `page`）。
- 布局**只能由模型改**：ai 提供 `layout` 工具，前端接工具帧。
- skill 说明怎么用这个工具、有哪些典型配方。
- 布局完全靠工具读写，**不做任何注入**（不碰 system prompt、不碰 user 文本）。

## 决策

1. **pane 对象**：每个 pane 是运行期的一个对象，挂在 tab 上。
   ```js
   { key, kind: "chat" | "page", contentId, el, messagesEl?, scrollEl?, frameEl?,
     session?, seenSeq, streamCtl?, streamGen, streaming? }
   ```
   `key` 是**树里的路径**（`""` / `"0"` / `"0.1"`），重渲染同一棵树时 key 不变，pane 复用。

2. **composer 是单例，跟着焦点走**。消息列表、流状态、会话都 per-pane；`#ai-input` / `#ai-cmd` 仍然只有一个 DOM 实例，用 `appendChild` 搬进当前聚焦的 pane。这样 `aiInputEl` / `aiCmdEl` 那 60+ 处引用不用动，草稿机制（`aiDrafts`）从「按 tab」改成「按 pane」。

3. **点击 pane 聚焦**。聚焦的 pane 是 composer 所在的那个；`chat` pane 可聚焦，`page` pane 聚焦时 composer 隐藏（没有可输入的东西）。

4. **重排会重挂 pane**：布局一变就按新树重建容器，pane 的 DOM 被搬过去。chat pane 会重新拉一次历史，page pane 的 iframe 会重载。**不做**“保住现场”的增量更新 —— 记为一个明确的简化。

5. **布局工具（ai）**：
   - 名字 `layout`；`args.layout` 省略 = **读**当前 tab 布局。
   - 给了 = **写**：整树替换（声明式，幂等，log 里 last-write-wins）。
   - `pane.content = chat` 且 `id` 省略/为空 → ai 顺手 `/ai/new` 建一个会话，把分配的 sessionId 写回树。
   - 写入前校验：≤6 pane、`brief` 只能是叶子、`weight ∈ 1..3`。
   - 结果里**回显归一化后的完整树**（模型忘了先读也能在写完之后对齐）。
   - tool description 里写死「改之前先不带参数读一次」。
   - 写 `/log/tab/*`；tabId 从 `Sess.tabId` 取。

6. **tabId 落到 ai 的 Sess 上**：`/ai/new` 与 `/ai/resume` 各接受可选 `tabId`，不带就生成 `t_<hex>`，响应里返回；ai 记在 `Sess` 上，工具用它读写布局。

7. **前端接帧**：`tool_execution_start{toolName:"layout"}` → `applyPaneLayout(tab, args.layout ?? <读回>)`。和 `ask_user` 同一分流点，**不画 tool chip**。

8. **`/ai/tab/detail` 与工具读到的布局**是恢复路径；`/log/tab/tab/list` 仍是 launcher 的 recent。

## 方案

### ai（TS）

- `src/registry.ts`：
  - `Sess` 加 `tabId`；`new()` / `resume()` 接受并保存。
  - 新 `layoutTool`（`defineTool`），execute 里：读/校验/分配会话/写 log，返回 `{ content: [...], details: { layout, tabId } }`。
  - `customTools: [askUserTool, layoutTool]`，并加进 `tools` 白名单。
- `src/layout.ts`（新）：`normalize(tree, { newSession })` —— 校验 + 归一化 + 回显；`readLayout(logBase, tabId)`。
- `src/server.ts`：`/ai/new`、`/ai/resume` 接 `tabId`。

### web

- `app.js`：
  - 新 `pane` 段：`tabPanes(tab)` 建/复用 pane、`renderPanes(tab, layout)` 按树建 DOM、`focusPane(key)`、`applyPaneLayout(tab, layout)`。
  - `#ai` 那块 DOM 改成模板：chat pane 的 `.pane` 里含 `.pane-scroll > .pane-messages`，composer 搬入。
  - `aiMessagesEl` → `aiPaneMessages()`；`aiSession`/`aiSeenSeq`/`aiStreamCtl`/`aiStreamGen`/`aiStreaming` → 当前 pane 的字段；`aiStream(pane)` / `aiCancelStream(pane)`。
  - `aiDrafts` 的 key 从 tab id 改成 pane key。
  - `tool_execution_start` 分支加 `layout`。
- `style.css`：`.panes` / `.pane` / 分割权重 / brief 高度。

### 契约与静态关系

- `ai-new` / `ai-resume` 的 request 各加 `tabId?`，response 各加 `tabId`。
- `atoms/ai.yaml`、`atoms/web.yaml`：无新接口（工具不是 HTTP 接口）。
- `edges/ai-to-log.yaml`：+3 条（ai 工具读写 `/log/tab/*`）。
- `atoms/ai.yaml` 的 description 补一句布局工具。
- `docs/ai.md` 补 `layout` 工具与新字段。

### skill

`.agents/skills/pane-layout/SKILL.md`：什么时候用、先读后写、schema、典型配方（单栏 / 双栏 / 主次 / 三栏 / 2×2 / 上 3 普通 + 下 1 brief / 详情 + 右侧 brief 堆）。

## 测试

`development/testing/dev/case-core-web-panes/`（浏览器）：

1. 默认单 pane，行为同 i2。
2. 工具帧把布局改成两栏 → 两个 `.pane`，左边会话是原来的、右边会话是新的。
3. brief pane 的高度明显小于 fill pane。
4. 每个 chat pane 有独立的消息列表；往第二个 pane 发消息，第一个不动。
5. 刷新后布局从记录恢复（两栏还在）。
6. `page` pane 渲染 iframe，`chat` pane 不渲染。
7. launcher 的 recent 仍按 tab 列。

`case-core-ai-flow` 追加：`/ai/new` 返回 tabId；`layout` 工具读写（stub 模式下手调工具不可行，改由直接调 `/ai/ask` 观察 tool 事件，或只测 HTTP 字段）。

## 实施记录（Phase 3）

### ai（TS）

- `src/layout.ts`（新）：`normalizeLayout`（校验 + 填默认 + 为新 chat pane 分配会话）、`describeLayout`、`readLayout` / `writeLayout`。上限 6 pane，`brief` 必须在 `row` 里，`weight ∈ 1..3`。
- `src/registry.ts`：`Sess.tabId`（不带就分配 `t_<hex>`）；`makeLayoutTool(logBase, sess, newSession)` —— **每个会话一个实例**，闭包持有 tabId；无参 = 读，带 `layout` = 整树替换并回显；工具写进白名单。
- `src/server.ts`：`/ai/new` 与 `/ai/resume` 各接可选 `tabId`，响应各回 `tabId`。

### web

- `index.html`：`#page` / `#page-frame` 删掉，换成 `#panes`；`#ai` 里只剩 composer（`#ai-scroll` / `#ai-messages` 变成每个 pane 自己一份）。
- `app.js`：
  - 新 pane 段：`defaultLayout` / `tabLayout` / `makeChatPane` / `makePagePane` / `ensurePane` / `buildPaneNode` / `renderPanes` / `showPanes` / `focusPane` / `paneAt` / `applyPaneLayout` / `applyLayoutFrame` / `loadPaneConversations`。
  - 事件：`panesEl` 的 mousedown 聚焦被点的 chat pane。
  - 单例改 per-pane：`aiSession`/`aiSeenSeq`/`aiStreamCtl`/`aiStreamGen`/`aiStreaming` → pane 字段；`aiStream(pane)` / `aiCancelStream(pane)` / `aiStreamOnce(id, since, ...)`；`aiRenderPane` 决定渲染目标（后台 pane 的流写自己的列表）。
  - composer 仍是单例，用 `appendChild` 搬进聚焦 pane；草稿 key 从 tab id 改成 `tab id + pane key`（**每个 tab 的树都从 `0` 开始，只按 pane key 会跨 tab 撞车** —— 实测踩到过）。
  - `activateTab` 重写：`syncTabRecord`（建 或 读回布局）→ `showPanes` → `focusPane` → 拉流。
  - `pushPageTheme` 遍历所有 tab 的所有 page pane。
- `style.css`：`#panes` / `.pane-tree` / `.pane-split.col|row` / `--w` 权重 / `.pane.brief`（132px 固定高）/ `.pane-scroll`；删掉 `#page` 与 `#ai.tab-mode` 的旧规则。

### 契约 / 静态 / 文档

- `ai-new` / `ai-resume` 各加 `tabId`。

- `edges/ai-to-log.yaml`：+2 条。
- `docs/ai.md`：两个接口的 `tabId` 字段，末尾加 `## Tools` 一节（ask_user + layout 与树形状）。

### skill

### 测试

- `case-core-web-panes`（新，9 项）全过：默认单 pane、composer 在聚焦 pane 里、两 pane 树渲染出 2 split + 2 chat + 1 page、每个 chat pane 有自己的消息列表、brief 明显矮于旁边、点第二个 pane 后发消息不影响第一个、刷新后拆分还在、无页面错误。
- `case-core-web-tabs` 41/41；`case-core-web-tab-records` 16/16 —— 都不回退。
  - 两个用例的启动脚本会重复启动服务（同端口），旧进程会继续服务旧库，导致 launcher 的 recent 里堆几十条脏记录。跑前先 pkill。
- `case-core-web-page` 为 pane 改了选择器（`#page` / `#page-frame` → `#panes .pane-page .pane-frame`），改完后 8 项通过，停在**与基线完全相同**的 iframe 主题步骤（前置缺陷）。
- `case-core-web-chat-route` 仍是基线那个超时，与本次无关。

### 端到端（真模型）

让模型自己拆：对话 `用 layout 工具把屏幕拆成左右两栏……` → 模型先调 `layout` 读，再写，屏幕真分成两个 chat pane（左 7 条消息保留，右新会话 0 条），**没有出现 tool chip**。记在这里因为这一半需要真 provider，用例没法确定性复现。

### 试跑时眼看抓到的两个问题（已修）

用例扫不到，跑起来才看见：

1. **composer 不沉底**。`#ai` 上还留着 `flex: 1`（它是整个内容区那会儿的写法），搬进 pane 后和消息列表各占一半，输入框悬在屏幕中间。改成 `flex: 0 0 auto` —— 在 pane 里它是 footer，上方的消息列表吃掉剩余空间。
2. **模型会自己编 chat session id**。它写了个 UUID（`01a13044-…`）当 `pane.id`，而 `normalizeLayout` 只在 id 为空时才开会话，于是整棵树指向一个没人能打开的会话 → 前端 `[error] session not found`。现在工具把“解析不到”的 chat id 当成省略处理（新增 `hasSession`：活会话 或 有历史记录），tool description 也补了一句“不要自己造 id”。

复验：tabs 41/41、page 15/15、panes 9/9、chat-scroll 9/9、tool-chips 32/32；真模型拆窗截图里左侧是干净空白对话 + 底部全宽 brief 条。

### 与设计稿的差异

- `edges/ai-to-log.yaml` 加的是 **2** 条不是 3 条：工具只读和写，不列。
- 设计稿说 `openPageTab` / `routePage` 不变；实际上 page 的渲染整体换成了 pane（`#page` 删掉），这两个函数本身仍只管"建个 page tab"，没动。

## 范围外

- 拖拽改分割（只能靠模型）。
- 重排时保住 chat 的滚动位置 / iframe 的现场。
- 删除 tab 记录。
- 每轮注入布局。
- `pane` 独立 id（仍以内容 id 关联）。
