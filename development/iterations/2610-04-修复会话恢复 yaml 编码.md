# 修复会话恢复：YAML 编码器产出非法 block scalar

## 需求

前端从会话列表切到某条历史会话时，部分会话报 `[error] session not found`，即使该会话在 sqlite 中有完整记录。需修复，使所有已存会话都能正常恢复。

## 现状与根因

- 前端 `aiLoadSession` 调 `POST /ai/resume`（`workspace/web/app.js:2135`）；
- ai 的 `Registry.resume` 经 `fetchRecords` 调 `POST /log/session-detail` 拉历史（`workspace/ai/src/registry.ts:320`、`workspace/ai/src/recorder.ts:56`）；
- log 用 `yaml.Marshal` 序列化响应（`workspace/log/internal/server/server.go:58`），默认 indent=4；
- `gopkg.in/yaml.v3 v3.0.1` 编码器在 indent=4 时，对**首行以空白开头、后续行缩进更小**的多行字符串，会写出缩进指示符错误的 block scalar（如 `|4-`），产出**非法 YAML**；
- 复现会话含 edit 工具调用的 `newText = "  hidePanel();\n  showView(parseRoute());\n} catch (err) {"`（`seq 259`），正好命中；
- JS 的 `YAML.parse` 抛异常，`fetchRecords` 的 `catch` 吞掉后返回空数组，`resume` 于是返回 404 → 前端显示 `session not found`；
- 同一 bug 在写库时也触发（`workspace/log/internal/store/store.go:108`）：已存会话约 14 条 payload 被写成非法 YAML，读库时被 `SessionMessages` 跳过（已损坏，无法还原；其余 285 条可用）。

## 方案

1. `log` 与 `static` 中所有 `yaml.Marshal` 改为统一走 `marshalYAML`，用 `yaml.NewEncoder` + `SetIndent(2)`：
   - `workspace/log/internal/server/server.go`（响应与 SSE 流）
   - `workspace/log/internal/store/store.go`（写库 payload）
   - `workspace/static/internal/server/server.go`（同款响应与 SSE）
2. `fetchRecords` 解析失败不再静默：打印错误后返回空数组，避免下次仍伪装成 404。

indent=2 的选择依据：以 348 组"首行带空格/换行"的多行字符串构造 payload 嵌套，indent=4 有 172 组产出非法 YAML，indent=2 **全部合法**。

## 范围外

- 不迁移/修复已损坏的 14 条历史 payload（不可逆）；
- 不改变 YAML wire 格式（仍为 `application/yaml`）。

## 验收

- `POST :7503/log/session-detail`（`sessionId=s_fa16b7b1f0bf0599`）返回的 YAML 可被 JS/Python/Go 解析；
- `POST :7501/ai/resume` 对该会话返回 `sessionId` 而非 404；
- 前端从列表切到该会话，不再出现 `session not found`，历史消息正常回放；
- `go build ./...`（log、static）与 `tsc --noEmit`（ai）通过。

## 影响面

`workspace/log/internal/{server,store}`、`workspace/static/internal/server`、`workspace/ai/src/recorder.ts`。无接口契约、schema 变更。
