# 标题短一些 + main 下划线左右对称

## 需求

两处界面上的小毛病：

1. **标题太长**：tab 名（`2610-53` 的自动标题）现在允许「20 个汉字 / 10 个英文单词」，
   实际出来常常是一句话。希望收紧：**英文 2–4 个单词，中文 10 个字以内**。
2. **main 选中时的下划线左右不等宽**：`main` 这个 tab 选中的下划线，文字左边那段比右边长。

范围外：标题的人工编辑 / 配置项；tab 条的其它几何（分组、chip、`+`）；tab 的最大宽度。

## 现状（实测）

**标题长度**。`workspace/ai/src/title.ts`：

- `TITLE_SYSTEM_PROMPT` 写的是「不超过 20 个汉字或 10 个英文单词」；
- `cleanTitle()` 的兜底是 `MAX_TITLE = 60` 个字符，一刀切、不分语言。

于是模型照着 20 字的上限写，tab 里就是一句半的话；而 60 字的兜底几乎不触发，等于没有。

**main 的下划线**。`workspace/web/style.css` 里两条规则叠在同一个元素上：

```css
#tabs .tab                      { padding: 4px 10px; ... }   /* 左右各 10px */
#tabs .tab[data-tab-id]         { max-width: 180px; padding-right: 4px; }  /* 右边只留 4px */
```

`padding-right: 4px` 原本是给 **×** 让位的（`.tab-close` 自己带 `padding: 0 3px`，贴着标签），
但选择器按 **`data-tab-id`** 命中——`main`（`btn.dataset.tabId = tab.id`）和 launcher 图标 tab
也有这个属性，却没有 ×。结果是这两格左边 10px、右边 4px：下划线（`border-bottom`，横跨整个
盒子）在文字左边露 10px、右边只露 4px，看着就是左边宽一截。

## 方案

**A. 标题**（`workspace/ai/src/title.ts`）

- 提示词改成「标题要短：中文不超过 10 个字，英文 2 到 4 个单词，用对话的主要语言」，
  好的例子一并改短（「查看蓝图」「修复登录」），免得模型照旧仿写长句。
- `cleanTitle()` 的兜底按语言分档：**没有汉字**（纯英文）数单词，超过 4 个词就在第 4 个词后截断；
  **有汉字**数汉字，超过 10 个汉字就在第 10 个汉字之后截断，且切点落在拉丁单词中间时把整个
  单词去掉（宁可短，不要半截 `logi`）。
- 截断后再走一遍原有的去首尾标点（`EDGE`），免得切口正好停在一个逗号前。
- `MAX_TITLE = 60` 删掉，换成 `MAX_CJK = 10` / `MAX_WORDS = 4` 两个常量。

**B. 下划线**（`workspace/web/style.css` + `workspace/web/app.js`）

把「右边只留 4px」挂在**有没有 ×** 上，而不是「有没有 tab id」：

- `app.js` 的 `tabButton()` 在画 × 的同一个分支里给按钮加 `closable` 类；
- CSS 拆成两条：`#tabs .tab[data-tab-id] { max-width: 180px; }` 与
  `#tabs .tab.closable { padding-right: 4px; }`。

main 与 launcher 图标 tab 不再命中右边那条，恢复 `padding: 4px 10px`，下划线左右各 10px。

契约 / atoms / edges 不动：没有接口变化，一处是提示词与清洗，一处是样式与类名。

## 验收

1. `development/testing/dev/case-core-ai-session-title` 第 0 段（纯函数）：
   换成新的断言 —— 纯英文超过 4 个词被截到 4 个词；10 个汉字以内原样保留；
   超过 10 个汉字被截到 10 个字；截断后不留句末标点。
2. 同一条用例第 1 段（真模型）的 `len(t) <= 60` 收紧为「汉字 ≤ 10 / 单词 ≤ 4」同一判据，
   并且真跑一轮，确认生成出来的标题确实短。
3. `development/testing/dev/case-core-web-tabs` 新增一条断言：`main` 的
   `getComputedStyle().paddingLeft === paddingRight`（下划线左右等宽）；带 × 的 session tab
   仍然是右边 4px（× 不被推开）。
4. 回归：`core-web-tabs`（tab 条几何）、`core-ai-session-title`（标题）。

## 验证（实测）

- `case-core-ai-session-title` 第 0 段（纯函数，`bun run` 直接跑 `title.ts`）：20 项断言全 PASS。
- 同一条用例第 1 段（真模型）：`session_title` 在 `agent_settled` 之后推下来，
  `title1=查看有哪些蓝图目录`（9 个汉字，不以「助手 / AI / 模型 / 用户 / 我」开头）。
- `case-core-web-tabs`：41 项检查全 PASS，含新增三条 —— main `padding 10/10`、launcher 图标 tab
  `10/10`、带 × 的 session tab `10/4`。
- **反证**：把 CSS 换回旧规则（`[data-tab-id] { padding-right: 4px }`）重跑同一条用例，
  main 量到 `left: 10, right: 4`，两条新断言 FAIL——断言确实盯住了这个毛病，不是摆设。
- 两条用例的 `kind: test` 记录已写入 log（`core-web-tabs` / `core-ai-session-title`）。

## 遗留

- 标题仍然是「模型写的 + 兜底截断」，截断后的读感不如模型直接写短的好；提示词是主要手段。
- 汉字超过 10 个时的截断按汉字切开，中文本身没有词边界，可能停在半截词上（与旧行为一致，
  只是更早）。真要分词得引一个分词器，本轮不做。
- 改动在 `workspace/ai` 与 `workspace/web`：`serve-web` 直接服务 `workspace/web`，刷新即生效；
  ai 侧要重启 `main.ts`（或重新打包）才生效。
