# 工具 chip 精简与横向排布

## 需求

对话区的 chip（thinking + 工具调用）现在是「一个 chip 占一行、标题就是工具名」，
既占纵向空间又看不出调用了什么。改成：

1. **标题只留关键信息**，宽度固定 `120px`，溢出显示 `…`：

   | chip | 标题 |
   | --- | --- |
   | thinking | `thinking` |
   | bash | 终端图标 + 命令名（首个程序名） |
   | read / write / edit | 文件名（basename，不含路径） |
   | grep / find | 搜索模式（`pattern`） |
   | ls | 目录 basename，空则 `.` |
   | save_skill | 技能名 |
   | 未知工具（兜底） | 工具名 |

2. **每个 chip 前置一个图标**（内联 SVG，12×12，`stroke: currentColor`，无依赖）。
   read / write / edit / grep / find / ls 各有自己的图标；未知工具用扳手。

3. **去掉右侧箭头**（`.ai-collapse-caret`）。可点性由 `cursor: pointer` 与 hover
   背景表达。

4. **chip 横向流式排布**：连续的 chip 用 `flex-wrap` 排在一行，排不下自动换行；
   一旦出现非 chip 内容（正文文字、用户消息、ask_user 卡片、上下文压缩提示），
   后面的 chip 另起一行。thinking 与所有工具**同属一个流**。

5. **详情在「所在那一行」下面展开**：点一个 chip，详情不是塞进那个 120px 的小格，
   而是在**该 chip 所在那一行的最后一个 chip 之后**插入一块横跨整行的面板。
   例如两行（第一行 8 个、第二行 6 个）：点第一行任意一个，详情出现在第一行与
   第二行之间，第一行的 8 个 chip 原位不动、第二行整体下移；点第二行任意一个，
   详情出现在第二行下面。

6. **同一时间只开一个详情**：面板会把它下面的行整体推下去，同时开多个只会一直
   向下叠，所以再点另一个 chip 时，先关闭已经打开的那个。

7. **面板第一行是工具名**，下面才是这次调用的详情：工具名在 120px 的 chip 上
   被参数挤掉了，展开后有地方，两者都要看得到。

## 现状

- `workspace/web/app.js:950` `aiCollapse(kind, title)` 构造 chip：标题 + 加载态 +
  `▸` 箭头，直接 append 到 `#ai-messages`（一个 `flex-direction: column` 容器），
  因此每个 chip 独占一行。
- `workspace/web/app.js:1016` `aiTool(toolName, args)` 直接拿工具名当标题；
  `aiThinking()` 同样。
- `workspace/web/style.css:770` `.ai-collapse.ai-tool, .ai-collapse.ai-thinking`
  固定 `300px`，展开态 100%。
- 工具白名单（`workspace/ai/src/registry.ts:362`）：`read` `grep` `find` `ls`
  `bash` `write` `edit` `ask_user` `save_skill`。参数名：`path`（read/write/edit/ls）、
  `pattern`（grep/find）、`command`（bash）、`name`（save_skill）。
- `ask_user` 在**实时**路径不渲染 chip（`app.js:1162` 直接渲染问题卡片），但在
  **历史回放**路径（`aiRenderRaw`，`app.js:2119`）会渲染成一个 chip —— 两条路径
  不一致。

## 方案

### 标题提取（app.js）

新增 `aiToolChip(name, args) -> { label, icon, name, tip }`：

- `basename(path)`：去掉尾部 `/`，取最后一个 `/` 或 `\` 之后的部分；空串回退到工具名。
- 命令名：按 `&&` `||` `;` `|` 换行切段，逐段取首个 token，跳过
  `VAR=x` 赋值、`sudo` / `command` / `exec` / `env` / `nohup` / `time` 包装词，
  以及整段只是 `cd <dir>` 的段；取第一个非空结果。**只取程序名**（`git commit` →
  `git`，`bun run x` → `bun`），完整命令在展开区与 `title` 里。
- `grep` / `find` 取 `pattern` 原文（不加 `/ /`，斜杠在小格子里是噪音）。
- `title` 属性 = 工具名 + 完整参数（路径 / 命令 / 模式），用于悬浮查看被 `…` 截断
  的部分。

### 图标（app.js）

`AI_ICONS`：工具名 → 24×24 viewBox 的 path 数据（Lucide 风格线性图标），
`aiIcon(name)` 包成 `<span class="ai-chip-icon">`，未知工具取 `AI_ICONS.unknown`
（扳手）。统一 `stroke="currentColor"`，颜色继承 `--fg-muted`，不按工具上色。

thinking 用**六芒星**（三条过中心的线段），不用四点星：四点星的凹边在 12px 下
墨量太少，和文件/文件夹那些大轮廓图标放在一起显小得看不清。

### 横向 chip 流（app.js + style.css）

- 模块级 `aiChipRowEl`；`aiChipRow()` 惰性创建 `.ai-chip-row` 容器（`display:flex;
  flex-wrap: wrap; gap: 6px; width: 100%`），`aiChipRowEnd()` 置空。
- `aiCollapse` 对 `thinking` / `tool` 追加到 `aiChipRow()`，不再直接 append 到
  `#ai-messages`。
- 非 chip 内容的构造点调用 `aiChipRowEnd()`：`aiMarkdown()`、`aiAppend()`、
  `aiAppendUserParts()`、`aiAskUser()`、`aiRenderRaw` 的 compaction 分支。
- 容器被清空（切换会话 / `innerHTML = ""`）时 `isConnected` 为 false，`aiChipRow()`
  自动重建，无需额外重置。

### 详情面板按行展开（app.js + style.css）

- 详情不再是 chip 的子元素（`wrap > body`），而是预先建好、**保持游离**的
  `.ai-collapse-body`；打开时才插入行内。它作为行的 flex item 占满整行
  （`flex: 0 0 100%`），所以 chip 打开时仍然是 120px。
- `aiShowPanel(entry, open)`：开关一个 chip 的详情（`.open` 类 + `hidden` +
  写入 `aiOpenPanels`），先把其他已打开的面板关掉（面板是排他的），然后交给
  `aiLayoutPanels()` 统一排版；`aiSetPanelState()` 只改状态、不排版，避免递归重排。
- `aiLayoutPanels()`：先把所有已打开的面板从 DOM 摘掉（这样量行边界不受面板
  自身影响），再按文档顺序逐个插到「该 chip 所在行的最后一个 chip」之后 ——
  用 `getBoundingClientRect().top` 判断同行的最后一个。按顺序插入保证后面那些
  chip 量到的是它们实际会落到的那一行。
- 只在开关和 `resize` 时重排，**不**在流式新增 chip 时重排：打开的面板把所在行
  「封」住，新 chip 排在面板下面，不会把正在看的内容顶走。
- `#ai-messages` 被清空时面板随之消失，`aiLayoutPanels()` 里顺手把已断开连接的
  条目从 `aiOpenPanels` 中剔除。
- 面板自己的样式（背景 / 描边 / 圆角 / `max-height: 200px` + 内部滚动）从 chip
  上搬到 `.ai-collapse-body`；thinking 的斜体从 `.ai-thinking .ai-collapse-body`
  改为 `.ai-thinking-body`（面板已不在 `.ai-thinking` 子树里）。
- 面板在建好时就插入第一行 `.ai-collapse-body-name`（等宽、加粗、带下分隔线），
  内容是 `aiToolChip` 返回的 `name`（thinking 就是 `thinking`）；调用详情跟在它
  后面。面板本身的子元素从不会被整体覆写（流式追加只写在内部的 `.ai-tool-body`
  / `.ai-thinking-body` 上），所以这一行不会被冲掉。

### 顺带修一致性

历史回放里 `ask_user` 不再渲染 chip（与实时路径一致），其 toolResult 也随之丢弃。

### 范围外

- 不改 `contracts/` `atoms/` `edges/`：SSE 事件流契约（`contracts/ai-stream.yaml`）
  不变，本次只是同一批事件的呈现方式。
- 不改 ai 服务、log / static 服务。
- 不做「命令名 + 子命令」两级标题（120px 放不下）。
- 不改 chip 展开后的内容、状态指示（转圈 / ✓ / `!`）与 `max-height`。

## 验收

- 单个 chip 渲染宽度 = 120px；所有标题都设了 `text-overflow: ellipsis`，放不下的
  确实被截断（120px 下 `README.md` 已经放得下，`**/*.spec.ts` 这类仍会截断）。
- 每个 chip 有图标；read / write / edit / grep / find / ls / bash / thinking /
  save_skill 各不相同；未知工具用扳手。
- chip 标题与面板首行都是次要信息，`font-weight` = 400（不加粗）。
- 没有 `.ai-collapse-caret` 节点。
- 连续 chip 在同一个 `.ai-chip-row` 内且 `flex-wrap: wrap`：窄容器下换行、
  宽容器下同行；出现正文后，下一个 chip 落在新的 `.ai-chip-row`。
- 点第一行的 chip：面板作为行的子元素插在「该行最后一个 chip」之后、第一行与
  第二行之间，宽度 = 整行宽；第一行 chip 的 `top` 不变，第二行整体下移；
  chip 本身仍是 120px。关闭后行内没有面板。
- 面板第一行 = 被点那个 chip 对应的**工具名**（`read` / `bash` / `ls` /
  `thinking` …，即 `aiToolChip` 的 `name`，不是 chip 上显示的参数），且这是面板的
  第一个子元素；详情内容在它下面。
- 再点同一行的另一个 chip：行内仍然只有 1 个面板，前一个 chip 的 `.open` 已摘掉，
  面板位置不变、行内 chip 的 `top` 仍不变，且面板第一行换成新工具的名字。
- 点最后一行的 chip：面板落在整行最后（行尾）。
- 历史回放（重新打开会话）与实时流两种路径的 chip 布局一致，且 `ask_user` 无 chip。

## 验证

浏览器 E2E（`case-core-web-tool-chips`）。工具事件无法由真模型确定性产生，
而 `app.js` 是 ES module、`page.evaluate` 拿不到其内部函数，因此用例自带一个
**假 provider**（Go，写在 /tmp，单独进程）按 `contracts/ai-stream.yaml` 的形状
回放一段固定事件流，并兼作 log 读接口；前端跑的仍是真实代码路径
（SSE 解析 → `tool_execution_start` → chip 构造）。假 provider 必须是独立进程：
ego-browser 的 runner 一旦发现脚本自己监听端口，就会丢掉该脚本的 stdout。

覆盖：实时流 11 个 chip 一行 + 正文后 2 个 chip、120px 固定宽、省略号、无箭头、
9 个图标互不相同且未知工具用扳手；第一行某个 chip 的详情落在第一行与第二行之间
（第一行 chip 不动、面板跨整行、chip 仍 120px）、再点同行另一个 chip 时仍只有
一个面板且位置不变、关闭后消失、最后一行的详情落在行尾；面板首行是工具名（逐个
断言 `thinking` / `read` / `ls`）、且标题与首行都不加粗；以及历史回放的同一分组与
`ask_user` 不成 chip。32 项检查全部通过。

另在 dev 栈上跑过三次真实模型（`how-to/deploy/dev/launch.sh`，ai :8501 /
web :8500，模型 deepseek/deepseek-flash）的对话：10 个调用的那轮排在两行（7 + 5），
点第一行第一个后面板插在该行之后（第一行 chip 原位、第二行下移），再点收起完全复原；
5 个调用的那轮用 16 倍放大截图确认了新图标；另一轮在面板首行看到了 `read`。
