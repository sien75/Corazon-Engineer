# 服务默认监听回环地址（127.0.0.1），保留全网段开放开关

## 需求

在本地（macOS）运行 engineer 时，公司端点安全软件（蚂蚁 Aspect/星点）每次启动都会触发 4 次检查/告警。需要定位敏感点并将其消除，同时**不能丢掉"需要时对局域网开放"的能力**。

## 现状与根因

实测本机运行中的 prod 实例：

```
$ lsof -nP -iTCP -sTCP:LISTEN | grep engineer
engineer-log      TCP *:7503 (LISTEN)
engineer-static   TCP *:7502 (LISTEN)
engineer-ai       TCP *:7501 (LISTEN)
engineer-web      TCP *:7500 (LISTEN)
```

4 个服务全部监听在 `*`（即 `0.0.0.0`，全网卡），而它们彼此只通过 `http://localhost` 通信。根因是端口地址写法一律省略 host：

| 位置 | 现状 |
| --- | --- |
| `how-to/deploy/prod/launch.go` | `addr := func(name string) string { return ":" + port }`；`portFree()` 探测端口也用 `net.Listen("tcp", ":p")` |
| `how-to/deploy/dev/launch.sh` | 3 处 `--addr ":$PORT_xxx"` |
| `workspace/log/main.go` | 默认 `":7503"` |
| `workspace/static/main.go` | 默认 `":7502"` |
| `workspace/ai/src/main.ts` | 默认 `":7501"`；`server.ts` 把 `:port` 显式映射为 `0.0.0.0` |
| `workspace/web/server/main.go` | `addr := ":" + strconv.Itoa(port)` |

**4 个全网卡监听 = 4 次检查/告警**，与观察一致。

除告警之外还有一个真实风险：7500 是 web UI，通过它可以驱动 agent 执行命令；监听在办公网段上意味着同网段任何人都能连上并操作。

## 方案

1. **默认全部绑 `127.0.0.1`**，端口不变 —— 各服务自己的默认端口（web 7500 / ai 7501 / static 7502 / log 7503，dev 为 850x）与改动前一致，这次只加 host 前缀，**没有改任何端口**。这些默认值只在手跑单个服务、不带地址参数时生效；正常由启动器选端口（占用即顺延）后显式下发，服务一律以启动器给的端口为准。
2. **保留全网段开放的参数能力**：新增环境变量 `ENGINEER_BIND`（值为 host），默认 `127.0.0.1`。
   - 由**启动器统一决定并显式下发**——bind host 属于一次运行，不属于某个服务：log/static/ai 走既有的 `--addr <host>:<port>`；web 的端口是位置参数、host 无处可传，故给它加一个 `--bind <host>` flag。
   - 各服务自身的默认值只负责"单独运行时也安全"。
   - `ENGINEER_BIND=0.0.0.0 engineer` 即恢复全网段开放；`ENGINEER_BIND=<本机IP>` 则只绑该网卡。
3. **URL 与绑定解耦**：服务间互调地址、以及 web 通过 `/config.js` 交给浏览器的地址，目前是 `http://localhost`。绑回环时 localhost 仍然可用；但绑 `0.0.0.0` 供远程浏览器访问时，localhost 会指向访问者自己，因此启动器在通配场景改用**本机对外 IPv4**（枚举网卡取第一个 global unicast IPv4，取不到回退 localhost）生成这些 URL，并打印出来。
4. **端口探测同源**：`portFree()` 用同一 host 绑定做占用探测；"是否有进程应答"的 dial 在 host 为通配时改用 `127.0.0.1`（`0.0.0.0` 不可 dial）。
5. **启动横幅**打印实际绑定的 host，非回环时明确提示已对全网段开放。

## 范围外

- **不改 `reclaim()`**（pid 文件 + `ps -ax` 枚举 + 按命令行 SIGTERM 回收上一个实例）：它是功能，且未观察到触发安全软件。
- **不改各服务默认值里的端口号**：`127.0.0.1:7503` 这类默认值只是 `--addr` 未传时的取值（仅手跑单个服务时生效），端口号与改动前完全一致；启动器下端口 100% 来自它的实选结果，顺延不受影响。已确认不构成问题，保持原样。
- 不改端口默认值与端口选择算法；不引入配置文件（沿用环境变量/参数）。
- 不改各服务的 wire 接口与契约。

## 验收

默认路径（常规回归）。注意**端口以启动器当次打印的为准**（被占用会顺延），断言只看host 与可达性，不看具体端口号：

- 默认启动后，四个服务监听的 host 均为 `127.0.0.1`，**没有**任何服务监听在 `*`（即 `0.0.0.0`）；端口取启动器打印的那四个。
- 默认下用启动器打印的 web 地址打开本机浏览器，对话与 schema 查询正常（回环不影响本机使用）。
- `go build ./...`（log / static / web）、`go build how-to/deploy/prod/launch.go`、`tsc --noEmit`（ai）通过。

开放路径（⚠️ 按需验证，**不作为常规回归** —— 执行即触发公司安全软件告警，见测试用例 `case-core-loopback-bind` 顶部的说明）：

- `ENGINEER_BIND=0.0.0.0 engineer`：四个服务全部监听 `*`，且横幅与 web 的 `/config.js` 给出本机对外 IPv4。
- 该模式下从另一台机器访问启动器打印的 web 地址，UI 正常且三个后端可调。

- 代码：`how-to/deploy/prod/launch.go`、`how-to/deploy/dev/launch.sh`、`workspace/log/main.go`、`workspace/static/main.go`、`workspace/ai/src/main.ts`、`workspace/web/server/main.go`
- 文档：`how-to/deploy/{prod,dev}/BOOK.md`、`README.md` / `README_zh.md`

- 无 contracts / atoms / edges 变更（这是 CLI/环境变量行为，不是 atom 之间的接口契约）

## 与安全软件的关系说明

已实测确认「全网卡监听 = 触发，回环 = 不触发」：默认绑 `127.0.0.1` 时不再触发；一旦用 `ENGINEER_BIND=0.0.0.0` 打开，端点安全软件即按进程告警（4 个服务 4 次）。

因此**默认值是回环，开放是显式动作**，并且开放路径的验证在测试用例里标为按需执行、不作为常规回归。若默认（回环）下仍触发，下一个嫌疑是 `reclaim()` 的全局 `ps -ax` 进程枚举 + 按命令行 SIGTERM（EDR 视角下的 Process Discovery / Termination），届时再单独评估。
