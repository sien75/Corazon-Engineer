# 图片限尺寸与蒙层查看

## 需求

- 信息流里的图片（用户粘贴的、生图工具产出的、正文 markdown 里的）一律按**最大 300×300、等比，图更小就按原尺寸**展示。
- 点图片在**蒙层**里看大图；蒙层只盖这个会话面板（这个 tab 的内容），不是整个窗口 —— tab 栏、其它 pane、页面其它部分都不受影响。点蒙层或按 Esc 关闭。

范围外：缩放 / 拖拽 / 多图翻页 / 下载；作者手工控制尺寸的 markdown 语法；`/blobs` 之外的图片存储变化。

## 现状（实测）

- `workspace/web/components/chat.js`：用户粘贴的图走 `userMessage()`（`img.ai-user-img`），生图结果走 `imageMessage()`（`img.ai-gen-img`，带 `details` 里的 `width/height` 属性），正文图是 markdown 渲染出的 `<img>`。
- `workspace/web/components/chat.css`：三类图都只写了 `max-width: 100%`（跟着 880px 的正文列走）。生图自带 `width/height` 属性，于是 1024 / 2048 的图就按接近原尺寸铺满整列 —— 这就是「直接原大小展示」。
- 没有点击 / 预览：组件是 shadow root（`components/chat.js` 的 `TEMPLATE` + `chat.css`），页面的 CSS / JS 进不去，所以预览只能在组件里做。
- 回放 log 历史的用户图是坏的：`replayHistory()` 交下来的是 `{type:"image", src}`，而 `userMessage()` 只认 `data` + `mimeType`，`src` 落在 `data:undefined;base64,undefined` 上（刷新后粘贴图变坏图）。

## 方案

**A. 尺寸上限**（`components/chat.css`）

- 一条共用规则罩住 `.ai-user-img` / `.ai-gen-img` / `.ai-markdown img`：`max-width: min(300px, 100%); max-height: 300px; height: auto; cursor: zoom-in`。
- 原来各自的 `max-width: 100%` 删掉（留着会与共用规则打架）；间距、圆角留在原规则里。
- `height: auto` 让 `max-height` 生效又不改比例；生图仍保留 `width/height` 属性，图没到之前位置照旧占着（属性比例给的是 `aspect-ratio`）。

**B. 蒙层**（`components/chat.js` 的 `TEMPLATE` + `wire()`，`components/chat.css`）

- `TEMPLATE` 在 `.pane` 末尾加 `<div class="ai-lightbox" hidden tabindex="-1"><img alt=""></div>`。
- `.pane` 加 `position: relative`；`.ai-lightbox` 是 `position: absolute; inset: 0` —— **贴着会话面板**，不是 `position: fixed`。这是「只盖这个 tab」的实现方式：`<engineer-chat>` 就是 tab 的内容盒。
- `[hidden]` 显式写 `display: none`：`display: flex` 是作者样式，UA 的 `[hidden]` 压不住。
- 打开：`messagesEl` 上一条委派 `click`，命中后的 `<img>` 把 `src/alt` 交给蒙层里的图并解除 `hidden`，焦点给蒙层。委派而不是逐处挂监听 —— 历史回放、实时渲染、以后新加的图都自动带上。
- 关闭：蒙层上任意点击；蒙层拿到焦点时 Esc（`stopPropagation()`，别让全窗口的「Esc 停掉这一轮」一起触发）；关闭时清掉 `src`。
- 蒙层里的大图 `max-width/max-height: 100%`（蒙层已经留了 24px 内边距），所以按面板大小看到原图。

**C. 顺带修好回放的用户图**（`components/chat.js` 的 `userMessage()`）

- `img.src = b.src || \`data:${b.mimeType};base64,${b.data}\``：刚发的这一条用 base64，回放用 blob 地址。只认 `data` 会让刷新后的粘贴图是坏图，而这条路径正好是本轮要验证的那一类图。

不改：`workspace/web/app.js`（外壳只负责挂 `<engineer-chat>`）、`dist/`（构建产物）。

## 测试

`development/testing/dev/case-core-web-chat-image-lightbox`（`desp.yaml`、`TEST.md`）：Bun 夹具
出页面 + 一段造出来的历史（用户粘贴图 + 生图结果），组件从 `workspace/web` 原样服务，真实浏览器
（`ego-browser`）断言三件事：

1. 两类图都在 300×300 以内且比例不变（宽图 300×150、竖图 180×300）。
2. 点图出蒙层，蒙层矩形**等于** `engineer-chat` 的盒子、等于面板盒子；页面顶栏那一条
   `elementFromPoint` 仍命中顶栏，说明蒙层没有盖到 tab 外面。
3. 点蒙层 / Esc 都能关掉；关闭后蒙层 `display: none`。

## 验收

1. `case-core-web-chat-image-lightbox` 全绿（`"ok": true`，退出码 0）。
2. 在 dev 栈上人工看一眼：粘一张大图、跑一次生图，两张在信息流里都不超过 300px，点开是蒙层，
   蒙层不出这个 tab，Esc 关掉，且 Esc 不会顺手停掉正在跑的那一轮。
3. 主对话（外壳自己的 tab）里的图同样是这个行为 —— 用的是同一个组件。

## 已知缺口

- 回放的用户图 `src` 指向 `${AI}/blobs/<sha256>`：ai 那边 blob 过期 / 被清掉时，历史里的粘贴图会
  是坏图（既有的回读路由，本轮不动）。
- 蒙层不做缩放、拖拽、多图切换；一次只能看一张，关掉再点下一张。
