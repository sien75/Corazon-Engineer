# 2610-37 /config.js 改为 ES module 导出

## 需求

`/config.js` 不再往 `window.ENGINEER` 上挂全局，改成 ES module 导出；前端、chat 组件、
blueprint 页面一律用 `import` 取，不再出现 `window.ENGINEER`。说明文档（`BLUEPRINT_how-to.md` /
`_zh`）里的写法同步改成 `import`。

## 为什么

- `window.xxx` 是隐式契约：谁先执行、谁写在页面里都没有保证，页面和组件只能"猜全局有没有到"。
  上一轮的实测结论是 `import("/config.js")` 只有副作用、`exports: []`，正是这个原因的极端表现。
- 模块导出是显式的：`import { ENGINEER } from "/config.js"`，取不到就是加载失败，浏览器直接报错，
  不存在"读到 undefined 再静默连错端口"。
- 顺带把"页面要用 `<script src>` 还是 `import`"这个反复解释的问题消掉：只有一种写法。

## 契约（先定形状）

`GET /config.js` → `200 text/javascript`，body：

```js
export const ENGINEER = {"static":"…","ai":"…","log":"…"};
export default ENGINEER;
```

- 具名导出 `ENGINEER` 是推荐用法（显式），额外给 `default` 只是省一次解构。
- 键序仍是 static / ai / log（由 `json.Marshal` 的结构体字段顺序决定，不变）。
- 仍然是生成响应、`Cache-Control: no-store`，与其它 web 响应一致。

这是一条 web 内部契约（web 自己产生、web 自己的页面消费），不改 `contracts/` 里的
ai / static / log 三份；`atoms/web.yaml` 的描述里补一句"config.js 是 ES module 导出"。

## 改动范围

1. `workspace/web/server/serve.go`：生成 `export const ENGINEER = …; export default ENGINEER;`。
2. `workspace/web/index.html`：删掉 `<script src="/config.js">`。
3. `workspace/web/app.js`：`import { ENGINEER as RUNTIME } from "/config.js";`，保留 ai / log 缺失时的明确报错。
4. `workspace/web/components/chat.js`：`runtime()` 改成 `await import("/config.js")`（动态 import，
   保持"页面不加载也能用"的既有行为；失败时仍给出可读提示）。
5. `.agents/blueprints/project/index.html`、`.agents/blueprints/hello/index.html`：内联脚本改
   `type="module"` + `import`，删除动态注入 `<script>` 的那段。
6. `.agents/BLUEPRINT_how-to.md` / `_zh`：`/config.js` 一栏、叙述段、static/log 例子全部改成 `import`。
7. `workspace/web/components/README.md`、`chat.js` 头注释同步。
8. 用例：`case-core-web-serve` §3 的期望 body；`case-core-web-chat-scroll` / `tab-state` /
   `panes` / `tab-records` 里 `window.ENGINEER.x` 改成 `(await import("/config.js")).ENGINEER.x`。

## 不做的

- 不做"全局 + 导出"双写兼容：那等于把隐式契约又留一份。
- 不改 ports / 地址来源 / 生成时机 / 缓存策略。
- 不改 `contracts/` 三份服务契约。

## 影响（要说清楚的）

`/config.js` 从经典脚本变成模块后，**旧 agent 副本里"动态注入 `<script src=\"/config.js\">` 再读
`window.ENGINEER`"的页面会失效**（`export` 在经典脚本里是语法错误）。已开的 project / hello 实例
需要重新实例化；pure-chat 不受影响（它自己没有 config 代码，`/components/chat.js` 是外壳的、
始终最新）。这是"副本是快照 + 外壳接口演进"的必然结果，本轮接受。

## 验证

- `case-core-web-serve`（§3 body）与四个引用 `window.ENGINEER` 的用例改完后复跑。
- dev 栈重启后：shell 正常起、`<engineer-chat>` 正常收发（走 chat.js 的动态 import）、
  project / hello 两个原型重新实例化后页面正常。
