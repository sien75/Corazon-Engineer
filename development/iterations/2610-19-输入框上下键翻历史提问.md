# 输入框上下键翻历史提问

## 需求

web 的 AI 输入框（`#ai-input-field`）里按 ↑ / ↓，像 CLI 那样翻**本轮对话里我发过的纯文本提问**：

- 范围 = **当前这个对话（session）自己的**提问，不含别的会话的；
- **关掉 tab 再打开、切走再回来、刷新页面、深链进来**，都要还能翻到；
- 带图片的提问不进历史；
- 多行输入时只在光标位于首 / 末**可视行**时才触发，否则是正常移动光标；
- 从最新一条往回翻到最旧后，再往下能回到"当前草稿"。

## 现状

- composer 是共享 DOM：`#ai-input-field`（`index.html:55`）；每个 tab 的草稿由 `aiDrafts`
  （`app.js:1750`）按 tab id 保存 / 恢复（`aiSwitchDraft`，调用点在 `activateTab`）。
- 发送入口只有 `aiSend()`（`app.js:1606`）：校验非空 → 清空输入框 → `aiBuildSendBlocks` 组装 blocks
  → `POST /ai/ask` → `aiStream()`。`aiAnswer()`（`app.js:1635`，`ask_user` 卡片作答）也走 `/ai/ask`。
- 消息 DOM：用户气泡 `#ai-messages .ai-msg.ai-user`（`aiAppendUserParts`，`app.js:980`）。
- **打开一个已有会话时前端已经拉过一次 `POST /log/session-detail`**：`aiLoadSession`
  （`app.js:3021`）先 `/ai/resume` 再拉 session-detail，交给 `aiRenderHistory` 回放
  （`activateTab` 的非 fresh 分支、`/resume`、`/chat/<id>` 深链、刷新后恢复 tab 都走这里）。
  新建会话（`tab.fresh` 分支）不拉，也没什么可拉。
- 现有方向键：`aiInputEl` 的 keydown（`app.js:2988`）；命令抽屉 `aiDrawer.kind === "command"`
  打开时 ↑/↓ 交给抽屉选择，抽屉由 `aiSyncCommandDrawer` 按 `/` 前缀打开。
- 现成能力：`aiResizeInput`（`app.js:834`）已经用 `getComputedStyle` + `scrollHeight` 做过文本块测量，
  但没有"光标在第几个可视行"的能力。

## 决策

1. **历史按 session 存，key 用 sessionId**（不是 tab id）：关 tab 再打开、切走再回来、刷新、深链
   都要能找到同一份列表。tab 只是这个会话的一个视图。
2. **两个数据源**：
   - **本页面发过的**：`aiSend()` 里记录，发出的瞬间就能翻到；
   - **这个会话记录里的**：`aiLoadSession` 回放消息时顺手把该会话的 user 文本轮次收成列表。
     `session-detail` 本来就已经拉了一次（就是用来回放的），所以**不加请求、不加契约**，
     也能覆盖"本页面打开之前发的""别的客户端发的""这个功能上线之前发的"。
3. **两个源合起来的口径**：这个会话的每个 **user 文本轮次**都进历史——包括普通提问、`ask_user`
   的作答、skill 开场那段文本。它们在记录里都是 user 消息，分不出处；要精确排除就得给记录加一个
   来源字段（`ask` / `answer` / `skill`），那要动 `log-session-detail` / `log-query-detail` 契约，
   列为后续项。
4. **带图片的轮次跳过**：记录里那段文本回填进 composer 也带不回图片（`aiBuildSendBlocks` 靠
   `[image]` token 配 `aiImages`），所以既不记也不回填。
5. **多行判定用镜像测量**（`aiCaretVisualLine()`）：↑ 只在光标位于第一个可视行时切历史，
   ↓ 只在最后一个可视行且已在浏览历史时切。软换行的长行也算多行——否则在长草稿里按 ↑ 会误吞内容。
6. **命令抽屉优先**：抽屉（command）打开时 ↑/↓ 仍归抽屉，历史让位（保持现有 early-return）。
7. **编辑即退出浏览**：浏览历史期间发生 `input`（键入 / 粘贴 / 删字）就退出浏览，当前文本留作草稿。
   不模仿 bash"编辑后继续从该位置翻"。
8. **回到底部恢复草稿**：第一次 ↑ 时把当时的 composer 文本存为 `draft`；翻到最新一条后再 ↓ 一次
   恢复它并退出浏览。
9. **有暂存图片时不切历史**：`aiImages.length > 0` 时 ↑/↓ 一律走正常光标移动——回填纯文本会让
   `[image]` token 与 `aiImages` 失配。

## 范围外

- 不改后端 / `contracts/` / `atoms/` / `edges`：复用已有的 `log-session-detail`，没有新接口。
- 不给记录加来源字段（排除卡片作答 / skill 开场）——后续项，需要动契约。
- 不做跨会话的历史（A 会话翻不到 B 会话的提问）。
- 不做翻到最旧再回绕、不做前缀搜索（bash 的 `Ctrl-R`）。
- 不动命令抽屉、`/new`、`/resume`、`/ai/ask` 的行为。

## 方案

### 状态与读写（app.js，紧邻 `aiDrafts`）

- `const aiPromptHistory = new Map(); // session id -> { items, cursor, draft }`
- `aiHistoryOf(sessionId)` 取 / 建；`aiHistoryRecord(sessionId, text)` 在 `aiSend()` 里 push
  （同时 `cursor = null`、`draft = ""`）；`aiHistoryEnd(sessionId)` 供 `input` 退出浏览；
  `aiHistoryClear(sessionId)` 供会话被删除时清理（`aiConfirmAccept`）。
- `aiHistorySeed(sessionId, prompts)`：本页面已经攒了列表就**不动**（本页面记录不会落后于 log，
  发送时先记后写记录），只在列表为空时用记录里的提问填充。

### 从记录里收提问（回放那一次遍历）

- `aiRenderHistory(messages, sessionId)`：新建 `prompts = []` 传进两个回放函数，结束时
  `aiHistorySeed(sessionId, prompts)`。
- `aiRenderRaw(raw, tools, prompts)` / `aiRenderLegacy(m, prompts)`：user 轮次里若 parts 全是文本，
  就 `prompts.push(parts.map(p => p.text).join(""))`；带图的不推。
- `aiLoadSession` 里改为 `aiRenderHistory(detail.messages || [], id)`（此处 `aiSession` 还没赋值）。

### 上下键（`aiInputEl` 的 keydown）

插在命令抽屉 early-return **之后**、Backspace/Delete 分支**之前**：

- ↑：`aiImages.length === 0`、历史非空、且（输入为空 或 光标在第一个可视行）→ `aiHistoryUp(aiSession)`
  并 `preventDefault()`；否则不拦。
- ↓：仅在浏览中（`cursor !== null`）时接管，否则不拦（正常移动光标）。
- `aiHistoryUp()`：`cursor === null` → `draft = value`、`cursor = items.length - 1`；
  否则 `cursor = max(0, cursor - 1)`。`aiHistoryDown()`：`cursor < items.length - 1` → `cursor++`；
  否则恢复 `draft`、`cursor = null`。
- 写入文本后统一：`setSelectionRange(len, len)`（光标到末尾，CLI 行为）、`aiResizeInput()`、
  `aiSyncCommandDrawer()`。

### 可视行判定（app.js + style.css）

`aiCaretVisualLine()` 返回 `{ first, last }`：

- 一个隐藏镜像 `div.ai-input-mirror`：`position: absolute; left: -10000px; visibility: hidden;
  white-space: pre-wrap; overflow-wrap: break-word;`，字体 / `line-height` 与 textarea 相同，
  `box-sizing: content-box` 且无 padding / border，宽度取 `aiInputEl.clientWidth` 减去 padding
  （clientWidth 含 padding 不含 border ⇒ 内容宽度与 textarea 一致，包括 10 行时滚动条占宽的情形）；
- 两段测量代替光标标记：把"光标前文本"与"整段文本"各测一次行数
  （`last = 总行数 <= 光标前文本行数`），`first = 光标前文本行数 <= 1`。
  不插零宽标记是因为无论空 `span` 还是零宽空格都会在换行点引入新的断行机会，反而可能改变测量结果；
- 行高 / 字体复用 `aiResizeInput` 的 `getComputedStyle` 读法，不写死数字；
- 只在按 ↑/↓ 时构建 / 更新（不挂在 `input` 上）；`#ai-input` 已是 `position: relative`。

### 边界

- 历史为空：不拦 ↑，光标正常上移。
- 浏览到最旧再按 ↑：停住（不回绕），仍 `preventDefault()`，避免光标跳。
- 回填的文本以 `/` 开头：`aiSyncCommandDrawer()` 会打开命令抽屉，与手输一致。
- 每条 session 上限 `AI_HISTORY_MAX = 100`，最旧的掉出。

## 待确认（review 时定）

1. **重复提问是否去重**：现方案像 bash 一样原样记录（同一句发两次就有两条）。要 `ignoredups`
   行为的话加一行判断即可。
2. **卡片作答 / skill 开场是否要排除**：现方案一起进历史（记录里分不出来）；要精确排除得加来源字段。

## 验收

- 空输入 / 单行草稿（光标在末）：↑ 依次回填**本会话**的提问（由新到旧），↓ 依次回到更新的一条，
  再 ↓ 恢复原草稿；↑ 到最旧停住。
- 多行草稿：光标在首行按 ↑ 回填历史；光标不在首行按 ↑ 只移动光标（无内容被替换）。
  长软换行草稿同样按"可视行"判定。
- 命令抽屉打开时 ↑/↓ 仍只在抽屉里移动。
- **关 tab 再打开、切走再回来、刷新页面、深链 `/chat/<id>` 进来，都能翻到该会话的提问**。
- 新建会话（`/new`、空白 chat、skill 开的会话未发过消息）历史为空；A 会话翻不到 B 会话的提问。
- 带图提问不进历史；输入框有暂存图片时 ↑/↓ 不切历史。
- `/static/validate` 仍 `ok: true`（无 schema 改动，回归确认）。

## 影响面

`workspace/web/app.js` + `workspace/web/style.css`（镜像样式）。无接口、无契约、无 schema 变更。

  关闭 / 刷新而消失。改为上面的 A 方案：按 session 存 + 从 `session-detail` 回放时收提问
  （见"决策 2"）。
- **代码**：
  - `app.js`：`aiPromptHistory`（`Map`，key = sessionId）、`aiHistoryOf` / `aiHistoryRecord` /
    `aiHistoryEnd` / `aiHistoryClear` / `aiHistorySeed` / `aiHistoryShow` / `aiHistoryUp` / `aiHistoryDown`；
    `aiSend()` 在组装 blocks 前 `aiHistoryRecord(aiSession, text)`（仅 `images.length === 0`）；
    `aiRenderHistory(messages, sessionId)` + `aiRenderRaw` / `aiRenderLegacy` 多收一个 `prompts` 数组；
    `aiLoadSession` 传 `id`；`aiInputEl` keydown 在命令抽屉 early-return 之后、Backspace 分支之前接管
    ↑/↓；`input` 监听里 `aiHistoryEnd(aiSession)` 退出浏览；`aiConfirmAccept` 删会话时
    `aiHistoryClear(sessionId)`。

- **与初稿的一处实现取舍**：镜像用两段测量代替光标标记（见"可视行判定"）。
- **实跑**（scratch 栈：log 8525 / static 8526 / ai 8527 `--stub` / web 8630，`ego-browser`）：
  - `case-core-web-input-history`（第 2 版）**20/20 通过**：↑ 从最新往旧回填并停在最旧、光标落到末尾；
