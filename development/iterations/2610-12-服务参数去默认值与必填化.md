# 服务参数去默认值与必填化

## 需求

四个服务（ai / web / static / log）的启动参数存在两个问题：

1. **`workspace/` 里给参数写默认值**——服务替启动方做主，会悄悄接到别人占用的端口上。
2. **四个服务的地址参数形状不统一**——web 用「位置参数给端口 + `--bind`」，其余三个用
   `--addr host:port`。

要求：

- `workspace/` 里**任何取值参数都不写默认值**；必填项缺失 → **直接不启动**（fail fast，
  打印用法并退出）。
- 四个服务的地址参数**统一为 `--bind` + `--port` 两参数**。

## 现状

| # | 文件:行 | 默认值 |
|---|---|---|
| 1 | `workspace/static/serve.go:25` | `--addr` = `127.0.0.1:7502` |
| 2 | `workspace/log/serve.go:26` | `--addr` = `127.0.0.1:7503` |
| 3 | `workspace/web/server/serve.go:57` | 端口 = `7500` |

| 5 | `workspace/web/app.js:10-12` | 浏览器侧兜底 = 同上三个 |
| 6 | `workspace/ai/src/main.ts:65` | `--addr` = `127.0.0.1:7501` |
| 7 | `workspace/ai/src/main.ts:66-67` | `--log` = `:7503`、`--static` = `:7502` |

`docs/` `atoms/` `edges/` `contracts/` 里没有任何 75xx，schema 不受影响。

### 这些默认值从来没被真正的启动路径用到

launcher 一直显式下发一切：

- `how-to/deploy/dev/launch.sh`：`NO` 默认值依赖，全部显式传
- `how-to/deploy/prod/launch.go:120-129`：`--addr` / `--log` / `--static` / `--agents` 全传

它们唯一的作用，是在**手起单个服务**时把进程接到 7501–7503 上。已经造成过一次真实事故：
`case-core-skill-suggest` 的 Setup 没传 `--log`，ai 就默认写进了**真实项目**的 log 库
（7503），scratch root 的隔离被绕过。

### 谁在吃这些默认值（用例）

| 用例 | 吃哪个默认值 |
|---|---|
| `case-core-ai-flow` / `skill-crud` / `skill-run` / `skill-suggest` | ai 的 `--log`、`--static` |

| 其余约 10 个用例 | 显式传了地址，但用的是 `--addr` / 位置参数旧形状 |

## 方案

### 统一的参数形状

四个服务一律：`--bind <host>` + `--port <n>`（web 取消位置参数，static/log/ai 取消 `--addr`）。

### 各服务的完整参数表（改后）

| 服务 | 参数 | 必填 |
|---|---|---|
| static | `--bind` `--port` `--root` | 全部必填 |
| log | `--bind` `--port` `--root` | 全部必填 |
| web | `--bind` `--port` `--assets` `--static` `--ai` `--log` | 全部必填 |
| ai | `--bind` `--port` `--root` `--log` `--static` `--agents` | 全部必填 |
| ai | `--model` | 选填（无默认值，不传即用 pi 自身配置）|
| ai | `--stub` | 开关（不传=关，不是"默认值"）|

### `web --root` 改名 `--assets`

web 的 `--root` 与另三个**同名不同义**：另三个指"你的工程根"（`atoms/` `edges/` …），
web 指"工具自带的前端资源目录"（`index.html` `app.js` …）。改名划清界限。

其默认值（二进制所在目录）本来也永远不对——二进制在 `.../bin/`、网页在 `.../web/`，
所以 launcher 每次都显式传。改名后一并去掉。

### 缺失必填项的行为

打印用法到 stderr，以非 0 退出码退出，**不监听、不连接任何地址**。

### `app.js` 的兜底删除

`serve-web` 现在必然注入 `/config.js`，浏览器侧的 75xx 兜底是死代码。删掉；若
`window.ENGINEER` 缺失或字段不全，在页面里**明确报错**（而不是静默连 7501-7503）。

## 范围外

- 不改 llm provider 配置、模型选择（`--model` 保持选填）。
- 不改 launcher 自己声明端口默认值（`launch.go:44 defaultPorts`、`launch.sh` 的
  8500-8503）——**挑端口是 launcher 的本职**。
- 不改任何 HTTP 契约（`contracts/` 不动）。
- 不改 `--bind` 的语义（loopback / 指定网卡 / 0.0.0.0 三态不变）。
- 不引入配置文件或环境变量来替代参数。

## 验收

- `grep -rn "75[0-9][0-9]" workspace/` 只剩注释无残留（源码里零 75xx 字面量）。
- 四个服务分别缺任一必填参数 → 退出码非 0、stderr 有用法、**端口未被监听**。
- 四个服务传齐参数 → 正常监听在 `--bind`:`--port` 上。
- `how-to/deploy/dev/launch.sh` 起栈成功，`curl <static>/static/query` 返回 atoms/edges。
- `how-to/deploy/prod/launch.go` 的 `engineer start` 起栈成功。
- `case-core-loopback-bind` §3a 改为必填校验用例后通过。
- `case-core-web-skill-tabs`、`case-core-skill-suggest` 用新参数跑通。
- `case-core-skill-suggest` 跑完后，**真实 `.engineer/engineer.db` 里没有本次测试的
  conversation 记录**（隔离生效）。
- 浏览器侧：`/config.js` 缺失时页面明确报错，不静默回退。
