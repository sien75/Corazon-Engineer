# 芯片组收成一行摘要

## 需求

对话区里 thinking / 工具调用的 chip 现在是「一连排气泡卡」，一段没人打断的 run 有几个
步骤就铺几行，纵向太占地方。改成：

1. **默认只占一行**：这一行报「正在处理的那一步」——thinking 就写 `thinking`，工具调用
   就写工具名（`edit chat.css`、`bash git`），右边是这一步的状态（转圈 / ✓ / !）。
   多个 step 时行尾多一个 `· N`，表示这行后面还有东西。
2. **拆分规则不变**：还是原来那套「连续的 chip 归一行，遇到正文 / 用户消息 / 问题卡就
   另起一行」（`addMessage` 结束当前组）。每个组各有一行摘要。
3. **点这一行才展开**：展开后就是现在这个 120px 卡片阵列，横向 `flex-wrap`。
4. **点卡片照旧在下面展开 detail**：横跨整行，排在组尾（自己那张卡下面）。
5. 收起整组时，组里开着的 detail 一起收掉。

## 现状

- `workspace/web/components/chat.js`：`chip()` 直接 `addChip()` 到 `.ai-chip-row`，
  一个 chip = 一张 120px 卡片；`settle()` 只改卡片自己的状态点。
- `components/chat.css`：`.ai-chip-row` 是横向 `flex-wrap`，`.ai-collapse-body`
  是横跨整行的展开面板（`max-height: 300px; overflow-y: auto; padding: 8px 10px`）。
- 顺带两处老问题：chip 的 detail 面板原来 `appendChild` 到 `rowEl`（**当前**那一行，
  点旧行里的 chip 会插到新行去）；`thinking_end` 事件没人接，thinking 卡片要等到
  `text_start` / `turn_start` 才落定。

## 方案

只改 `workspace/web/components/chat.js` + `components/chat.css`：

1. `rowEl` 换成 `group`：`chipGroup()` 造一个 `.ai-msg.ai-chip-row.ai-chip-group`，
   第一个孩子是摘要行 `.ai-chip-head`（`▸/▾` + 标题 + `· N` + 状态点，整行宽），
   点它 `toggle("open")`。
2. `refreshGroup(g)`：在 `g.chips` 里挑「还在跑的最后一个」，都跑完了就挑最后一个，
   把它的 `summary` 和状态写进摘要行。`settle()` 记 `block.state` 并刷新。
3. `addChip()` 创建组、把新 chip 插在组里的面板之前（面板永远在组尾）。
4. `chip(kind, label, name, summary)`：`summary` 是摘要行上的写法（工具 = `name label`，
   两者相同时只留一个）。
5. 卡片自己的点击：面板改成 `hidden` 切换 + 开到组尾，不再 `bd.remove()`，也不再
   依赖 `rowEl`。
6. `thinking_end` 落定 thinking（摘要里它不再算「正在处理的那一步」）。
7. CSS：`.ai-chip-head` 一行摘要的样式——**不加框、不占满宽**，宽度跟着自己的文字走
   （无 `background`/`border`，hover 才给一层 `--surface-inset`；行高 18px + `padding: 4px`
   = **26px**），展开方向**在点下去的那一下定**：贴底（`atBottom()`）就往上长——继续跟底，
   摘要行在屏幕上原地不动，卡片和 detail 从上面一层层长出来；翻上去了就往下长——不碰滚动条，
   就地展开、把下面的内容推下去。往上长靠 `.ai-chip-group.up { flex-wrap: wrap-reverse }`：
   DOM 里的「摘要 → 卡片 → detail」在屏幕上反着排，摘要行留在最下面、贴着它所属的那条回复
   （`.ai-chip-group.open > .ai-chip-head
   { flex: 0 0 100% }` 让摘要独占一行，但没有背景/边框，展开态连 hover 高亮也去掉，
   所以还是块轻标签）。箭头跟着说方向：收起 `▸`、往上展开 `▴`、往下展开 `▾`；
   状态点跟在文字后面、不被推到行尾
   （`.ai-chip-head .ai-collapse-status { margin-left: 0 }`）；detail 面板的 `max-height` 从 200px 放到 300px；`.ai-chip-group:not(.open) > .ai-collapse,
   .ai-chip-group:not(.open) > .ai-collapse-body { display: none }` 收起来。
8. 贴底判定的容差 `STICK` 从 40px 收到 **5px**（`atBottom()` 同时决定展开方向和「新内容要不要跟底」，
   40px 太松：差一截没到底也算贴底）。

## 验证

`/tmp` 里的假 provider（按 `contracts/ai-stream.yaml` 发 thinking → read → bash → edit →
正文，每一步之间 450ms）+ 真 `serve-web` 资产 + `ego-browser`，实测四态：

| 时刻 | 摘要行 | 卡片 | detail |
| --- | --- | --- | --- |
| 跑到 thinking | `▸ thinking`（转圈） | 隐藏 | — |
| 跑到第 3 步 | `▸ bash git · 3`（转圈） | 隐藏 | — |
| 跑完 | `▸ edit chat.css · 4 ✓` | 隐藏 | — |
| 贴底点摘要行 | `▴ edit chat.css · 4 ✓`（原地不动，实测 409.0 → 408.9px） | 4 张卡片，在摘要行**上方**（371px） | — |
| 翻上去点摘要行 | `▾ edit chat.css · 4 ✓`（原地不动，实测 661.3px） | 4 张卡片，在摘要行**下方**（693px） | — |
| 点第一张卡 | 同上 | 4 张卡片 | 跟着方向：往上长时在卡片**上方**（300px）、往下长时在卡片**下方**（731px），横跨整行，`max-height: 300px` |
| 再点摘要行 | `▸ …` | 隐藏 | 一起收掉 |

## 影响面

- 只影响 `<engineer-chat>`（shell 的 main 与所有 blueprint 页面共用），不碰后端、
  契约、`app.js`。
- 没新增 E2E 用例：`development/testing/dev/` 里还没有覆盖 chip 的用例，本次是
  fixture 级实测；要固化的话按 `write-e2e-case` 补一个。
