# 2610-39 tab 成为会话容器

## 目标

把 `tab` 从"一块可以随便重写的布局"变成**会话的容器**:

1. 一个 session 只属于过一个 tab,之后不可变更(1:1,不可变)。
2. tab 有 `title`、`lastAt` 两个展示字段,`tab bar` 与 launcher 的 recents 都读它们。
3. launcher 的 recents 从"列 session"改成"列 tab",点击直接切到那个 tab,**不允许多开**。
4. main 的 workspace 工具按 `current / tab / layout` 三层重新组织,干掉整树重写的 `tab-mutation`。

## 数据结构

### log.tabs

```yaml
tab_id      TEXT PRIMARY KEY
title       TEXT NOT NULL DEFAULT ''   # 新增:各 pane 的页面 <title> 去重后以 " · " 连接
layout      TEXT NOT NULL              # pane 树,log 不解释结构
created_at  TEXT NOT NULL
updated_at  TEXT NOT NULL              # 布局最后一次写入
last_at     TEXT NOT NULL DEFAULT ''   # 新增:布局写入 或 tab 内 session 有新消息,取 max
```

老库用 `ALTER TABLE` 补两列(与当初加 `sessions.blueprint` 同一做法)。

### log.sessions

```yaml
session_id  TEXT PRIMARY KEY
kind        TEXT NOT NULL DEFAULT 'sub'
blueprint   TEXT NOT NULL DEFAULT ''
tab_id      TEXT NOT NULL DEFAULT ''   # 新增:这个会话属于哪个 tab;写过就不再改
created_at  TEXT NOT NULL
```

绑定的来源不是解析 layout,而是调用方显式传 `sessionIds`(ai 建会话时本来就知道)。

### title 的来源

`.agents/blueprints/<slug>/index.html` 里的 `<title>`,由 ai 侧读文件取(不是浏览器渲染值)。
layout 每次变动(新增 pane / 删除 pane)都重算并整串写回 `tabs.title`。

## 工具(ai,main 专属)

session 层级的工具全部去掉(`session-list` / `session-resume` / `session-delete`):会话只能通过 tab 打开,打开即 resume,tab 删除即连带删会话。

| 工具 | 参数 | 说明 |
|---|---|---|
| `current-tab-list` | `{}` | 当前打开的 tab(按打开顺序),带 `title` / `lastAt` / pane 数 |
| `current-tab-mutation` | `{ ops: [{ op: on\|off, tabIds: [..], index? }] }` | 开关/排序,可一次多个;on 幂等,off 幂等 |
| `tab-new` | `{ blueprint, open?: true }` | 必带 blueprint;sessionId 由服务端生成,不接受传入;建 tab + 首个 pane + title;open 默认 true |
| `tab-delete` | `{ tabId }` | 硬删:tab 记录 + 从打开列表摘除 + 删掉每个 pane 的 session(agent + records) |
| `tab-layout-mutation` | `{ tabId, ops }` | 见下 |

### tab-layout-mutation

```yaml
ops:
  - { op: add, nextTo: <paneId>, side: left|right|top|bottom, blueprint: <slug>, flex?: "2 1 0" }
  - { op: delete, paneId: <paneId> }
```

结构由 `nextTo + side` 推出,不传 layout:

- `side` 与 `nextTo` 父容器同方向(左右 / 左右,上下 / 上下)→ 直接插入父的 children
- 方向交叉(row 里要 bottom)→ 把 `nextTo` 那个 pane 摘出来,和新 pane 一起装进一个新容器,放回原位
- `delete` 后容器只剩一个孩子 → 自动塌陷
- 应用完至少留 1 个 pane,最多 6 个(`MAX_PANES`)
- 整条 ops 先全量校验再应用:任一条不合法整条不生效
- 成功后重拼 `tabs.title`、bump `last_at`

## log 接口(契约改动)

| 端点 | 改动 |
|---|---|
| `/log/tab/new` | 请求改 `{ title, layout, sessionIds? }`,layout 必填(不再有空 tab);成功即绑定 sessionIds 并加入打开列表 |
| `/log/tab/mutation` | 请求加 `title`、`sessionIds?`;写布局的同时 bump `last_at` |
| `/log/tab/on` | 新增,`{ tabIds, index? }`,幂等,tab 不存在则 404 |
| `/log/tab/off` | 请求改 `{ tabIds }`(兼容旧的 `tabId`) |
| `/log/tab/list`、`/log/tab/detail` | 响应加 `title`、`lastAt`;list 按 `last_at` 排序 |
| `/log/session/detail` | 响应加 `tabId` |
| `/log/mutation` | `kind=conversation` 写入时,顺带 bump 该 session 所属 tab 的 `last_at` |

绑定冲突(`sessionIds` 里有已属于别的 tab 的会话)→ `/log/tab/new` 返回 400,message 带上那个 tabId。

## web

- tab bar 标签 = 记录的 `title`(重载后同步可画,不再先闪 `…`);空则退回老的 `fetchTabName`
- launcher recents = `/log/tab/list`,行标题 `title`,副标题 `${pane 数} panes · ${lastAt}`
- 点击 recents 行:tab 已在打开列表里就直接激活,否则 `tab/on` 后再激活 —— 不新建记录

## 不做

- `asChild` / 给 split 节点加 `nodeId`(这版锚点只能是 pane)
- 软删除(`is_delete`)
- 历史 tab 数据清理
- 页面用 JS 动态改 title 的情况(store 里存的是文件里的静态 `<title>`)

## 验收

- `current-tab-list` 能看到打开的 tab 及其 title
- `tab-new` 建的 tab 有 title,重载后 tab bar 立刻显示
- `tab-layout-mutation` 的 add/delete 生成的树与预期一致(含交叉方向造容器、塌陷)
- 同一 session 不能被两个 tab 持有(无论是 tab-new 还是 tab-layout-mutation 都被拒)
- recents 列 tab、点击切换而不是新开
- 会话有新消息后,其所属 tab 的 `lastAt` 前移
