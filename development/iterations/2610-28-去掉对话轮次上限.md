# 去掉对话轮次上限

## 需求

去掉 ai 对话里那个「100 轮」的硬上限：一次 `/ai/ask` 的 run 里，模型想调多少轮工具就调多少轮，
只在模型自己不再调工具（或用户中止 / 出错）时才结束。

**不做保护性替代**：不加 `--max-turns`、不留兜底阈值——真陷入循环时靠用户手动停止。

## 现状

- 上限：`workspace/ai/src/registry.ts:259-261`

  ```ts
  // pi's agent loop has no built-in round cap; stop a runaway turn loop
  // gracefully after this many turns.
  const MAX_TURNS = 100;
  ```

- 生效点：`workspace/ai/src/registry.ts:473`

  ```ts
  session.agent.shouldStopAfterTurn = () => ++sess.turns >= MAX_TURNS;
  ```

- 计数载体：`Sess.turns`（`registry.ts:253`，注释 `turns elapsed in the in-flight prompt (loop cap)`），
  在 `runTurn()` 开头归零（`registry.ts:687`）。**按每次 `/ai/ask` 计**，不是会话累计。
- pi 的语义（`node_modules/@earendil-works/pi-agent-core/dist/types.d.ts:180-192`）：
  `shouldStopAfterTurn` 返回 `true` 时，当前这一轮正常做完，发 `agent_end` 后退出，不再发起下一次 LLM 调用。
  即**无声截断**：前端不显示任何「已到上限」的提示，表现就是答案说到一半停住。
- 它是纯本地实现细节：`docs/ai.md` 没有提，`contracts/` 里没有，`development/testing/dev/` 下
  21 个用例没有一个覆盖它（`/ai/*` 的请求 / 响应形状与它无关）。

## 决策

**按 A 方案整段删掉**，不在代码里留任何轮次上限：

1. 删 `MAX_TURNS` 常量与它上面那段注释。
2. 删 `session.agent.shouldStopAfterTurn = ...` 那一行——不设该回调，pi 的 loop 就没有轮次上限，
   完全按「模型不再调工具就结束」走。
3. 删 `Sess.turns` 字段（含 `interface Sess` 里的声明、`resume()` 里的 `turns: 0` 初始化、
   `runTurn()` 里的 `sess.turns = 0`）——没有消费者了，留着是死代码。

被否决的替代：

- **B（`--max-turns`，默认不限）**：默认行为跟 A 一样，却多一个参数、一条要文档化的路径。
- **C（抬到 1000）**：只是把「无声截断」推远，长任务照样可能撞上，且撞上时依然无声——没解决问题。

## 影响面

- `workspace/ai/src/registry.ts`：四处删改（常量、赋值、字段声明、两处初始化）。
- **契约不动**：`/ai/ask`、`/ai/new`、`/ai/resume` 的入参 / 出参 / 事件流都不变——上限既不是入参也不是出参，
  它只决定 run 什么时候结束。
- **静态关系不动**：没有端点增删，`atoms/`、`edges/`、`contracts/` 全不动。
- **文档不动**：`docs/ai.md` 从未写过这个上限。
- **用例不动**：没有 casing 覆盖它，也不需要新增——要真验证得让模型主动循环 100+ 轮，
  既不稳定也不该进 E2E；用「代码里搜不到 `MAX_TURNS` / `shouldStopAfterTurn`」+ 一次真跑对话来验。
