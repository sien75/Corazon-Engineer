# 中途挂载的页面要接管在跑的那一轮

## 需求

页面在一次运行**中途**才挂载（刷新、重开标签、换一个 iframe）时，应当接着这一轮走：
stop 按钮在、后续事件继续画出来。用户实测到的现象是「你在跑着，但是我这里不显示 stop 按钮了，
也没有问题显示」—— 页面看起来是死的，直到用户再发一条消息。

## 现状（代码 + 契约）

`workspace/web/components/chat.js` 里，进入「正在跑」只有一条路，全都在 `ask()` 里：

```
613:      setRunning(true);     // 唯一的进入点
628:    if (!steer) void pump(); // 唯一的开流点
```

挂载路径只做了两件事：

```
1088:      await streamOnce(() => {});   // 只挪水位：事件拿到手就丢
1099:  if (!…no-history…) void replayHistory();  // 画历史
```

于是挂载时 `running === false`：不显示 stop、不开流、也不会有新内容。只有用户自己发一条
消息，才会走到 `ask()` 里把这一轮"开"起来（而那次发送还会被服务端当作对在跑那一轮的插话）。

契约其实早就写明了该怎么做 —— 是前端没实现：

```yaml
# contracts/ai-resume.yaml
lastSeq: number  # last pi event seq already emitted for this session; 0 when freshly rebuilt
active: boolean  # whether a run is in flight; a resuming client should reattach to /ai/stream when true
```

而 `replayHistory()` 里那句 `await fetch(AI + "/ai/resume", …)` **把响应直接丢了**。

顺带记下同一处的第二个毛病：`replayHistory` 的 resume 与 log 读取在同一个 `try` 里，
ai 不在时连历史都不画（用例里用 ai 存根绕过了，这次不动它）。

## 根因

挂载路径不知道"这一轮还在跑"，也没有从 resume 给的水位接流。

## 方案（`chat.js`，一处）

把挂载做成三步，顺序有意义：

1. `resumeState()`：一次 `/ai/resume`，拿 `lastSeq`（水位）与 `active`（在不在跑）；
   失败返回 `null`，全部退回原行为。
2. 画历史（`replayHistory()` 只读 log，不再混着 resume）——ai 不在也该看到记录。
3. 水位：有 `lastSeq` 就用它，不再靠「空订阅读水位」那趟；没有（resume 404 / 失败）
   才退回 `streamOnce(() => {})`。
4. `active` 时 `setRunning(true)` + `void pump()`：stop 亮起来，流从 `lastSeq` 续上。

另外给 `pump()` 加一个兜底：某一趟流**一个事件都没拿到**就返回时，用 `resumeState()`
复查一次 `active`，不活跃就 `finish()`。否则服务端重启之类的情况下，接管会变成一个
空转的循环（每 300ms 开一次流）。今天没有这条路径（挂载不开流），加了接管才有。

`ask()` 本来就 `await ready`，所以第一次发送仍会等 resume 完成，行为不变。

### 取舍（写下来，免得以后当成 bug）

从 `lastSeq` 续流意味着：**挂载之前已经发出的那条消息，前缀不重画**（它还没落进 log）。
为什么不从 0 重放？因为这一轮里已经完成的消息**已经**在 log 里被 `replayHistory` 画过一次了，
从 0 重放会把它们画第二遍。等这条消息落定，再刷新就能看到全文。

## 不改

`contracts/`（`ai-resume` 的 `active` / `lastSeq` 就是这次要用的，无需新增）、
`atoms/`、`edges/` —— web 的接口没变，这是组件内部行为。

## 验收

新增 `development/testing/dev/case-core-web-reattach-run`（端口 9072 起一个脚本化的 ai，
`/components/` 直接服务 `workspace/web`）：`/ai/resume` 返回 `{lastSeq: 3, active: true}`，
`/ai/stream` 从 `since` 之后补几条事件再 `agent_settled`。断言：

1. 页面**没被点过任何东西**，stop 按钮就是可见的；
2. 流请求的 `since` 是 3（从水位续，没有重放整轮）；
3. 那一轮的事件画了出来（助手气泡有字）；
4. `agent_settled` 之后 stop 消失。

再加两条回归：`case-core-web-chat-composer`（composer / 插话 / stop 的老路径）与
`case-core-web-chat-scroll`。

## 遗留

- 中途挂载时正在生成的那条消息只显示后半截（见上面的取舍）。
- `replayHistory` 依赖 resume 成功才读 log 的老问题，这次没动。
