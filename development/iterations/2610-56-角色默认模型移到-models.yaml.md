# 角色默认模型移到 models.yaml（不再用 pi 的模型选择）

## 需求

- 模型选择不再走 pi 的 `~/.pi/agent/settings.json`（`defaultProvider` / `defaultModel`）。
  在 Engineer 的数据 home（`.engineer`）里单开一份配置，记录 **main** 和 **sub** 两个角色的模型。
- 每条记录就是 `provider/model-id`（斜杠形式，不拆成两个字段；按第一个 `/` 切）。
- 每个角色有两个 slot：**chat**（对话）和 **image**（生图；现在的会话模型本身已经能看图）。
- 创建时传入的 `chat` / `image` 都是可选的；不传就降级到对应角色对应 slot 的默认。
  `model` 保留为 `chat` 的旧别名。
- 目前的取值：`chat` = `deepseek/deepseek-flash`；`image` 留空（工程里还没有生图能力）。
- 优先级（每个 slot 各自一条链）：
  - chat：**会话内切换（记录）> 创建时传入 > models.yaml 的 chat > pi 目录里第一个可用模型**；
  - image：**会话内切换（记录）> 创建时传入 > models.yaml 的 image > 空（未配置）**。

范围外：pi 的 settings 永不改写；生图工具本身；`compress` 模型（pi 的压缩继续用会话模型，
不单独配）；前端模型选择控件；thinking 档位。

## 现状（实测）

- `workspace/ai/src/registry.ts` 的 `build()` 按「最后一条 `model` 记录 → 创建时的 model →
  不传」解析；不传时 `createAgentSession` 的 model 为空，交给 pi。
- 不传 model 时 pi 的解析链（`pi-coding-agent/dist/core/model-resolver.js:502`）是：
  settings 的 `defaultProvider/defaultModel`（有凭据就用）→ 已知 provider 的默认型号 →
  第一个可用模型。也就是说"完全不管"仍会回到 pi 的模型选择。
- `--home` 已经是本服务的数据目录（dev 是 `<checkout>/.engineer/home`，prod 是
  `~/.engineer/data`），和 `engineer.db` 同级；ai 启动时已有这个值，不需要新参数。
- 生图模型是 pi 的另一套目录：`pi-ai` 的 `ImagesModels` / `generateImages`，
  内置 provider 只有 `openrouter`（`pi-ai/dist/providers/openrouter-images.js`），
  模型 id 自带斜杠（如 `black-forest-labs/flux.2-flex`），凭据不在 pi 的 `auth.json` 里。
  本服务目前没有任何生图消费者。
- 会话行 `model` 只在创建时带了显式 model 或 `model` 工具切换后才有值；空串表示"没有显式选择"
  （`workspace/log/internal/store/workspace.go:37` 的注释、`contracts/log-list.yaml:18`）。

## 方案

### 1. 配置文件

`<home>/models.yaml`：

```yaml
# chat:  对话模型，pi 的会话模型目录；main 和 sub 各一条
# image: 生图模型，pi 的图片模型目录（内置只有 openrouter）；
#        形如 openrouter/black-forest-labs/flux.2-flex，空串 = 还没配
main:
  chat: deepseek/deepseek-flash
  image: ""

sub:
  chat: deepseek/deepseek-flash
  image: ""
```

- 新文件 `workspace/ai/src/models-config.ts`：`ensureModelsConfig(home)` 在 ai 启动时
  （`Registry.init()`）调用——文件不存在就写出上面这份（带注释），目录不存在先建。
  写失败只打警告，不挡启动。
- 每次 `build()`（新建或恢复）重新读文件，所以改完配置对新会话和下一次恢复生效；
  运行中的活会话不监听。
- 读的时候逐项校验：
  - `main` / `sub` 缺一个 → 整块用内置默认；
  - `chat` / `image` 缺一项 → 该项用内置默认；
  - ref 形状不对（没有 `/`、provider 或 model 为空）→ 该项用内置默认；
  - 以上都打一行警告（`console.error`），继续说下去，不抛。
  - YAML 解析失败 → 整份用内置默认 + 警告。
- 内置默认：`chat = deepseek/deepseek-flash`，`image = ""`。
- `image` 只做形状校验，不做可用性校验（没有消费者）。

### 2. 解析（`registry.ts` 的 `build()`）

候选链按优先级排：

1. 历史里最后一条 `role === "model"` 记录的 `raw.model`；
2. 创建时传入 / 会话行上的 `model`；
3. `models.yaml` 里 `kind` 对应角色的 `chat`。

从前往后，第一个能在 pi 的可用列表里解析到的就用它；跳过的每一个打一行警告。
三个都不可用（或配置为空）时：

- 从 `this.available` 里挑一个：**优先与第 3 项同 provider 的模型**，否则取第一个；
- 打一行警告（`configured ... is not usable now; using ...`），并把它**显式**传给
  `createAgentSession`。

这样 `createAgentSession` 永远拿到一个非空 model，pi 的 `findInitialModel` 走不到
settings 那一步（`sdk.js` 里 `options.model` 有值就跳过）。`thinkingLevel` 仍只在
"最后一条 `model` 记录真的被采用"时跟随恢复，避免给另一个模型套错档位。

image 单独解析，不碰 pi 的 chat 目录：

1. 历史里最后一条带 `slot: image` 的 `model` 记录；
2. 创建时传入 / 会话行上的 `imageModel`；
3. `models.yaml` 里该角色的 `image`（可以为空）。

结果存到 `Sess.imageModel`，不参与 `createAgentSession`，也不做可用性校验——生图工具以后读它。

`server.ts` 对 `ai/new` 的未知 model 仍返回 `400`，不变。

### 3. 记录与展示

- 会话行不写解析后的默认值：空 `model` 继续表示"没有显式选择"，所以改 `models.yaml`
  对"从没显式选过模型"的老会话（下一次恢复）也生效。
- `session-list`（`workspace.ts`）里 `rec.model || "pi default"` 改成显示该角色在
  `models.yaml` 里的 `chat`；`WorkspaceDeps` 增加一个 `defaultModel(kind)` 回调。
- `model` 工具按 `slot` 工作：`slot: chat`（默认）走 `agent.setModel` 并写会话行 `model`；
  `slot: image` 没有活的 image runtime，只写记录 + 会话行 `imageModel`。工具的 `list` / `set`
  都接受 `slot`，描述从"覆盖 pi 的配置默认"改成"覆盖 models.yaml 的默认"。

### 4. `model` 记录的格式（chat / image 两个 slot）

```yaml
role: model
slot: chat | image      # 老记录没有这个字段 = chat
model: provider/model-id
thinkingLevel: high     # 仅 chat
```

- 读某个 slot 的当前值 = 最新一条**同 slot** 的 `model` 记录；chat 读不到就跳过 image 记录，
  反之亦然。
- 生图切换也插同一条记录流（`slot: image`），只是没有 `thinkingLevel`。
- 回放不变：`role: "model"` 一律 `toAgentMessage()` 返回 `undefined`，pi 看不到 `slot`。

## 静态关系

`atoms/ai.yaml` 的 description 里两处要改：

## 风险

- 配置写错/模型下线 → 会话仍能建，但会跑在"第一个可用"上；警告只在 ai 日志里，界面上看不出来。
  可接受：这是本地工具，日志可查，且比整条链路起不来好。
- 每次 build 读一次小文件 + YAML 解析，开销可忽略。
- `models.yaml` 在 `.engineer` 下（git-ignored），不进仓库；换机器/重装要自己带过去。
- 生图配置目前没有消费者，但 `image` 的默认、创建值和每会话切换都已经落库（会话行 +
  记录），生图工具接上后直接读，不需要再改格式。

## 实施记录

按方案落地，实测要点：

- 新文件 `workspace/ai/src/models-config.ts`：`ensureModelsConfig(home)` 在 `Registry.init()`
  里调用（`--stub` 也调用，配置面与是否接模型无关）；`readModelsConfig(home)` 每次 `build()`
  重读。缺文件 → 写出带注释的默认；缺角色 / 缺项 / 坏形状 / 坏 YAML → 该项或整份回默认
  + 一行 `warning:`。
- `registry.ts`：候选链 `记录的 model → 创建时 model → models.yaml[kind].chat`，逐个用
  `modelFor` 解析；都不可用时按 `roleDefault` 的 provider 优先，否则 `available[0]`，**显式**
  交给 `createAgentSession`。`thinkingLevel` 只在记录的 model 真被采用时跟随，避免套错档位。
- `workspace.ts`：`session-list` 的模型列从 `pi default` 改为该角色的 `chat` 默认
  （`WorkspaceDeps.defaultModel(kind)`）。
- 会话行加 `imageModel`（log 的 `sessions.image_model`，`ALTER TABLE` 迁移）；
  `ai/new` 收 `chat` / `image`（`model` 为 chat 的别名），`session-new` 同步。
- `main.ts` 启动日志加一行 `models=<home>/models.yaml`，配置在哪一眼可见。
- `model` 工具：`list` / `set` 加 `slot`；chat 仍是 `agent.setModel` + `slot: chat` 记录 +
  会话行；image 只写 `slot: image` 记录 + 会话行 `imageModel`，并更新 `Sess.imageModel`。
- `persistModel` 按 slot 写记录与对应行字段；`lastModelChoice(records, slot)` 只认同 slot
  的记录（老记录无 slot = chat）。
- 契约（`ai-new`、`log-session-kind`、`log-session-upsert`、`log-list`）、`atoms/ai.yaml`、
  `atoms/log.yaml`、两份 `AGENTS.md`（中英）、`docs/ai.md`、`how-to/deploy/dev/BOOK.md`
  的模型描述同步改掉。

### 一个实现上的观察

`available[0]` 不是稳定的：pi 的远程目录刷新后，可用模型列表会变（本机从只有两个 deepseek
模型变成还带 zenmux 的若干模型）。所以兜底只保证「一个 pi 现在能用的模型」，不保证是哪一个；
配置里写清楚 `chat` 才是稳定行为。
