# 生图工具与图片展示

> 图片链路的「发图」早就通了：粘贴 → 压缩 → `/ai/ask` 的 base64 → 落 blob → log 里只存 sha256 → `/blobs/<sha256> (the ai service)` 回读。断在两头之外：**没有任何东西消费 image slot**，`assistant` 侧也画不出一张图。

## 需求

1. main 和 sub 都多一个生图工具，用**这一轮对话自己的生图模型**（三层配置里的 image 那一层）。
2. 生成的图**在对话里显示出来**，刷新/重开还在。
3. 协议只做一份：OpenAI 兼容的 `/images/generations`，provider 不是代码分支，只在查 baseUrl 和 key 时用。
4. 上下文里**不塞像素**：模型拿到的是文字，图走 `details` 交给页面。

## 现状(改之前)

- `models.yaml` 有 `main.image` / `sub.image`，`ai-new` 和 `model` 工具的 `slot=image` 都能写进会话行，`build()` 已经把两层解析成 `sess.imageModel`。**没有消费者**。
- `chat.js` 只画 `type:"text"`；`assistant` 的 raw 里就算有 image 块也不画，重放分支同样只取文本。工具结果只有 `pre` 文本。
- `pi-agent-core` 的 `AgentToolResult` 支持 image content，`pi-ai` 甚至有 `createImagesModels` / `generateImages`（内置 provider 只有 openrouter）。两者都不用，理由见决策。

## 决策

### 1. 一个适配器，不按 provider 分叉

`POST {baseUrl}/images/generations`，body `{model, prompt, n, size}`，响应 `{data:[{b64_json}|{url}]}`。baseUrl 和 key 都来自 pi 自己的配置（`ModelRuntime.getRegisteredProviderConfig` / `getAuth`），所以 `provider/model-id` 里的 provider 只用来查这两样。

`/images/generations` 不在时（404/405，chat 型网关的常态）退到第二种形状：`POST {baseUrl}/chat/completions` + `modalities:["image","text"]`，从 `choices[0].message.images[].image_url.url` 取 data URL 或链接。400 不退——那是对这次请求的答复，换形状重发只会再来一次。

**不发 `response_format`**：gpt-image 系列不认这个参数（直接报错），dall-e 系列默认回 url。两种响应都处理，省掉一张按 provider 的分支表。

真正会分叉的是**能力**，按模型记：尺寸档位、`n` 上限。未知模型用默认（`1024x1024`、n≤4），失败原因原样回给模型。

### 2. 模型看到的是文字，不是像素

`content` 只有一行文本（尺寸、mime、sha256、说明可 `read` 那个文件）。图放 `details.images`。

- toolResult 里塞 image 块：pi 支持，但 OpenAI 的 tool message 只收文本，回放会掉；而且每一轮都要重新付一次像素的 token。
- 需要「看见」时模型自己有办法：blob 就在 `home/.engineer/uploads/<sha256>.png`，`read` 能识图，按需付费。

### 3. 图和粘贴的图是同一种东西

沿用 `saveImage`：同一份内容寻址存储、同一个 sha256 命名、同一个 `/blobs/<sha256> (the ai service)` 路由。所以 log 契约一个字都不用改，前端也只有一套 `<img>` 逻辑。

`details` 的形状（log 里的 toolResult raw，原样存、原样重放）：

```yaml
role: toolResult
content: ""
raw:
  role: toolResult
  toolCallId: call_abc123
  toolName: image
  content: [ { type: text, text: "generated 1024x1024 (image/png)" } ]
  details:
    images: [ { type: image, sha256: <64hex>, mimeType: image/png, width: 1024, height: 1024 } ]
    prompt: "…"
    model: zenmux-openai/openai/gpt-image-2
  isError: false
```

`externalizeImages` 只看 `content`，`details` 里已经是 sha 引用，所以记录侧不用动。

### 4. 展示：图单独占一块，不进芯片

芯片默认是收起的，而图就是给人看的那一下 —— 塞进去等于没画。所以生图结果单独占一块（`ai-msg ai-images`，和正文同列），芯片只留调用参数。不做 overlay、不做缩放——先用 `<img>`，`loading="lazy"`、`max-width:100%`、宽高先按 details 占位，和 `.ai-user-img` 同一套观感。

- 实时：`tool_execution_end` 的 `ev.result.details.images`。
- 重放：`replayHistory` 里那条 toolResult 的 `raw.details.images`。
- 两处都走同一个 `imageBlock(details)`。
