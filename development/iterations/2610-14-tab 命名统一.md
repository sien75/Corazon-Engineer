# tab 命名统一

## 需求

承载会话页面的东西**就叫 tab**，不再叫 “skill tab”。概念分层是：

- **skill 是 skill**——它是一段文本、一项能力，与 tab 不是一个层级的东西。
- 用某个 skill 可以**生成一个 chat instance**（ai 服务建会话、把 skill 文本
  作为第一条消息交给模型）。
- **一个 tab 页承载一个 chat instance**，仅此而已。

现状代码把这两层混在一起：承载会话的 tab 处处带 `skill` 前缀
（`skillTabs` / `openSkillTab` / `.tab.skill` / `TABS_KEY =
"engineer.skill.tabs"`），读起来像 “tab 是 skill 的一种”。

## 现状

`workspace/web/app.js`（`skill tabs` 段落，约 1620-1860）与
`workspace/web/style.css`：

| 现在 | 位置 |
| --- | --- |
| `skillTabs` / `loadSkillTabs` / `saveSkillTabs` / `renderSkillTabs` | `app.js` 1633 / 1708 / 1728 / 1734 |
| `openSkillTab` / `activateSkillTab` / `closeSkillTab` | `app.js` 1789 / 1807 / 1846 |
| `activeSkillId` | `app.js` 1634 等 |
| `.tab.skill` / `data-skill-tab` | `app.js` 1739 / 1740 / 1735 / 1764；`style.css` 152 / 157 |
| `skillMode` / `.skill-mode` | `app.js` 1775-1782；`style.css` 461 |
| `TABS_KEY = "engineer.skill.tabs"` | `app.js` 1627 |
| `openSkillTab` 默认 label `"skill"` | `app.js` 1796 |
| 注释里的 “skill tab / skill mode” | `app.js` 501 / 553-554 / 608 / 1772-1773 / 2152 |

`skillId`、`/ai/skill/*`、`newTabSkills`、`skill-item`、`skill-confirm*` 等
**是 skill 本身**，与本次改动无关。`renderedTabId` 本来就叫 tab，不动。

用例 `development/testing/dev/case-core-web-skill-tabs/` 的选择器直接吃这些
名字（`#tabs .tab.skill`、`[data-skill-tab]`、`#ai.skill-mode`、
`engineer.skill.tabs`），`case-core-web-chat-route` 也用了
`.tab.skill` / `.skill-mode`。

## 方案

### 命名映射（代码）

| 现在 | 改成 |
| --- | --- |
| `skillTabs` | `openTabs` |
| `loadSkillTabs` / `saveSkillTabs` / `renderSkillTabs` | `loadTabs` / `saveTabs` / `renderTabs` |
| `openSkillTab` / `activateSkillTab` / `closeSkillTab` | `openTab` / `activateTab` / `closeTab` |
| `activeSkillId` | `activeTabId` |
| `TABS_KEY` 的值 `engineer.skill.tabs` | `engineer.tabs` |
| `.tab.skill` | 不加限定类：动态 tab 就是 `class="tab"`，认 `data-tab-id` |
| `data-skill-tab` | `data-tab-id` |
| `skillMode` / `.skill-mode` | `tabMode` / `.tab-mode` |
| `openSkillTab` 默认 label `"skill"` | `"chat"` |

**动态 tab 不再有第二个身份词。** DOM 上：固定视图 `class="tab fixed"`，
承载会话的 `class="tab"` + `data-tab-id="<tab id>"`。JS 选择器
`#tabs .tab[data-tab-id]`，CSS 那两条（`max-width: 180px` / label 省略号）
改用 `#tabs .tab[data-tab-id]`；固定 tab 有 `fixed` 本来就区分得开。

### 注释与段落

`app.js:1620` 段注释按新模型重写：skill 是一段文本；用它开一个 tab 就是让 ai
建一个 chat instance 并把文本作为第一条消息；固定视图不是这种 tab，它们是
shell，不能关。其余注释里的 “skill tab” 改为 “tab”；真正在说 skill 的地方
（skill 文本、`/ai/skill/run`、扫描）保留 skill 说法。

### 测试

- 目录与 id：`case-core-web-skill-tabs` → `case-core-web-tabs`，
  `desp.yaml` 的 `id: core-web-skill-tabs` → `core-web-tabs`。
- 选择器跟随：`.tab.skill` → `.tab[data-tab-id]`，`.skill-mode` →
  `.tab-mode`，`engineer.skill.tabs` → `engineer.tabs`。
- `case-core-web-chat-route`、`case-core-web-input-grow` 里的同类表述与选择器。
- 断言文案里的 “skill tab” → “tab”；`/tmp/skill-tabs-*.log`、截图路径一并对齐。

### localStorage

key 直接改名，**不做迁移**：tab 列表是界面状态，丢了就从 `/new` 重新打开，
不值得为它留一段读旧 key 的兼容代码。

### 静态关系

不动。`atoms/web.yaml` / `edges/web-to-ai.yaml` 描述的是 web 消费哪些 ai
接口，本次只改内部命名，接口与依赖都不变。

## 范围外

- 不改任何行为：路由（`/chat/<sessionId>`、`/new`）、草稿隔离、`/new` 重建
  实例、recent 过滤、固定视图，逻辑一行不变。
- 不动 skill 相关命名与概念（`skillId`、`/ai/skill/*`、新建页文案）。
- 不重写历史迭代记录（`development/iterations/2610-*` 里的旧说法保持原样）。
- 不动 `dist/` 下的打包产物（走重新打包）。

## 验收

- `workspace/web/app.js`、`style.css` 中不再出现 `skillTab` / `skill-tab` /
  `data-skill-tab` / `tab.skill` / `skillMode` / `skill-mode` /
  `engineer.skill.tabs`。
- DOM：固定视图 `#tabs .tab.fixed` 无关闭按钮；承载会话的 tab 是
  `#tabs .tab[data-tab-id]`，带 ×。
- 回归用例实跑通过：`core-web-tabs`、`core-web-chat-route`、
  `core-web-input-grow`（dev 环境，`how-to/deploy/dev/BOOK.md`）。
- `workspace/static` 校验通过（`/static/validate`）——静态关系未改，作为回归。
