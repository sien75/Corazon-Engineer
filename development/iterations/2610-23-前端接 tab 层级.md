# 前端接 tab 层级（pane 拆分 · i2）

> 接 i1（`2610-22-tab 层级与布局存储.md`）。目标：前端搬到 tab 层级，但**行为与现在等价** —— 这一步的风险隔离意义大于功能意义，拆窗留给 i3。

## 需求

- 前端每个 tab 有 `tabId`（后端生成）和一条 tab 记录（布局）。
- recents（新标签页）列的是 **tab**，不是 session。
- page tab 也建记录（不再是"纯前端"）。
- i2 **只渲染主 pane**：布局里的树还不拆，行为与现在一模一样。

## 现状

- `openTabs` 存 localStorage，`tab_xxx` 是前端随机串；没有 tabId 概念。
- chat tab 建在 `openTab()`，page tab 建在 `openPageTab()`（纯前端，一个服务都不调）。
- 新标签页的 recent 段（`recentSessions()`）调 `/log/list` 列 session。
- `/resume` 命令也调 `/log/list`（对话内恢复会话）。

## 决策

1. **tab 对象加 `tabId`**；`layout` 存在记录里，i2 渲染只用 `primaryPane(layout)`。

2. **建 tab 时写记录**，入口收在 `ensureTabRecord(tab)` —— 在 `activateTab()` 里调用，这样新建 / 深链 / 刷新恢复 / 旧 tab 补建**全部覆盖**，只有一处代码。`tab.tabId` 非空时是空操作。

3. **旧数据**：localStorage 里的旧 tab 没有 tabId，首次激活时补建并把 tabId 写回 localStorage。不再被任何 tab 引用的旧 session 从 recents 消失 —— 它们仍能通过 `/resume` 找到（见决策 5）。

4. **recents 列 tab**：新标签页 recent 段改用 `/log/tab/list`；点击 → `/log/tab/detail` → 按主 pane 建 / 激活 tab。

5. **`/resume` 命令不动**：它恢复的是"一个会话进当前 tab"，不是"打开一个工作区"。两条列表语义不同，各管各的。

6. **关 tab 不删记录**：recents 的意义就是"找回**关掉的**那个"。删除 tab 记录留作后续项。

7. **改 session 时同步记录**：`rebindActiveTab()`（/resume 换绑）和 `aiCommandNew()`（/new 换会话）都要把记录里的主 pane 换成新 sessionId；`/new` 沿用**同一个 tabId**（同一个 tab 换实例，不是新 tab）。

8. **`primaryPane(layout)`** 提成独立 helper：取树里第一个 pane 叶子。i2 用它渲染，i3 拆窗后仍用它做兜底（读到非法树时退化成单 pane）。

## 方案

### `workspace/web/app.js`

新增（放在 ai panel 段之后、tabs 段之前）：

- `tabPut(tabId, layout)` → `/log/tab/mutation`
- `tabDetail(tabId)` → `/log/tab/detail`
- `tabList()` → `/log/tab/list`（一页，100）
- `primaryPane(layout)`
- `ensureTabRecord(tab)`：写记录 + 写回 `tab.tabId` + `saveTabs()` + `renderTabs()`

改动：

- `loadTabs()`：保留 `tabId` 字段
- `activateTab()`：开头的 `applyLayout()` 之后调 `await ensureTabRecord(tab)`
- `rebindActiveTab()` / `aiCommandNew()`：改完 session 后 `tabPut(tabId, {pane:{content:"chat",id:<新 sessionId>}})`
- `openPageTab()`：不变（记录由 `ensureTabRecord` 建）
- `recentSessions()` → `recentTabs()`，走 `/log/tab/list`；过滤掉已打开的 `tabId`
- `newTabSessionHtml()` → `newTabTabHtml()`，`data-action="opentab"`，`data-id=<tabId>`
- `newTabResume(sessionId)` → `newTabOpenTab(tabId)`：`tabDetail` → `primaryPane` → chat 走 `openTab`，page 走 `openPageTab`
- `newTabSessions`（session id → 标签）→ `newTabRecords`（tabId → 显示名）

显示名从哪来：tab 记录里只有布局，没有标题。i2 用主 pane 的 id（sessionId 或 blueprint slug）兜底；chat 的更好标题需要 session 的 preview —— 但那是 `/log/list` 的事，i2 先用 sessionId 短串，**记为已知的粗糙点**。

### 静态关系

- `atoms/web.yaml` 的 `consumes` 加三条（`log-tab-mutation` / `log-tab-detail` / `log-tab-list`），照现有 `log-list` 那条的写法。
- `edges/web-to-log.yaml` 加三条边。

## 测试

`development/testing/dev/case-core-web-tab-records/`（`desp.yaml` + `TEST.md`），浏览器跑（ego-browser），起自己的 log / static / ai(stub) / web：

1. 新建 blank chat → localStorage 的 tab 有 `tabId`，且 log 里有一条记录，布局是单 chat pane、id = sessionId
2. 刷新页面 → 同一个 `tabId`，记录没有翻倍（补建只发生一次）
3. 新建 page tab → 记录是单 page pane、id = blueprint slug
4. 新标签页的 recent 段列的是 tab（关掉一个 tab 后它出现在 recents 里）
5. 点 recents 里的一条 → 开回同一个 tabId 的 tab
6. `/resume` 仍能列 session 并换绑（回归）

## 实施记录（Phase 3）

### 改了什么

`workspace/web/app.js`：

- 新 helper 段（`// ---------- tab records ----------`）：`primaryPane` / `tabPut` / `tabDetail` / `tabList` / `tabLayoutOf` / `ensureTabRecord`。
- `loadTabs()` 保留 `tabId`；`activateTab()` 开头 `await ensureTabRecord(tab)`（所有入口一处收口）。
- `openTab()` / `openPageTab()` 各多一个 `recordId`（从已有 tab 记录打开时不重复建）。
- `rebindActiveTab()`（/resume 换绑）/ `aiCommandNew()`（/new 换会话）同步改记录；`/new` 沿用同一 tabId。
- `recentSessions()` → `recentTabs()` + `sessionPreviews()`；`newTabSessionHtml()` → `newTabTabHtml()`；`newTabResume()` → `newTabOpenTab()`；点击动作 `resume` → `opentab`。
- `atoms/web.yaml` +3 consumes；`edges/web-to-log.yaml` +3 边。

### 与设计稿不同的一处（已补进代码）

设计稿把“记录里只有布局、没有标题”记为粗糙点、先用 id 兜底。实装时发现 launcher 的 recent 会变成一串 `s_1a2b…`，不可读。改成：`recentTabs()` 并发拉 `/log/tab/list` 与 `/log/list`，chat pane 用会话 preview 当行名（页面 pane 用 blueprint 名）。两个请求 `Promise.all` 并发，所以只多一次往返的延迟。

### 测试

- `case-core-web-tab-records`（新，16 项）**全过**：server 分配 tabId、刷新不重建记录、page tab 也建记录、recent 列的是 `opentab` 行、开着的 tab 不在 recent、重开同一条不新建记录、`/resume` 仍列 session。
- `case-core-web-tabs`（既有，41 项）全过，但**需要先修用例**——见下。

### ⚠️ 发现：三个既有 web 用例在本机是坏的（与 i2 无关）

用 A/B 验证过：**把 `workspace/web/app.js` 换成改动前的版本，失败完全一样。**

| 用例 | 基线状态 |
|---|---|
| `case-core-web-page` | 第 6 步 iframe 主题等待超时（15s）—— 基线同样 |
| `case-core-web-chat-route` | 末尾 `waitForFunction` 超时（30s）—— 基线同样 |
| `case-core-web-tabs` | 第 3 步“back 回到 launcher”失败 —— 基线同样 |

`case-core-web-tabs` 那两项是**用例自己的假设错**，不是实现错：

1. 点 back 后只等 URL 变、不等 DOM 渲染完，就去断言“4 个 section”——竞态；而且紧接着又多点了一次 `.newtab-back`（那一刻还在 skills 页才会存在，靠竞态“侥幸”生效）。已改成等到 4 个 section，并删掉多余的第二次点击。
2. 第 9 步跑技能开的是**空会话**（技能文本只在输入框里、没发出去），reload 后当然没有消息；用例却断言有气泡。已在 reload 前先发送。
3. 第 4b 步断言“recent 里 0 条”——那是 session 语义下的期望；tab 语义下，第 3 步关掉的那个空白 tab 本来就应该出现在 recent 里。改成断言“开着的那个 tab 不在 recent 里”。

另两个用例（page / chat-route）没有动——它们与本 iteration 无关，修它们是另一件事。
