# 新建页改版与技能落盘

## 需求

新建页（`/new`）从「一列流水」改成「两列：类 / 实例」，同时把 my skills 从隐藏的
sqlite 搬到项目里，成为能 review、能进版本库的文件。

- **技能落盘**：my skills（custom）住 `.agents/skills/<slug>/SKILL.md`；用户在项目内
  创建技能 = 在项目内创建文件；自动发现的 suggested 被接受时，**从 sqlite 复制一份到
  项目目录**。
- **放 `.agents/` 而不是 `agents/`**：`agents/` 是「开发这个程序用的说明书」，
  `.agents/` 才是「程序运行时用的 agent 能力」——两者不能混。附带好处：`.agents/skills`
  正是 pi 的项目级技能目录，落在这里外部 agent 直接就能吃。
- **新建页布局**：左列＝类（built-in / my skills / suggested），右列＝实例
  （recent chats）；中间一条**不贯通**的分割线；两列整体**偏居中**，不分散到两边。
- **展示规则**：built-in 与 my skills 全量；suggested 取最近 10 条；recent chats
  直接列 `log/list` 的第一页（100 条），**不分页**，并**过滤掉已打开的会话**
  （它是「找回关掉的会话」的入口）。每条技能行除自身动作外都带一个 `chat`
  按钮——用它开对话。
- **built-in 保持硬编码**（只 Chat），不落盘、不扫描目录。

## 现状

- 存储：`workspace/ai/src/skill/store.ts` —— SkillStore 独吞 `.engineer/skill.db`，
  四张表 `skill` / `skill_session` / `scan_pending` / `scan_state`，custom 与 suggested
  同在 `skill` 表里。id 形如 `t_ab12cd34`。
- 新建页：`workspace/web/app.js:1927` `newTabReload()` 一列渲染
  built-in → my skills → suggested → recent；`recentSessions(limit = 10)`（`app.js:1971`）
  拉 `log/list` 第一页、**过滤掉已打开 tab**、只留前 10 条。
- 样式：`workspace/web/style.css:473` 起，`.newtab-body { width: min(680px, 100%); margin: auto; }`
  单列居中。
- `log/list` 的 `pageSize` 是 `workspace/log/internal/store/store.go:17` 的常量 100，
  **被 `log/query`、`log/search`、`log/list` 三个端点共用**。
- 技能在 AI 侧也能创建：`registry.ts:243` 的 `save_skill` 工具调同一个 `store.save()`。

## 决策

1. **文件形态**：一技能一目录，`<root>/.agents/skills/<slug>/SKILL.md`，
   frontmatter 只有 `name` / `description`，正文＝技能文本（= 运行时交给模型的那段
   text）。选这个而不是单文件 `<slug>.md`，是为了直接兼容 pi / Claude 的 skill 约定。
2. **`description` 由文本派生**：取 text 第一条非空行、截 120 字符。它不是第二个字段，
   只是给外部 skill 发现用的摘要。
3. **id 语义**：custom 的 id = slug（目录名），创建时由 name 派生
   （小写、非字母数字→`-`、trim `-`、冲突加 `-2`/`-3`）。**改名只改 frontmatter 的
   `name`，不移动目录**——id 稳定，`skill_session` 里的映射不作废。
4. **sqlite 降级为「候选 + 簿记」**：`skill` 表只留 suggested；`skill_session` /
   `scan_pending` / `scan_state` 不动。suggested **不落盘**，唯一出处仍是 sqlite。
5. **`/ai/skill/ignore` 只对 suggested 有意义**：对 custom id 返回 404（行为变更，见
   「范围外」）。custom 没有 status 列——文件就是技能，没有「忽略」这个状态。
6. **接受一个 suggested = 落盘 + 删行**：`save({id: "t_xxx"})` 写文件、删除 sqlite 行，
   返回的新 id 是 slug。
7. **recent 不分页，但保留「已打开」过滤**：直接展示 `log/list` 第一页 100 条
   （过滤后可能不足 100）；**不改** log 的 `PageSize`（它被另外两个端点共用，改
   10 会连坐 records 列表与搜索）。
8. **每条技能行加一个 `chat` 按钮**（custom / suggested 都有）：效果等同于点整行
   —— 用该技能开一个对话（`data-action="run"`）。行的动作按钮变成
   custom `chat` `delete` / suggested `chat` `save` `ignore`。
   `delete` 会删掉项目里的一个目录，所以要先问一句：**按钮旁弹一个 popover**
   （不是遮罩弹窗，页面继续可见），在里面点 `Delete` 才真删，`Cancel` /
   Esc / 点别处 / 滚动都只是关掉它。
9. **万一列出了一个已打开的会话，点击也安全**：`openSkillTab` 先按 `sessionId`
   找已有 tab（`app.js:1789`），命中就不新建——不重复开、草稿不丢（草稿按 tab id
   存在 `aiDrafts`）。有了过滤，这只是兜底。

## 方案

### 存储（`workspace/ai/src/skill/store.ts`）

新的解析 / 序列化（无依赖，手写 frontmatter，不引 yaml 库）：

```
---                          name: Payment logs
name: Payment logs           description: check payment-service logs in dev
description: check pay...    ---
---                          check payment-service logs in dev for the last 30 minutes
check payment-service ...
```

- `files()`：扫 `.agents/skills/*/SKILL.md`，读 frontmatter + 正文，得到
  `Skill{ id: slug, name, text, source: "custom", status: "active" }`；
  `createdAt` / `updatedAt` 取文件 mtime（birthtime 可用则作 createdAt）。
  目录存在但没有 SKILL.md → 跳过。
- `list(filter)`：files + sqlite suggested 合并，按 source / status 过滤，按
  `updatedAt` 倒序（契约说 newest updated first）。
- `get(id)`：先当 slug 找文件，再查 suggested 行。
- `save({id?, name, text})`：
  - 无 id → `slug = uniqueSlug(name)`，建目录写文件；
  - id 命中文件 → 重写文件（name / text 以入参为准）；
  - id 命中 suggested 行 → 写文件 + 删行（决策 6）；
  - 都不命中 → `undefined`（上层 404）。
- `remove(id)`：文件 → `rm -rf` 技能目录；suggested 行 → 删行。都没命中 → false。
- `setIgnored(id, ignored)`：只认 suggested 行，其余 `undefined`。
- `known()`：files + 全部 sqlite 行（含 ignored）——扫描去重用的「已知技能」。
- **不做迁移**：`skill` 表里遗留的 `source='custom'` 行不再被读取（custom 技能
  在这之前不存在于真实项目里，本地库 0 条），不写一次性导出逻辑。

sqlite 侧只删不改：`skill` 表结构保留（suggested 还在用），custom 只是不再往里写。

### 前端

`workspace/web/app.js`：

- `newTabReload()` 重排成两列 DOM（**保持 h3 顺序** built-in → my skills → suggested →
  recent，左列在前）：

  ```html
  <div class="newtab-cols">
    <div class="newtab-col">            <!-- 类 -->
      <h3>built-in</h3> …Chat…
      <h3>my skills</h3> …
      <h3>suggested</h3> …            <!-- slice(0, 10) -->
    </div>
    <div class="newtab-divider"></div>
    <div class="newtab-col">            <!-- 实例 -->
      <h3>recent</h3> …                <!-- 第一页 100 条，过滤掉已打开 -->
    </div>
  </div>
  ```

- `suggested` 前端 `.slice(0, 10)`（`list` 已按 updatedAt 倒序）。
- `recentSessions()`：保留 `open` 过滤，删掉 `slice(0, limit)` 的 10 上限，
  取 `log/list` 第一页的全部（≤100）。
- `newTabItemHtml()`：行内动作前面统一加 `chat`（`data-action="run"`）。
- `skillConfirmOpen()` / `skillConfirmClose()`：`delete` 的二次确认 popover。
  `position: fixed`、按按钮的 box 定位（下方放不下就翻到上方，不越过右边缘），
  Esc 走捕获阶段监听，避免先被「Esc 离开新建页」吃掉；重渲染与离开页面都会关掉它。
- 数组为空时的 `nothing here yet` 提示保留（用例在断言它）。

`workspace/web/style.css`：

- `.newtab-body` 放宽到 `min(1040px, 100%)`，仍是 `margin: auto` 双向居中
  （用例在断言 `.newtab-body` 相对 `#newtab` 的 dx/dy ≤ 2）。
- `.newtab-cols { display: flex; gap: 36px; align-items: flex-start; }`，
  两列 `.newtab-col { flex: 1; min-width: 0; }`——**偏居中**：由 body 的
  max-width + margin auto 决定，两列等比撑满，不贴窗口两边。
- `.newtab-divider { width: 1px; align-self: stretch; background: var(--border); }`
  ——高度=内容块高度（**不贯通**整页，也不是 100vh）。
- 窄屏（`max-width: 900px`）降级单列：`flex-direction: column`，divider 变成
  1px 高的横线。

### 契约 / 文档

- `contracts/ai-skill-list.yaml` / `ai-skill-save.yaml` / `ai-skill-delete.yaml`：
  形状不变，补充 id 语义（custom 的 id 是 `.agents/skills/<id>/` 目录名）。
- `contracts/ai-skill-ignore.yaml`：注明只对 suggested 生效，custom → 404。
- `atoms/ai.yaml` 的 description + `docs/ai.md`：把「in its own sqlite
  (.engineer/skill.db)」改成「custom 落 `.agents/skills/<slug>/SKILL.md`，
  suggested 候选与扫描簿记在 `.engineer/skill.db`」。
- `agents/schema.md`（+ `zh/`）**不动**：`.agents/` 是 Engineer 运行时的私有约定，
  不属于通用 schema 规范。

## 范围外

- 不改 suggested 的发现机制（队列、10 条阈值、扫描实现、`/ai/skill/refresh`）。
- 不改 `log/list` 契约与 log 服务的 `PageSize`（仍是 100）。
- 不给新建页加技能编辑表单（用例在断言页面上没有 `form`）。
- 不给 built-in 做文件化 / 目录扫描。
- 不做 recent 的分页控件。

## 验收

- `.agents/skills/<slug>/SKILL.md` 存在，frontmatter 有 `name` / `description`，
  正文等于技能文本；`save` 返回的 `id` 等于目录名。
- `skill.db` 的 `skill` 表里没有 `source='custom'` 的行；suggested 仍在表里，
  ignore / restore 仍只作用在它上面。
- 接受一个 suggested：项目里出现对应目录，sqlite 里那一行消失。
- `delete` 删掉整个技能目录；再次 delete → 404。
- 重启 ai 服务后 my skills 仍在（文件在，不在内存）。
- 新建页：三块在左列、recent 在右列，中间一条不贯通的分割线；两列整体居中；
  窄屏单列。
- recent 列出最近 100 个会话、**过滤掉已打开的**；点开一个 = 恢复正常会话。
- 每行都有 `chat` 按钮：custom 是 `chat` `delete`，suggested 是
  `chat` `save` `ignore`。
- `delete` 先弹确认 popover：确认前技能还在；`Cancel` / Esc / 点别处都只是关掉它；
  确认后技能从页面消失，项目里对应的 `.agents/skills/<slug>/` 目录也没了。
- `development/testing/dev/` 里的 `case-core-skill-crud` 与
  `case-core-web-skill-tabs` 通过（前者已按文件化改造）。
- 静态校验通过（`contracts` / `atoms` / `edges` 无悬空引用）。

## 实施记录（Phase 3）

- **契约形状零变更**：只补了 id 语义与 ignore 只作用于 suggested 的注释，`atoms/` `edges/` 不动，`static/validate` `ok: true`。
- **log 未动**：`log/list` 不改（`pageSize` 仍是全局 100），新建页只展示第一页；`/resume` 抽屉也就没受影响。
- **没有迁移**：按用户要求不写一次性导出；`skill` 表里遗留的 custom 行不再被任何读取路径碰到。
- **自定义技能没有 createdAt 列**：取文件的 birthtime（缺则 mtime），所以重写后 `createdAt` 在 macOS/ext4 上保持不变；没有把时间戳塞进 frontmatter 污染对外格式。
- **窄屏修正**：`.newtab-cols` 的 `align-items: flex-start` 是为两列准备的，竖排时会反过来把每列压到内容宽、让长文本横向溢出；媒体查询里改回 `stretch`（并在用例里按 709px 实测过无横向溢出）。
- **review 后回改**（用户 2026-10-07 确认）：行内加 `chat` 按钮（`data-action="run"`，与点整行同效）；recent **恢复**「已打开」过滤（原方案去掉，实测该列表就是「找回关掉的会话」的入口）；**去掉**遗留行迁移（真实项目里 custom 技能此前不存在）；`delete` 增加二次确认 popover。
- **用例实跑**：`core-skill-crud`、`core-skill-run`、`core-skill-suggest`、`core-web-skill-tabs`、`core-web-chat-route` 全部通过；测试记录已写入 log（`kind: test`）。
- **未做**：把改动打进安装态应用（`~/.engineer/apps/current` 还跑着旧 web 资源）——那是 Type 2，走 `how-to/deploy/prod/BOOK.md`，等 review 通过再说。
