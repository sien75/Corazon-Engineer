# chat 实例替换与输入草稿隔离

## 需求

修两个多会话（skill / chat tab）下的问题：

1. **`/new` 之后旧对话又回来了**：在某个 chat 里执行 `/new`，当前的对话内容被清空；
   切到别的 chat，再切回来，**被清空的旧对话又显示出来了**。
   期望：`/new` = **取消当前 chat instance（tab），新建一个通用对话**，而不是
   「把当前视图清空」。旧 instance 的 session 留在 recent 里可再打开，但不会
   再绑在当前 tab 上。
2. **待发送的输入在多个 chat 之间串台**：同时开着多个 chat instance，在一个 chat
   输入框里敲了一半的问题，切到另一个 chat，输入框里还是那段文字。

## 现状

- tab 的会话由 `skillTabs` 里的 `t.sessionId` 决定；切换 tab 时
  `activateSkillTab` 用 `tab.sessionId` 走 `/ai/resume` + log 重放
  （`workspace/web/app.js:1695`）。
- `/new` 命令（`aiCommandNew`，`app.js:2253`）只是 `aiMessagesEl.innerHTML = ""`
  再调 `aiNew()`（`app.js:936`）。`aiNew()` 只改全局 `aiSession` 并把
  `renderedTabId = null`，**没有改当前 tab 的 `sessionId`**。于是切走再切回时，
  `activateSkillTab` 仍按旧的 `tab.sessionId` 重放，旧对话就回来了。
- 输入框 `#ai-input-field`、待发送图片 `aiImages` / `aiImageTasks` 都是**全局一份**
  （`app.js:558` / `app.js:584`）。`activateSkillTab` 不碰它们，切 tab 时输入框内容
  原样保留，所以多个 instance 共用同一份草稿。
- 同类问题（同一个根因）还有两处：删掉「当前打开会话」后 `aiConfirmAccept` 调
  `aiNew()`，tab 仍指向被删的 session；`/resume` 选了另一个 session 后 tab 也仍
  指向旧的。本次只修前者（删当前会话是 `/new` 的直接相邻路径），`/resume` 的
  tab 语义留待后续（见「范围外」）。

## 方案

### 1. `/new` = 替换当前 instance（app.js）

- 抽出 `aiNewSession()`：只负责 `POST /ai/new` 并返回 `sessionId`；
  `aiNew()`、`newBlankChat()`、`aiCommandNew()` 共用，去掉重复的 fetch。
- `aiCommandNew()` 改为：
  1. 调 `aiNewSession()` 拿新 session；
  2. 找到当前激活 tab 的下标；把该下标处的 tab **整体替换**成一个新的
     `{ skillId:"", sessionId, name:"new chat", text:"", fresh:true }`（新 id），
     没有激活 tab 就 push；
  3. 删掉被替换 tab 的草稿，`renderedTabId = null`，`saveSkillTabs()` +
     `renderSkillTabs()`，再 `activateSkillTab(新 tab)`。
- 旧 session 不删：仍留在 log / recent，可从新建页 recent 再打开——这与
  「关掉 tab 只是删 tab，会话本身还在」的既有语义一致；`/new` 的「取消」指的是
  取消这个 **instance（tab）**。

### 2. 输入草稿按 instance 隔离（app.js）

- 新增 `const aiDrafts = new Map()`：`tab id -> { text, images, tasks }`。
  只存内存，不落 localStorage（图片 base64 体积大）。
- `aiSnapshotDraft(tabId)`：把 `aiInputEl.value` / `aiImages` / `aiImageTasks`
  存进 `aiDrafts`；`aiRestoreDraft(tabId)`：取回并写回三处（含 `aiResizeInput()`）。
- `aiSwitchDraft(tabId)`：先给「即将离开的 tab」（`renderedTabId`）拍快照，再恢复
  目标 tab 的草稿。
- 挂点：
  - `activateSkillTab`：早退（同一 tab 已渲染）判断之后、`aiDrawerHide()` 之前调
    `aiSwitchDraft(id)`——新建 tab 恢复为空，符合「新 instance 空输入框」。
  - `closeSkillTab`：`aiDrafts.delete(id)`，关掉的 instance 不保留草稿。
  - `aiSend` 发送后无需特殊处理：下次切走时拍快照会用清空后的输入框覆盖旧草稿。
- `aiAddPastedImage` 里压缩回调原来写全局 `aiImages[idx]`；切 tab 后全局数组已换，
  异步完成会写错数组。改为在调用时捕获当前数组 `const arr = aiImages` 再写
  `arr[idx]`，并把该 promise push 进当次 `aiImageTasks`（随草稿一起被快照）。

### 3. 删当前会话时重绑 tab（app.js，同一根因的相邻修复）

`aiConfirmAccept` 删掉的正好是 `aiSession` 时：先记下绑定该 session 的 tab，
`aiNew()` 之后把 tab 的 `sessionId` / 名称 / skillId 重绑到新 session，并
`renderedTabId = tab.id`，避免之后切回该 tab 去 resume 一个已删除的 session（404）。

### 范围外

- `/resume` 命令在 tab 模型下的语义（应重绑当前 tab 还是新开 tab）——本次不动。
- 草稿不持久化（刷新 / 关闭页面后丢失）。
- 不改 `contracts/` `atoms/` `edges/`：接口与事件流不变，纯前端状态修复。
- 不改 ai / log / static 服务。

## 验收

- 在一个 chat（无 skill 的空对话或 skill tab）里先产生一段对话，执行 `/new`：
  当前 tab 就地变成一个名为 `new chat` 的空白 tab，消息区为空、输入框为空；
  切到别的 tab 再切回来，仍是空白（旧对话不再出现）；旧 session 出现在新建页
  recent 里，仍可重新打开。
- 开两个 chat tab：在 A 输入框敲 `draft-A`，切到 B，B 输入框为空；在 B 敲
  `draft-B`，切回 A，A 的 `draft-A` 还在。输入框内容在两个 instance 之间不共享。
- `/new` 后旧草稿被丢弃（不会在新 instance 的输入框里出现）。
- 删除「当前打开的会话」后，该 tab 重绑到一个新的空 session，切走再切回不报
  404、不显示已删除的对话。

## 验证

按 `case-core-web-skill-tabs` 自带 Setup 起隔离栈（log :8513、ai `--stub` :8511、
web 8610，不碰真实 `.engineer`），ego-browser 跑扩展后的用例。**30 项检查全过**
（log 记录 `4fa79ab000d353cc`）。新增 6 项：

- `the tab has a conversation before /new`：`Seeded skill` tab 有 2 条消息；
- `/new replaces the tab with a fresh generic chat`：tab 变 `new chat`、0 条消息、
  输入框为空、tab 数仍为 1（原地替换）；
- `the /new'd tab stays empty when reopened`：切走再切回仍是 0 条（旧对话不回来）；
- `another instance starts with an empty composer`：切到另一个 instance 输入框为空；
- `switching back restores the first instance's draft`：切回恢复 `draft-A`；
- `the second instance's draft is intact`：第二个 instance 的 `draft-B` 还在。

顺带清理：该用例第 10 步原有一条 `300px chips` 断言，是 `2610-06` 把 chip 改成
120px 后遗留的过期断言（chip 形状现有专门用例 `case-core-web-tool-chips`），
本次改动之前就已经失败；已从本用例移除，只保留「气泡不压滚动条」的检查。

## 范围外（补）

- 删掉的 session 若绑在**后台 tab** 上（不是当前 `aiSession`），该 tab 仍会指向已删
  session；本次只处理当前会话这一条路径。
- `/resume` 命令选另一个 session 后，当前 tab 的 `sessionId` 仍不同步。
