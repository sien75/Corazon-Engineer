# 模型优先级收敛为三层，模型选择只落会话行

## 需求

- 一个会话跑哪个模型，优先级收敛为三层（chat / image 两个 slot，各自一条链）：

  1. **会话维度**：会话行 `model` / `imageModel`。`model` 工具的切换和创建时传入的
     `chat` / `image` 都只写这一处——同一层，不分先后；
  2. **`models.yaml`**：engineer home 里的 `main` / `sub` × `chat` / `image`；
  3. **pi 自己的默认**：pi 的 settings 里 `defaultProvider` / `defaultModel` 拼出来能用到就用，
     否则取 pi 现在能用的第一个模型。**只有 chat 有这一层**；image 到第 2 层为止，空 = 未配置。

- 不再有 `model` 记录帧：会话里不写 `role: model` 的记录，重启 / 恢复只看会话行。
  旧会话里已有的 `model` 帧不读、不当兼容兜底——这条逻辑当不存在。
- thinking 档位不再被特殊对待：`model` 工具切换模型时不再把 `agent.thinkingLevel` 抄下来，
  build 时也不回传。既然 pi 的配置、`models.yaml`、创建时传入都没有"档位"这个概念，
  它就不该只在"切换模型"这一处冒出来——交给 pi 按自己的规则（per-model 覆盖 > 全局默认）算。
- 默认值的修改就是改文件：`models.yaml` 里的一格，main 用 `write` / `edit` 改，不加工具。
- 文档：`agents/models.md`（+ `agents/zh/models.md`）简述三层优先级、`models.yaml` 怎么改、
  pi 的配置分别是什么、谁可以动。main 的 spec 里给一条工具说明和这个文档的路径。

## 现状（实测）

- `registry.ts` 的 `build()` 候选链是「历史里最后一条 `model` 帧 → 会话行 `model` →
  `models.yaml` 的 chat」；三层都不可用时按 `models.yaml` 里那个 provider 取 `available`
  第一条，再 `available[0]`；pi 的 settings 完全不看。
- `persistModel()` 同时写一条 `role: model` 记录和会话行 mirror，且记录优先——同一件事两个真相。
- `model` 工具切换后把 `String(agent.thinkingLevel)` 抄进记录，`build()` 再读回来传给
  `createAgentSession`。而 `setModel()` 本来就算好了档位（`agent-session.js:1260`
  `_getThinkingLevelForModelSwitch`：per-model 覆盖 > 全局默认），抄的只是派生值。
- pi 自己的默认解析（`model-resolver.js` 第 3、4 步）：settings 的
  `defaultProvider` / `defaultModel`（有凭据）→ 已知 provider 的默认型号 → 第一个可用模型。
- 会话表已有 `model` / `image_model` 列，`UpsertSession` 空值保留旧值
  （`workspace/log/internal/store/workspace.go:303`），所以一次切换只要写一列。

## 方案

### 1. 解析（`registry.ts` 的 `build()`）

- chat：`[会话行 model, models.yaml 的 <kind>.chat]` 里第一个能在 pi 的可用列表里解析到的就用；
  都不行 → `settings.getDefaultProvider()` / `getDefaultModel()` 拼成 ref 再解析，仍不行 →
  `available[0]`；跳过的每一层和最后的选择各打一行警告。
- image：`[会话行 imageModel, models.yaml 的 <kind>.image]`，空就是空，不兜底。
- thinking：不传，交给 pi。

### 2. 工具与配置

- `model`：`set` 只写会话行（`/log/session/upsert` 的 `model` / `imageModel`），不写记录；
  `list` 仍报 `thinking X`——那是当下 pi 的状态，不是持久化字段。
- 默认值不加工具：`models.yaml` 是配置文件，main 用 `write` / `edit` 直接改。写之前核两件事
  ——`chat` 得是 pi 现在能用的 `provider/model-id`（`model list` 里有），`image` 同形状或
  `""`。读文件时不做可用性校验，名字不可用时 build 会跳过并警告。

### 3. 文档

- `agents/models.md`（+ `agents/zh/models.md`）：三层优先级、`models.yaml` 四个格子的写法规矩、
  pi 的 `auth.json` / `models.json` / `settings.json` 各是什么、谁能改。
- `main.ts` 在 main 的 spec 末尾追加本 spec 的目录，让 main 能用 `read` 找到 `models.md`；
  `agents/main/AGENTS.md`（+ zh）加一条：默认值没有工具，改文件，先读 `models.md`。

范围外：前端模型控件；生图工具（image slot 仍然没有人消费）；压缩模型；pi settings 的写入
工具（继续用 `write` / `edit`）；thinking 档位的持久化——明确不做。

## 验收

- 会话记录里不再出现 `role: model`；`model` 工具切换后只有会话行变化。
- 杀进程重启后，会话仍跑最后选定的模型（会话行压过 `models.yaml`）。
- `models.yaml` 里的名字不可用时退到 pi settings 的默认；再不可用退到第一个可用模型。
- main 改完 `models.yaml`，新会话 / 下次 resume 生效，文件里原有注释还在（`edit` 定点改），
  写一个 pi 用不了的名字不会报错，只在 build 时被跳过并警告。
