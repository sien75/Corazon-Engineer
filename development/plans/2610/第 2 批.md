### Agent 间通信

A2A?

内部通信, 然后还考虑下能不能跟外部的 codex 一类的通信

### 多 agent 设计

主 agent 是宏观层面的, 修改 schema, 宏观层面执行运行/测试/连接/监控, 然后它不涉及具体的事情.

比如说, 增加了什么接口, 他不负责分析, 只负责出方案, 然后和子 agent 对话, 看他们的是否符合要求, 然后问子 agent 你增加了哪些能力, 然后补充到 schema 里, 但是通过测试去测试它对不对.

### 权限控制 + 校验机制

重新设计 static 部分, prompt + code 缓存机制 + 权限控制 + 校验机制

**权限控制**

现阶段只做粗粒度 —— 只能改本项目内容(直接改),改项目外内容需审核,读不限(可用 jev 判断? 或者沙箱)。后续很复杂:多 agent、按步骤/agent 限定可改哪个文件,验证通过再进入下一步。

**校验机制**

理想是完成一步后校验一次。先保证 YAML 语法/规范合规(atoms / contracts / edges 按 contract 规范);其余是 md,无法结构校验。后续再扩展校验其它内容。
