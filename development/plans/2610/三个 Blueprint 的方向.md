# 三个 Blueprint 的方向

> 2026-10-20 讨论记录。记录方向与建议命名，尚未展开实施设计；本次不迁移目录、不修改功能。`pure-chat` 保留，现有 `project` 后续删除，本稿不讨论它的调整。

Blueprint 应由使用 Corazon 开发自己项目的开发者构建。这里提供可参考、可修改的例子，围绕三个问题组织：系统是什么、开发进行到哪里、相关资料在哪里。

## 1. 结构图（Structure）

- 建议统一目录名为 `structure/`，将现有 `atoms/`、`edges/`、`contracts/` 收到其下，保留三类内容各自的子目录。
- 主体是一张图，使用项目现有 `graph.js` 中的图库，表现节点及节点之间的关系。
- 点击节点、连线或对应的契约入口，可以查看具体的 atom、edge、contract。
- 图承担整体理解，详情承担精确查阅；具体如何把 contract 放进图中，后续再设计。

## 2. 开发台（Development）

- 围绕一次迭代组织开发过程，iteration 和 test 都是 AI 生成的开发产物。
- 展示已创建的 iteration 及其内容。
- 展示测试用例的变更情况和执行情况。
- 展示代码变更、structure 变更。
- 涉及打包、发布时，也展示打包与发布的情况。
- 方向是让人看清一次迭代改了什么、验证了什么、交付到了哪里。各类变更和执行记录如何关联到迭代，后续再设计。

## 3. 资料库（Library）

- 以文件浏览器为主体，加上常用功能按钮；具体按钮后续按使用场景确定。
- 浏览新的 `notes/`、新的 `docs/`、`how-to/`、`agents/` 和根目录 `AGENTS.md` 等文本资料。
- 保留目录与文件本身的组织方式，方便阅读并围绕内容与 Agent 交流。

建议名称暂定为：**结构图、开发台、资料库**；对应 Blueprint slug 为 `structure`、`development`、`library`。
