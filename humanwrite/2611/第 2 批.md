### 多 agent 设计

主 agent 是宏观层面的, 修改 schema, 宏观层面执行运行/测试/连接/监控, 然后它不涉及具体的事情.

比如说, 增加了什么接口, 他不负责分析, 只负责出方案, 然后和子 agent 对话, 看他们的是否符合要求, 然后问子 agent 你增加了哪些能力, 然后补充到 schema 里, 但是通过测试去测试它对不对.

需要一个 sop.

gemini -> 客户经理
claude -> 产品经理 & 架构师
deepseek -> 工程师

### 群聊模式

对话设置为聊天模式, 主要和 super 去聊, super 会拉群, 人直接群聊, 不指明就是 super 回复, 指明就是单独和 sub 的某个 agent 聊 (这个通过 @ 显式和 jev 判断隐式以及 super 判断的转发等方式)

这里聊天遵从简洁+深入的模式, 简洁的偏好理解的短话, 和展开才能看的复杂细节的长话, 不要在群里发长文.

群聊模式还可以可视化成步骤, 这就是所谓的 sop 视图, 看整体步骤.

这是个 personal agent, 换话题或者什么时机下得压缩一下, 或者这里不叫压缩, 而且不同层级的存储, 对话中叫内存, 用户偏好和长期记忆是支持检索的硬盘.
