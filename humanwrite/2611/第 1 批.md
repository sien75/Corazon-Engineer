## 工具 / 接口 / 命令的梳理

> 原则, ai 内部用工具, 外部用接口, 必要的工具和接口显化为工具 or UI 功能

(合适的)工具和接口都要做成命令, 然后部分比如当前模型和用量还要展示在 UI 上.



## 存储系统

存储系统才是之前没想明白的那块事情的解法, 这下子就理清楚了.

### 基础存储

现在的项目和对话属于基础的存储, 这些是最基础的内置的能力, 蓝图也可以用.

### 蓝图专属存储

可以在存储系统里加存储项, 也可以使用现有的, 共蓝图使用, 因为蓝图本身是 algorithm, 需要 data 才能真的展示.

不内置在系统内, 但是开放这样一系列接口.



## 蓝图的处理

### super 也有蓝图

super 也得有个蓝图, 他得去展示群聊 / 进度&sop 这一类. 先不用管 super 怎么绘制蓝图, 先把这个基础能力坐上去.

首先有个最基础的 pure chat, 这个就是内置, 不作为开放的组件. 这是最基础的能力, 即 ce 打开可以有一个 super 的纯对话.

当然这个 pure chat 就像是 cli 模式, 日常使用应使用 super 的 blueprint, 即 gui 模式.

super 的蓝图就是把对话能力, 项目管理能力, 等, 作为[名词性的存储]去处理.

### 蓝图的后端能力

蓝图需要有后端能力, 但是不需要专门的后端服务, 这里的后端能力其实就是去调存储接口 (即直连 sql, GraphQL?).

那普通蓝图, 需要具备前后端一体的能力, 前后端是 html, 再加一个数据依赖声明 (写 sql, 感觉也不用声明, 或者在 html 某个部分声明).

像 super 的蓝图, 后端其实就是 ai 服务, 前端是 web, 这么看是不是 ai 服务可以合并到 web 啊. web 就是 0 号蓝图 (当然改名字, 叫 pure chat?).
