# Blueprint

Blueprint 是项目里给 agent 用的页面: 目录 `.agents/blueprints/<slug>/`. Blueprint 是类, 由它建出的 session 是实例.

## 形状

| 文件 | |
|---|---|
| `README.md` | 必需 — agent 的开场上下文 (追加在 system prompt 最后) |
| `index.html` | 必需 — 页面入口 |

其余的东西 — css, js, 图片, 子目录 — 都属于这个页面, 用相对路径引用 (`./my-view.css`).

- 被伺服的就是这个目录本身, 地址是 `/agent/<sessionId>/`. 没有按 agent 复制的副本: 改一处就是所有实例刷新后的页面, 并且落在项目工作区里.
- `<title>` 就是用户看到的名字.
- 实例化只检查这两个文件在不在.

## 自成一体

Blueprint 自己管自己. 外壳自己的组件, 库和样式是外壳的: 页面不依赖它们. 页面要用的东西 — 库, 样式, 图片 — 都是 blueprint 目录里的文件, 用相对路径引用. 库下载进这个目录, 不要用 CDN.

## 修改

- 用户说改什么就用 `write` / `edit` 改文件, 然后请用户刷新 — 不用先提方案.
- `README.md` 要和页面保持一致: 它是 agent 被告知的、关于它所驱动的 UI 的全部.

## 建议新建

- 同一个话题反复出现, 或用户要的东西"看"比"读"更容易 (列表, 表格, 图表, 流程, diff, 对比) 时, 建议建 blueprint.
- 优先扩展已有的 blueprint, 而不是新建.
- 用一两句话提议 — 展示什么, 数据从哪来, 新建还是修改 — 用户同意之前什么都不要动.
